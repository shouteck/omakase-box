# K3: remove the old container verification harness

Milestone: K3 · Station: service-data · Base: master after K2b · Branch: `wave/K3` · Timebox: 2 hours

## Outcome

Every piece of the Docker-based verification stack that K2 made dead is gone: `scripts/box-verification/`, `tests/box/verification/`, the `BOX_VERIFICATION_PROFILE`/`BOX_VERIFICATION_BROWSER_PATH` switches, the synthetic compose runtime and its bring-up scripts. `node scripts/verify.mjs` with the standard suites exits 0, and no test file anywhere references `docker`, `composeArguments` or `private-task-mvp-synthetic`.

## Scope

- Delete (only after a repo-wide search shows no live references):
  - `scripts/box-verification/**`, `tests/box/verification/**`
  - `scripts/synthetic-runtime.mjs`, `scripts/migrate-runtime.mjs`, `scripts/verify-runtime.mjs`
  - `infra/compose.yaml` if nothing references it
  - the `BOX_VERIFICATION_PROFILE` / `BOX_VERIFICATION_BROWSER_PATH` code paths in `scripts/suite.mjs` and `scripts/vitest.config.mjs`
  - dead imports/helpers left over in ported files, e.g. `docker`/`composeArguments` imports in tests and `tests/e2e/intent/scripts.d.ts` if it only served the removed machinery
- Keep: `scripts/docker.mjs` and `verify.mjs --db=docker` (still a supported disposable-database mode); `tests/box/auth/fixture-transport.test.ts` if it still passes after the box-verification deletion — if it tests only the deleted transport, delete it too and say so.
- Update docs that describe the removed stack: `docs/runtime.md`, `docs/tooling.md` (replace stale lines, keep it short).
- Do not touch: `.execution/**`, `docs/legacy/**`, `milestones/**`, `tasks/*.json` (frozen/history), product code, `scripts/verify.mjs` core.
- The four `private-task-mvp-synthetic-*` containers: after the final green run, bring the stack down (`docker compose ... down -v` via the compose project name) and remove the `.runtime/synthetic-runtime/` directory. These are kitchen-created resources being retired by this wave.
