# BT28: bounded agent memory, record tracking notice, relations and purpose search

Milestone: BT · Station: packaging (also evidence) · Base: master at dispatch, after K25 · Branch: `wave/BT28` · Timebox: 150 minutes; at expiry the cook stops and reports where it is

**Brief.** Written by the CTO on 17 October 2026 from the five proposals in `kitchen/reviews/K25-memory.md`, approved by the owner at the K25 close. All five keep what an agent sees **unasked** constant in both lines and characters at any number of bounties, bound the overview at large N, and leave existing behaviour and output budgets at small N unchanged.

## Outcome

1. **Bounded ended overview (`render.ts`).** In compact `status` and `box bounty` (`!options.full && options.id === undefined`), when `ended.length > ENDED_OVERVIEW_LIMIT` (`ENDED_OVERVIEW_LIMIT = 5`), only the 5 most recently ended records (by `events.at(-1)?.at ?? createdAt`, ties broken by `id` descending) are joined on the `ended` line:
   `ended (<total> total, 5 most recent): <5 items>; all <total>: box bounty status --full`
   When `ended.length <= 5`, or under `--full` or `status <id>`, the `ended: ...` line is unchanged.
2. **Bounded unasked hook start and `OPEN` (`hook.ts`, `render.ts`).** Export `HOOK_START_OPEN_LIMIT = 10` from `hook.ts`. In `runHook` (`slot === 'start'`), when `open.length > HOOK_START_OPEN_LIMIT`, summarize the first 10 open records and append `; and <open.length - 10> more` before ` — see: box bounty status`, while still marking all open records' arrival and conflict keys in `told.told`. In `renderOpenLine` (`render.ts`), when `open.length > HOOK_START_OPEN_LIMIT`, format the first 10 open records and append `, and <open.length - 10> more (see: box bounty status)`. When `open.length <= 10`, both are byte-identical to master.
3. **Bounty relation field (`--part-of "<job or bounty-id>"` on `create`).** Add optional `--part-of` to `BOUNTY_COMMANDS.create` (`args.ts`), `parseCreateArgs`, `CreateOptions`/`planBounty` (`create.ts`), `RecordSeed`/`BountyRecord` (`partOf?: string` in `record.ts`, validated in `asRecord` as a non-empty single-line string), `bounty.ts`, `renderStatus` and `json.ts`. (`--job` stays in `RETIRED_FLAGS` so `bt15.test.ts` and `bt18.test.ts` remain untouched; `renderHelp()` must not contain `--job` or any word forbidden by `cli.test.ts`.) Where status, apply/close `jobLine` or `status --json`'s `job` field reads `record.job?.file`, read `record.partOf ?? record.job?.file` (and on an open bounty header in `renderStatus`, append `  (part of: ${record.partOf})` when `record.partOf` is set). Refuse a blank `--part-of ""` with `BountyRefused('missing-part-of', ...)`.
4. **State whether `.box/bounties/` is tracked in Git, and warn on public remotes (`render.ts`, `owner.ts`, `json.ts`).** Add a helper `trackedRecordFiles(repoRoot): string[]` that checks whether `.box/bounties/` has tracked files in Git **without adding any `git` process spawn when `.box/bounties/` is untracked** (`k14-start-budget.test.ts` pins `git: 3` on `status`): inspect the Git index file bytes first (resolve `.git/index` or a worktree's `gitdir` index; if the index file is absent or its bytes do not contain `bounties/`, return `[]` with zero `git` spawns; only when present run `gitOutcome(repoRoot, ['ls-files', '-z', '--', '.box/bounties'])`).
   - When `tracked.length > 0`: print `records: ${tracked.length} file(s) in .box/bounties/ are tracked in Git — bounty records hold owner-only context (why, saved job, local path, scan findings) that pushing to a public remote publishes; untrack with git rm --cached -r .box/bounties` in compact `status`, `status --full`, bare `config` and `config --full`.
   - When `tracked.length === 0`: stay silent in compact `status` and bare `config` (preserving `bt17.test.ts` budgets); in `status --full` and `config --full` print `records: .box/bounties/ is not tracked in Git (local to this checkout)`.
   - Add `records: { tracked: tracked.length > 0, trackedFiles: tracked.length }` to `statusDocument` and `configDocument` (`null` when `repoRoot === null`), and map `'records': '/records/tracked'` in `tests/box/bounty/json-agreement.test.ts`.
5. **Purpose search (`box bounty find <query> [--json] [--repo <path>]`).** Add `find` to `BOUNTY_COMMANDS` (`args.ts`), `renderHelp()` (one line, keeping `help` within `bt17.test.ts`'s 32-line / 4,200-char budget), `packages/box-bounty/` (`findBounties`, `renderFind`, `findDocument`, exported from `index.ts`), and `packages/box-cli/src/bounty.ts`. Case-insensitive substring match over readable records' `id`, `title`, `why`, `partOf`/`job.file`, `content.task.text`, and `resume.note`. Order open matches first, then ended matches (newest first), bounded at `FIND_RESULT_LIMIT = 20` in text with a count of total matches and which fields matched (`matched: title, why`), plus `next:`. Refuse a blank/whitespace query with `BountyRefused('missing-query', ...)`. `--json` prints schema `box-bounty/find@1`.
