# K51: verify runs what proves the product, and nothing that does not

Milestone: K (kitchen) · Station: evidence · Base: `master at dispatch` · Branch: `wave/K51` · Timebox: 240 minutes; at expiry, report partial findings and stop
Owner decisions: D-2026-11-10-k49-answers
Horizon: long: start with `/plan` and keep the plan in this file. Hillclimb playbook: a before and an after.

**Brief.** Written by the CTO on 10 November 2026 from the owner's answer to [K49](K49.md): "If you find that there are things that should be removed, then we should remove them from the verify run. But of course we want to keep the necessary stuff there to prove that our whole product works correctly." The suites today: 90 bounty test files (about 19,500 lines), 16 platform, 18 kitchen. They grew one wave at a time; nobody has asked of the whole which tests still earn their minutes.

## Outcome

A list of every test file with what it alone proves and what it costs, and the run cut to the files that prove something no other file does. After the cut, every guarantee in `docs/box-v4/CONTRACTS.md` and every refusal name is still proven by a test that fails when the guarantee is broken.

## Scope

- Write: `tests/` (removals and merges only), `scripts/suite.mjs` and `scripts/vitest.config.mjs` where a file list or a limit changes, `kitchen/reviews/K51-tests.md`, `docs/box-v4/KITCHEN.md` if a verification line changes
- Read for context: `docs/box-v4/CONTRACTS.md` and `kitchen/reviews/K30-contracts.md` (the proof map: guarantee to test), [K23](K23.md), [K24](K24.md), [K45](K45.md), BACKLOG "Bounty suite under load"
- Do not touch: `packages/` (no product change), any test's expected outcome, the three hard stops' tests, the real-journey tests

## Done when

- **Measured first:** each file's time on the hosted run and locally, from at least three runs, and its count of tests. The table is in the review.
- **A removal is proven safe before it is made.** For each file proposed for removal or merging: name the guarantees it touches from the proof map, and for each one break the guarantee in a scratch copy and show another remaining test goes red. A guarantee only this file catches means the file stays. The break and the red test are listed per file.
- Classes to look for, each reported with its count: a test of something retired (old commands, old record shapes with no reader left); the same journey set up twice in two files where one assertion block would do; a pass-probe or review file whose cases the main file now holds; a measurement that asserts nothing; a kitchen test of a rule no longer in the rulebook.
- **Never by this wave:** loosening a time limit to make a slow test pass, skipping a test on a system to make the run green, or editing an expected outcome (rule 2).
- After the cut: the proof map is regenerated and has no guarantee without a test and no refusal name without a test; the count of each is the same as before or the difference is listed by name.
- Before and after, from named runs on the same commit base: files, tests, minutes on the hosted run, minutes locally.
- Accepted the way [K50](K50.md) sets, if it has merged: the hosted run green on all three systems; otherwise `node scripts/verify.mjs --full test:box-bounty test:kitchen` and the platform suite, locally.
- If the measurement shows little to cut (under a tenth of the minutes), the Result says so and removes nothing; a small saving is not worth a lost check.

## Steps, in order

Written so any model can cook it. This wave removes tests, so it is slow on purpose: one file at a time, proof before removal. When unsure, keep the file.

1. **The protected list first.** Before measuring anything, write into `kitchen/reviews/K51-tests.md` the files that are out of scope for removal:
   - every test file that attacks a hard stop: search `tests/` for `never-ship`, `github-private-repository`, `owner-allow-needed`, `scanPatch`, `foreignFields`, and list the files;
   - the real-journey tests (those that run the packed tool end to end: `bt12-install`, `bt12-package`, and any file whose name or first comment says "journey");
   - `tests/platform/` files that drive a payment.
   Nothing on this list is touched, whatever the measurement says.
2. **Measure.** For every remaining test file: its number of tests and its time, from three runs. Use the runner's own per-file timing (run a suite with its JSON or verbose reporter through `node scripts/suite.mjs`; read `scripts/suite.mjs` for how arguments pass through). Hosted times come from three runs' logs. One table: file, tests, median seconds local, median seconds hosted, spread.
3. **The cut-off.** Add up the minutes of the slowest files. **If no candidate set you can name saves at least a tenth of the run, stop here:** write the table, remove nothing, close the wave.
4. **Classify candidates,** each into one of the five classes in Done when, with one sentence of evidence:
   - *retired:* the command, option or record shape it tests no longer exists in `packages/` (show the search that finds no reader);
   - *duplicate journey:* another named file sets up the same thing and asserts the same facts;
   - *probe held by the main file:* a `-pass`, `-probe` or review file whose every case appears in the main file (list the pairs);
   - *asserts nothing:* a measurement with no `expect` that can fail;
   - *retired rule:* a kitchen test of a rule no longer in AGENTS.md or KITCHEN.md.
5. **Prove each removal, one file at a time.** For candidate file F:
   1. list the guarantees F touches from `kitchen/reviews/K30-contracts.md` (the map from guarantee to test) and every refusal name F asserts (`grep -o "'[a-z-]*'" F` against the refusal list);
   2. for each guarantee and each refusal name: in a scratch worktree, break it in `packages/` with the smallest edit that defeats it (for example make the check return early), run the suite **without F**, and see another test go red. Record: the edit, and the test that went red;
   3. if for any one of them nothing else goes red: **F stays.** Write that down and move on;
   4. only when every one is covered: delete F (or move its one unique case into the other file, unchanged) in its own commit, named for F.
   Undo each scratch break before the next. `git status` clean between files.
6. **Regenerate the proof map** the way [K30](K30.md)'s review made it, and compare with the map from before: the same guarantees, the same refusal names, each still with at least one test. Any difference is listed by name.
7. **After:** files, tests and minutes, hosted and local, on the same base commit. **Verify** the way [K50](K50.md) sets if it has merged, else the full local run.

## What the review file contains

`kitchen/reviews/K51-tests.md`, in this order: the protected list; the timing table; the candidates with class and evidence; per removed file, the break-and-red table; the files kept and why; before and after.

## Traps

- "Slow" is not a reason to remove. Only "proves nothing another file does not" is.
- A file with one unique case and forty duplicates keeps its one case: move it, do not drop it.
- Do not loosen a timeout, do not add a skip, do not edit an expectation (rule 2). If a slow test is slow because of a fault, that is a BACKLOG line, not a removal.
- Do not delete helpers or fixtures until a search shows no remaining test imports them.
- The pre-cook card says how many files you expect to remove; if the proof phase raises that number by more than half, tell the owner before going on.

## Lenses

- [x] **Measurement fairness:** times from repeated runs with the spread; every file listed, kept or cut; a file whose value could not be judged is kept and named.
- [x] **Security:** the tests that attack the hard stops (never-ship, private repository, the owner's permission, the secret scan, the reading boundary) are out of scope for removal; list them first so none is cut by accident.

## Notes

- Removals are the owner's go, given here in principle for tests proven redundant; the pre-cook card still says plainly how many files it expects to remove.
- Best after K50: on a 5-minute run, the saving that matters is flakiness and clarity more than minutes.
