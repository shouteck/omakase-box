# PF61: the board knows you by your GitHub ID, and signs you in with PKCE

Milestone: platform · Station: packaging · Base: `master at dispatch` · Branch: `wave/PF61` · Timebox: 180 minutes (a hosted run takes about 25); at expiry, report partial findings and stop
Owner decisions: D-2026-11-24-one-fact-one-owner
Horizon: short to medium. Bug fix playbook; principles: fix-root-causes, boundary-discipline, prove-it-works.

**Brief.** Written by the CTO on 24 November 2026 from the walkthrough of the board's sign-in, sessions and webhooks with the owner ("yes").

**Why.** Sign-in, sessions and webhooks follow good practice:
- GitHub OAuth with no scope, a `state` cookie, and the token used once and dropped;
- a 32-byte session token in a `__Host-`, `Secure`, `HttpOnly`, `SameSite=Lax` cookie, stored only as its SHA-256;
- every write must come from the board's own page (`Origin`) and be JSON;
- Stripe's HMAC signature is checked as Stripe documents (`signatureHolds`, `src/stripe.ts`), and PayPal's through PayPal's own verification API (`webhookHolds`, `src/paypal.ts`);
- webhook events are deduplicated and bound to payments the board recorded.

Three gaps:
1. **Who-may-see is decided by login name, not GitHub ID.**
   - `roleOf` and `ownerOnlyAllowed` (`packages/box-platform/src/visibility.ts`) compare the viewer's login with the bounty's `poster` and the merged authors' logins. `src/account.ts` passes `viewer.login` when showing a solver's owner-only payment methods (near line 369), when recording paid (`recordPaid`, near line 409) and when answering received (`answerReceipt`, near line 445).
   - A GitHub login can change hands: renamed accounts release their old name. A stranger who claims an old poster's name is treated as the poster of that account's bounties, and can see solvers' owner-only methods and record payments. A session also keeps the login it was given for 30 days.
   - The board already stores the IDs (`bounties.poster_id`, `pull_requests.author_id`), and its own comment in `finishSignIn` says cards and Stripe accounts "hang on the GitHub id, so a login changing hands reaches none of them". The visibility rules do not.
2. **Sign-in has no PKCE.** GitHub supports PKCE for OAuth apps (S256 only) since July 2025 and recommends it for the authorization-code flow ([changelog](https://github.blog/changelog/2025-07-14-pkce-support-for-oauth-and-github-app-authentication/)). It protects the sign-in if the returned code is intercepted. `startSignIn`, `identityFrom` and `tokenFrom` (`src/account.ts`) send none.
3. **No "sign out everywhere".** A lost device's session stays valid for up to 30 days.

## Outcome

1. **Every role is decided by GitHub ID.**
   - `PaymentFacts` carries `poster_id` and each merged author's `author_id`.
   - `roleOf`, `ownerOnlyAllowed` and `payeeOf` compare the viewer's `github_id` with them.
   - Logins are kept only for showing names.
   - Where a row has no ID (older rows), the role is `other`: owner-only methods stay hidden, and recording paid or received is refused with "this bounty's account could not be confirmed by GitHub id; nothing changed". That fails safe.
   - Rows written by the refresh get their IDs filled from GitHub's answers on the next read, where GitHub gives them.
2. **PKCE on every GitHub sign-in the board starts:** the ordinary sign-in, and the PF32 listing sign-in while it exists (PF57).
   - A fresh `code_verifier` (32 random bytes, base64url) is kept in the existing `__Host-` state cookie, bound to `state`.
   - `code_challenge` (S256) and `code_challenge_method=S256` are added to the authorize URL; `code_verifier` is added to the token exchange.
   - A callback whose verifier is missing is refused like a bad `state`.
3. **"Sign out everywhere":** `POST /auth/sign-out` with `{ "all": true }` deletes every session for the viewer's GitHub ID, with the same `Origin` and JSON checks. Your page gets one button for it.
4. **`/privacy/` and `docs/box-v4/PLATFORM-UX.md`** say sessions are tied to the GitHub ID, and that signing out everywhere exists.

## Traps

- **Do not migrate by matching logins to IDs** for old rows: that is the very assumption being removed. Fill IDs only from GitHub's own answers.
- **The `code_verifier` is a secret for the length of one sign-in:** cookie only, never a URL or a log.
- **`same()` stays for display matching only.** Grep for every `same(` call that decides a permission, and list them in the Result before and after.
