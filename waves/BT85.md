# BT85: the solver's one yes states the real risk, and `take` says how to be paid

Milestone: BT (the bounty tool) · Station: packaging · Base: `master at dispatch` · Branch: `wave/BT85` · Timebox: 120 minutes (a hosted run takes about 25); at expiry, report partial findings and stop
Owner decisions: D-2026-11-03-solver-in-the-tool
Horizon: short. Feature playbook; principles: prove-it-works, subtract-before-you-add.

**Brief.** Written by the CTO on 23 November 2026 from the walkthrough of `take` with the owner ("yes brief it").

The owner's direction: the solver side should carry no more guard rails than it needs. A solver spends no money, and the one step that truly needs a person is setting up a way to be paid. The solver side already asks a person for only one thing, the one-time `config set solving allowed`. "Ask each time" and the limits are the owner's optional extras. This wave keeps that single yes and adds nothing. It makes the yes informed, and it puts the payment step where the solver will see it in time.

**Why.**

1. **The words promise what the tool does not do.**
   - When the owner turns solving on, `changeSolving` (`packages/box-bounty/solving.ts`, the line after `save`) says the agent "should work only in a throwaway copy, with none of your credentials in reach".
   - `describe` for solvers (`packages/box-bounty/wording.ts`, near line 59) tells the agent the same.
   - `take` then puts the workspace on that same machine, where `gh` stays signed in, and its own output says it "cannot stop an agent reaching that sign-in".
   - The "ask each time" prompt in `takeBounty` says the agent will "run that repository's code in a throwaway folder" and does not mention the sign-in.

   The real risks, neither one about money, are a stranger's code running on this machine while it is signed in to GitHub, and a draft pull request under the account's name. The owner's yes should be given on those facts. A setting must honour what it says.
2. **Payment comes up too late.** `status` already says, once per account, when the board shows no way for the solver to be paid (`payWayLines` in `packages/box-bounty/attempt.ts`). `take` says nothing. A solver can do the work, have it merged, and only then learn that nobody can pay them.

## Outcome

1. **The three places state the same two facts, and no advice the tool cannot back:**
   - `config set solving ask|allowed`;
   - the "ask each time" prompt;
   - `describe` for solvers.

   The facts:
   - the agent will run a stranger's code in a throwaway folder on this machine, while the machine stays signed in to GitHub as that account; the tool cannot keep that sign-in out of the agent's reach;
   - the draft pull request and every push go out under that account's name.

   What stays: keep every *other* credential out of the folder. What goes: "none of your credentials in reach".
2. **`take` on a bounty with a reward above $0 adds the payment lines `status` gives** (`payWayLines`), with the same once-per-account rule:
   - if `take` showed the one-step line, `status` does not repeat it;
   - a $0 bounty, or the board turned off, adds nothing.
3. **`previewTake` shows the same payment lines,** without marking them shown.

## Steps, in order

Written so any model can cook it.

1. **Tests first,** the list above, seen failing on master.
2. **The words:** write the two facts once, as constants in `wording.ts`. Use them in `changeSolving`, in the waiting prompt in `takeBounty`, and in the solver `describe` text. The account's name comes from what each place already knows: `take` has `login`; `config` and `describe` say "this machine's GitHub account".
3. **The payment lines:** after `saveTaken` in `takeBounty`, when `facts.reward > 0`, append `payWayLines(login)`. In `previewTake`, append a variant that reads but does not `markShown`.
4. **Docs:** SOLVER-CLI.md's `take` row and its paragraph. Re-record text snapshots, listing each under `## Changed expectations`.
5. **Verify,** push, hosted run, Result, merge.

That sentence is not in scope and should still pass. If it does not, list it with the reason.

## Traps

- `payWayLines` calls the board (`readPayAccepts`). It must not run when the board is off, and must not make `take` fail when the board is unreachable: today it returns a "not read" line instead. Keep that.
- The once-per-account mark (`shownFor` / `markShown`) is shared with `status`. Do not add a second mark for `take`.
- Words only state facts. Do not tell the owner the risk is small or large, and do not tell them what to choose.

- [x] **User experience:** the reader is the owner at `config set solving allowed`, and the solver agent right after `take`. Print each text as it now reads and say, for each, whether it answers "what am I agreeing to" and "will I be paid".
