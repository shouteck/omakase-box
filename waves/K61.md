# K61: a scratch folder Windows will not release never fails a test, and GitHub's storage outage never fails a run

Milestone: K (kitchen) · Station: evidence · Base: `master at dispatch` · Branch: `wave/K61` · Timebox: 90 minutes (a hosted run takes about 26 minutes); at expiry, report partial findings and stop

**Brief.** Written by the CTO on 12 November 2026 from two hosted Windows failures that were not about the code under test. Facts, read from the logs:

- **The cleanup of a scratch folder failed a test, twice.** Run 43027294715 attempt 1 (`github.test.ts:111`, "refuses missing gh, a non-GitHub remote and mismatched pushurl") and run 43088503658 attempt 1 (`k12-bounty-parallel.test.ts:54`, "withoutGh() restores PATH and GIT_EXEC_PATH"): the test's own assertions had passed, then `Error: EPERM, Permission denied: \\?\C:\Users\runneradmin\AppData\Local\Temp\box-bt1-BT6a-ci-no-gh-<random>` with `syscall: 'rm'`. That folder is `withoutGh()`'s: it holds copies of `node.exe`, `git.exe` and Git's DLLs, which a process spawned from them may still hold for a moment. The call already retries (`maxRetries: 10, retryDelay: 250`, about 2.5 s); on a slow runner that is not enough, and a leftover folder in the temp area is not a verdict on anything. The reruns of both passed. Two failures in about a dozen hosted Windows runs.
- **GitHub's own artifact storage failed a run.** Run 43088503658 attempt 2: every test step passed (`verify` PASS on all three systems); the job failed in "Upload verify run logs" after five tries: `Failed to CreateArtifact ... Unexpected token '<', "<!DOCTYPE "... is not valid JSON`, GitHub's outage answering HTML. The upload is a diagnostic aid; failing a run whose tests passed costs a 22-minute rerun.

## Outcome

A cleanup that fails because Windows still holds a file in a scratch folder retries for longer, then leaves the folder behind and the test result stands; any other cleanup fault is still thrown. The upload of the run logs cannot fail a run. Both are pinned by a test.
