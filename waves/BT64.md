# BT64: one spelling of the repository folder, so a never-publish entry holds however the folder is spelled

Milestone: BT (the bounty tool) · Station: packaging · Base: `master at dispatch` · Branch: `wave/BT64` · Timebox: 120 minutes; at expiry, report partial findings and stop
Owner decisions: D-2026-10-11-public-origin
Horizon: short (one shared helper and its callers); if the inventory below finds more than about eight callers, `/plan` first. Bug fix playbook.

**Brief.** Written by the CTO on 10 November 2026, from K50's first run on GitHub's Windows machine (run 42802182752). That machine's temp folder is `C:\Users\RUNNER~1\...`, the 8.3 short spelling of `C:\Users\runneradmin\...`. Reproduced on this host the same day by pointing `TEMP` at a short spelling (`...\Temp\KIE5A6~1`): `bt8c.test.ts` and `create.test.ts` fail 8 of 34.

**A hard stop is breached.** `bt8c.test.ts:81`: a path on the owner's never-publish list is in the shipped set (`plan.files` holds `private/...`). Mechanism, read from the code: the list is keyed by `realpathSync(repoRoot)` when written (`never-ship.ts:296`) and when read (`never-ship.ts:239`); Node's JavaScript `realpathSync` keeps an 8.3 spelling, while `create` reaches the root through `git rev-parse --show-toplevel` and `realpathSync` (`create.ts:126`), which returns the long one. One folder, two keys: the list written from one spelling is not found from the other. An owner who sets the list from a short-spelled folder and creates a bounty from the long one (or the reverse) ships what they listed.

**A false refusal from the same cause.** `snapshot.ts:204` resolves each shipped path with `realpathSync.native`, which expands short names, and compares it with a root kept in the short spelling: six `create.test.ts` junction cases refuse "1 path(s) inside the repository resolve outside it". Safe in direction, wrong in fact.

**The shared assumption:** that the repository folder the tool is handed is already its one spelling. K50 found a second instance on macOS to check here, not assume: `answer.test.ts:378`, "nothing a solver wrote runs", expected the refusal `apply-unsafe-config` and got none on `macos-15` (temp under `/var/folders`, which is `/private/var/folders`). If its cause is the same assumption, it belongs here; if not, say so and brief it apart.

## Outcome

Every place the tool turns the repository folder into a key or a base for comparison uses one function that returns one spelling for one folder (on Windows the long name; on macOS the resolved `/private/...`). The never-publish and safe-to-publish lists, the settings key for the repository, and the snapshot's inside-or-outside judgement agree however the folder was spelled.
