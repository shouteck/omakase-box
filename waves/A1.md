Milestone: A · Station: packaging · Base: `0415a31` · Branch: `wave/A1` · Run limit: A1 only; stop and report if the outcome cannot be met within this scope.

## Outcome

An owner can declare setup and guard/outcome checks for arbitrary programs, plus what a solver needs installed, without a required Node/pnpm/TypeScript/Vitest toolchain. Every declared program is checked for availability before commands execute. One documented operating-system launch rule handles Windows command-file shims without tool-specific dispatch. Existing active agreements and callers migrate together; the old agreement format and fixed command-tool enum are removed.

- Findings:
  - **F1 (defect, blocking):** the `.cmd`/`.bat` launch rule wraps each token in `"..."` but never escapes a trailing backslash. Verified by direct `cmd.exe /d /s /c` reproduction on this host: args `["trail\", "second arg", "a & b"]` reach the child as `["trail\" second","arg a","&","b"]` — the `\"` escapes the closing quote under CommandLineToArgvW rules, merging arguments. Silent argv corruption (no injection — cmd still confines the line — but "argv reaches the program verbatim" is violated for any path ending in `\`, a common Windows arg). Fix: escape `"` and trailing/embedded `\` before the closing quote, or extend the refuse-set to args ending in `\`, plus a regression test in command-checks.test.ts.
  - **F2 (host-rule noncompliance, reported not edited):** the dispatch instruction "prohibits adding/removing code comments" is violated — the diff rewrote block comments in `commands.ts`, `install.ts`, `agreement.ts`, `manifest.ts`, `export.ts`, `verify.ts`, `scaffolds.ts`, `cli.ts` and added comment lines in tests. Most rewrites describe genuinely changed behavior (arguably necessary), but the rule is strict; flagged for worker correction/CTO adjudication rather than edited by the pass.
  - **F3 (limit, not blocking):** `resolveProgram` resolves a *relative* spelled-out path (`tools/x.cmd`) against `process.cwd()` of the host process, not the check's context root — a portable spelling that resolves to a file under the checkout could run the wrong artifact. Bare-name PATH resolution and absolute paths are correct. Either resolve relative spellings against the context root or require absolute spellings + document.
  - **F4 (limit):** `requires[]` (solver prerequisites) is preflighted on the *owner* host; a solver-only tool absent on the owner blocks export/verify even though the recipient could run it. Per the brief's literal text this is required ("preflight covers every declared executable prerequisite"), noted so A2/A3 can scope preflight by context if desired.
