# K67: the owner's authority as data, and the gate once (the second pilot of the layered method)

Milestone: K (kitchen) · Station: evidence · Branch: `wave/K67` · Timebox: 240 minutes
Owner decisions: on 12 November 2026 the owner asked for a faster way to write tests for this tool; [K65](K65.md) piloted it on never-ship, the owner said "next area".

**The area.** Hard stop 3, nothing happens beyond what the owner said. The decision is `readDecision(repoRoot)`: what the owner wrote (a project level, an all-projects default, a denial) against the repository's GitHub remotes. `bt8` checked its precedence by building a posting world per case (3 to 7 s each). It is data: a table of what the owner said and the decision read, plus the gate once.

## What it does

[tests/box/bounty/owner-decision-layers.test.ts](../tests/box/bounty/owner-decision-layers.test.ts), 29 tests:

- **Level 1, the decision as data (24 rows plus 4):** six project states (nothing, allowed, ask, off, denied after being allowed, only another repository listed) against four defaults (none, allowed, ask, off), each row the owner's rule in a sentence (a project's word stands over the default, a denial blocks the default, nothing written is never allowed, another repository's word never reaches this one); and a checkout with two GitHub remotes (an all-projects default never chooses between them; another repository's listing does not decide it; listing one of its remotes does).
- **Level 2, the gate once:** one drafted bounty walked up the ladder: nothing (`owner-allow-needed`, a recorded wait, the status line), ask (`owner-answer-needed`, wait reason `owner-ask`), off (`owner-answer-needed`, `owner-off`), denied with a default allowed (`owner-allow-needed`), then a project allowed over a default ask: it posts, records `allowedBy`, and has no wait left.

## The proof (K65's method; `scripts/guard-audit.mjs` against nine breaks of `settings.ts` and `gate.ts`)

Each break was applied in a scratch worktree and `bt8` and the new file run. Results:

| break | `bt8` red | new file red |
|---|---|---|
| a repository's own decision ignored | 3 | 17 |
| the all-projects default ignored | 0 | 3 |
| a denial falls through to the default | 0 | 5 |
| the denied flag dropped | 0 | 4 |
| nothing written read as allowed | 2 | 3 |
| the owner gate always allows | 4 | 1 |
| the two held-action refusals swap names | 4 | 1 |
| wait reasons ask and off swap | 1 | 1 |
| several unlisted remotes no longer undecided (a repository listed elsewhere) | 0 (`bt16` 0) | 1 |
| the same, only the default speaking | 0 (`bt16` 1) | 1 |

- **The new file catches all ten; `bt8` catches six.** Three breaks of the precedence logic and one of the unlisted-remote rule were noticed by no old test. The unlisted-remote break was first *silent* in the comparison (neither file had a two-remote repository); adding the rows to the new file fixed that, which is what the audit is for.
- **Removed from `bt8`**, three tests the ladder and the table now hold, each red under a break only where a new test is also red: "nothing written: the post waits in a named state and prints the exact owner commands", "project-level allowed posts without asking and records which answer allowed it", "the project level is read first — a project ask stands over a default allowed, and back" (together about 14 s of `bt8`'s 50). The rest of `bt8` stays: the secret-scan holds, the one-bounty answers and the hard-stop settings words test something the layers do not.
- The nine breaks are now rows of `kitchen/reviews/guard-breaks.json` (19 in all; the static check runs in every verify).

## Changed expectations

- bt8.test.ts::nothing written: the post waits in a named state and prints the exact owner commands — replaced by the ladder's first step (the refusal name, the recorded wait and its reason, the status line) and the table's "nothing written" rows; red under the same breaks as the new tests.
- bt8.test.ts::project-level allowed posts without asking and records which answer allowed it — replaced by the ladder's last step (posted, `allowedBy` project and allowed, no wait) and the table's project rows.
- bt8.test.ts::the project level is read first — a project ask stands over a default allowed, and back — replaced by the table (the project ask over a default allowed, and every other combination) and the ladder's top step (a project allowed over a default ask posts).
