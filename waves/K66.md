# K66: the hard stops, broken on purpose (H3 of K51d)

Milestone: K (kitchen) · Station: evidence · Branch: `wave/K66` · Timebox: 240 minutes
Owner decisions: on 12 November 2026 the owner left the order and handling of the K51d hypotheses to the CTO, and asked that the work be about the tests' design and the code, not machines.

**Why.** K51b counted tests that mention a hard stop; K64 tagged them. Neither says whether a guard *works*: a test can pass on broken code. This makes K65's break proof permanent and repeatable for the guarantees that must never fail.

## What it does

- `scripts/guard-audit.mjs`: applies each break of `kitchen/reviews/guard-breaks.json` (one exact-text replacement, the guarantees it breaks, the test files tagged for them) in a throwaway `git worktree` of the committed code, builds the tool, runs those tests, and says **red** (a test failed: the guard works) or **silent** (nothing failed: a guarantee is unprotected there). A break whose text is gone is **stale**, one that matches twice is **ambiguous**, one that no longer compiles is **build-failed**. The working tree is never touched; the worktree borrows `node_modules` through a directory link removed with `rmdir`/`unlink` before the worktree is, so Git never walks into the real folder.
- `node scripts/guard-audit.mjs --check-breaks` (no run, runs inside every verify through `tests/kitchen/k66-guard-audit.test.ts`): every break's text is present once, its test files exist and carry a `// @guards` tag for its guarantees, and **every hard-stop guarantee in CONTRACTS has at least one break**. A hard stop added to CONTRACTS without a break fails the kitchen suite.
- The full audit is on demand: it takes about 40 minutes of test time for ten breaks, too long for every verify.

## What it found

- **One guard is thin.** Breaking the check on a change published for the first time (`publish-wip-never-ship`) turns exactly **one** test red, `github-history`'s "refuses work the task needs when it touches a never-ship path". The other P2 tests (unpushed commits, `--include`, the safe list) exercise other paths and do not notice. Not silent, but a single guard for a hard-stop path; BACKLOG has the line.
- **The shared rule is guarded heavily, the paths around it lightly:** the folding break turns 46 tests red, the `.env` rule 7, the create filter 9, the owner gate 32, the merge hold 10; the private-repository check 3, the settings hard-stop words 6, the board's private rule 9, the return history check 5.
- **A good break must keep the types.** Three of the first ten failed to build (`if (false)` or `undefined` made TypeScript narrow code to `never`); they were rewritten to keep their types (`Boolean(0) &&`, `&& Boolean(0)`). A break that does not compile is reported, not counted as red.
- **A global break is slow:** about eight minutes for a break of the shared rule (eleven test files). The audit is a periodic check, not a gate.
