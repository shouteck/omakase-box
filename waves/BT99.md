# BT99: every `--json` document states what may grow, and the surface check tells a compatible change from a breaking one

Milestone: BT (the bounty tool) · Station: packaging · Base: `master at dispatch` · Branch: `wave/BT99` · Timebox: 180 minutes (a hosted run takes about 25); at expiry, report partial findings and stop
Owner decisions: none
Horizon: short to medium. Feature playbook; principles: encode-lessons-in-structure, prove-it-works.

**Brief.** Written by the CTO on 24 November 2026 from the walkthrough of the `--json` documents with the owner ("yes"). It closes the codebase walkthrough.

**Why.** The documents (`packages/box-bounty/json.ts`; BOUNTY.md, the `--json` section) are well specified:
- `schema` comes first;
- "a change to a field's meaning grows `@2`, never silently";
- `null`, never a missing key;
- strangers' text only in `fromOthers`, listed in `foreignFields`;
- every field and its type pinned in `tests/box/bounty/SURFACE.txt` by `scripts/surface.mjs` (BT62: 510 field lines over 21 schemas).

Two things are missing, and the waves now briefed make them matter:

1. **No promise about what may be added.**
   - Readers are told when a document breaks, not what may grow under `@1`.
   - Waves add values: BT84 adds the stage `starting`, BT86 `ended`, and several waves add refusal names. BT87 and others add fields.
   - An agent that switches on `stage`, or on `refused`, and treats the list as fixed breaks silently.
   - Google's API guidelines treat an added field as compatible, but warn that new values in a response enum are the risky case, because "user code does not handle new values gracefully" ([AIP-180](https://aip.bybutter.com/180)). They ask each enum to say whether it is frozen or will grow ([AIP-126](https://google.aip.dev/126)). SDKs add an explicit unknown value for this ([Oracle's SDK](https://oracle-cloud-infrastructure-python-sdk.readthedocs.io/en/latest/forward-compatibility.html)).
2. **The surface check cannot tell compatible from breaking.**
   - `surface.mjs` reports any difference, and `--write` accepts it.
   - A removed field and an added one look the same to it, and SURFACE records a field's type but not the values a value-like field takes.

## Outcome

1. **The contract, written once in BOUNTY.md's `--json` section and linked from `describe --json`'s help:**
   - **Compatible, under the same `@1`:** new keys appear (read and ignore keys you do not know); an **open** field gains a value (read an unknown value as "something else", and go by the document's `next`).
   - **Breaking, needs `@2`:** a key removed or renamed; a type changed; a value added to a **closed** field; a field's meaning changed.
2. **Every value-like field is labelled open or closed, with its values,** in SURFACE.txt as new lines:
   ```
   values box-bounty/status@1 bounties[].stage open drafted|waiting|posted|answered|applied|rejected|withdrawn|undone
   ```
   - The lines are derived from the code's own types and constants by `tests/box/bounty/surface.ts`, never typed by hand.
   - The label comes from a short table in that file. Stages, refusal names (`refused`, `reason`), kinds and outcomes are **open**. A field whose values are a fixed fact of the world (`source`: `"solver"` or `"other account"`) is **closed**.
3. **`surface.mjs` sorts each difference into compatible or breaking:**
   - **Compatible:** an added field, an added value in an open field. Printed as such; `--write` accepts it.
   - **Breaking:** a removed or renamed field, a changed type, an added value in a closed field, a value removed from any field. `--write` refuses, naming the line and the rule, unless the same change moves that document's schema to `@2` in SURFACE.

   This lets an agent-facing break fail a wave the same way a test does.
4. **Each document carries its contract version** in BOUNTY.md: which fields are open, so an agent can read the list once.

## Scope

- Write: `tests/box/bounty/surface.ts` (the values lines, the open/closed table), `scripts/surface.mjs` (the classification), `tests/box/bounty/SURFACE.txt` (by `surface.mjs --write`: the new lines), `tests/box/bounty/bt62-record.test.ts` (the record's shape gains `values` lines), `docs/box-v4/BOUNTY.md` (the contract), `docs/box-v4/TESTING.md` (what the surface check now refuses), `tests/box/bounty/bt99.test.ts` (new)
- Read for context: `waves/BT62.md`, `waves/BT19.md`, `waves/BT61.md`, `packages/box-bounty/json.ts`, `packages/box-bounty/record.ts` (the stage type), `tests/box/bounty/bt40.test.ts` (refusal names)
- Do not touch: what any document contains; any schema's version (none changes in this wave)

## Traps

- **Do not label a field closed to be safe.** A closed field turns every later value into a `@2`, a cost to every reader. Closed is for values that cannot grow.
- **Refusal names grow with nearly every wave.** They are open by design, and the contract tells agents to go by `next`, never by matching a name they do not know.
- **Land it before the waves that add values** (BT84, BT86, and the refusal-adding waves), or each of those must label its own new value.
