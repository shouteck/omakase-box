## The seats

One fresh agent per seat. Each gets **only** the material listed. Each is told its goal and nothing about how the tool works, and is never shown this brief, the repository's docs or another seat's notes. The cook records each seat's transcript of commands and output, and where the agent hesitated, guessed, misread or gave up.

| Seat | Given only | Goal it is told | What it must report |
|---|---|---|---|
| **S1 Stranger** | The packed tarball (`node packages/box-cli/pack.mjs`) and its README, installed with `npm install -g <tgz> --prefix <scratch>`; a scratch clone of the sandbox | "Set this up so your coding agent can hand off work it cannot do." | Install friction; whether it found how agents learn of the tool (P1); whether it understood what becomes public (P3) and how to remove everything (P2) |
| **S2 Arriving agent** | A scratch clone of the sandbox with the tool installed, and a task it should not do itself (as in K31b: a file the project rules forbid it to edit). Run twice: instructions **off**, then **on** | The task only; the tool is not mentioned | Whether it discovers the tool at all in each run; if it does, the full create → preview → post journey on the sandbox at $0 |
| **S3 Solver** | The public URL of the S2 issue, nothing else | "This issue offers a bounty; answer it." | Whether the issue alone was enough: what to change, where to branch, how to answer, how to get paid (P7) |
| **S4 Later agent** | A second scratch clone on another settings folder, after S3 answered | "Continue whatever this project had in flight." | Whether it found the bounty, read the solution, merged or closed it, and what it told the owner |
| **S5 Owner** | Only the lines the tool addresses to the owner, collected from S1 to S4 (owner blocks, `allow` and `config` output, held messages, the payment message from a **stand-in** run with a $5 reward and a test-mode `pay-to:` link) | Answer in plain words: what did I allow, what is public, what do I owe and to whom, how do I stop it all? | Each answer graded right or wrong against the facts, with the line that misled |

The S5 payment run uses the GitHub stand-in (`tests/box/bounty/github-fixture.ts`, as K39's script extracts it), never real GitHub: the sandbox decision covers $0 posts only. Settings are always scratch (`BOX_BOUNTY_SETTINGS_DIR`), never the owner's.
