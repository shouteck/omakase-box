# BT14: what the agent reads

Milestone: BT · Station: packaging · Base: master at dispatch, after BT13 · Branch: `wave/BT14` · Timebox: 150 minutes; at expiry the cook stops and reports where it is, whatever state that is

**Pre-brief.** Written by the CTO on 14 October 2026 from K18's critique (`kitchen/reviews/K18-flow-critique.md`) and the K17 Result's list of product output found hard to read. Clarity only: what the tool does does not change, except where an item below says so. **One item removes a duplicate way to do something (the `config` repository verbs), so the pre-cook card waits for the owner's go.** The head chef checks names against master at dispatch.

## Outcome

An agent finds what it needs at the top of what it reads, is never left guessing where a file goes or what the tool changed, and is never told to do something that cannot work.

- Write: `packages/box-bounty/**`, `packages/box-cli/**` (the `bounty` commands, and the top-level `box` help), `tests/box/bounty/**`, `docs/box-v4/BOUNTY.md`.

In order of harm, as K18 ranked them. If the timebox runs out, stop at a finished item.

1. **The tool says when it edits an instruction file** (F3). The output that adds or removes the tool's notice in `AGENTS.md` or any instruction file names the file and says the change is not committed, as the tool already says of its record ("commit it with the project").
2. **`create` says where the task may be and what it leaves** (F4). One line: a task or note file may sit anywhere outside never-ship paths, and is not committed or removed for you. A title never keeps a leading `#` and stops at the end of the task's first sentence, at a stated length. The preview and the issue say the same thing about the note: if the tool wrote one, neither says none was supplied.
3. **`create` states the owner's permission** when the repository is not allowed: posting will wait for the owner. One line, so the agent can tell the owner while drafting.
4. **`status` leads with what to act on** (F5, known since K17). Solutions waiting come first, each with its pay fact and the command; the saved job context after them, never with solutions nested under it; "0 collected" not shown beside waiting pull requests; the format-block and cached-observation lines only with `--full`.
5. **A failed GitHub refresh says why** (F6). The line carries the reason's own name (`github-response-invalid`, `github-issue-mismatch`, …) and offers a retry only where a retry can help.
6. **The secret-scan advice works for a committed secret** (F9). When the flagged content is in a commit that would be published for the first time, the message says that removing it in a new commit does not help, and says what does, without suggesting the agent rewrite history on its own.
7. **Bare `config` is short** (F7). Settings that are off and were never set are left out; one line says how to see everything. **One verb per action:** a repository is added with `allow` and removed with `deny`; `config add/remove repositories` refuse by name and name the verb that replaced them (the removal the owner's go covers). A removed repository is not offered a command to remove it again. The output of `deny` says what went with the entry (its reward and limit).
8. **Small ones** (F8 and K17): top-level `box --help` lists `box bounty` first and the older commands after it, and exits 0; the first-merge notice and the pay message are one block, not two; `allow`'s line that a waiting bounty went out names the amount it states.

**Measured:** for the collecting journey and the posting journey as K18 ran them (K19's corrected stand-in), the characters an agent reads and the line where the thing it acts on first appears, before and after. One fresh collecting agent and one fresh posting agent run each journey after the change, cold; the Result gives every command not named by earlier output.

**Cases that must fail, each a named refusal that changes nothing:** `config add repositories`, `config remove repositories`; a task file on a never-ship path (as today, now with the line that says where one may go).
