# K38: the shared posted-world fixture copies safely, every time

Milestone: K · Station: evidence · Base: `master at dispatch` · Branch: `wave/K38` · Timebox: 60 minutes; at expiry, report partial findings and stop
Owner decisions: none new (the owner asked for this fix on 19 October 2026 after K30)

**Brief.** Written by the CTO on 19 October 2026. Cook: low reasoning; reviewer: medium.

## Why

The hosted run on master `6cd8a24` (run 39273307351) went red on Linux in `tests/box/bounty/bt15-guarantees.test.ts` › "a solver-added never-ship path is refused before recording or writing owner files" with `Error: ENOENT, No such file or directory '/tmp/box-bt1-posted-scratch-…/remote.git/objects'` (syscall `cp`). A rerun of the same commit passed: it is intermittent. The copy is `cloneWorld` in `tests/box/bounty/github-fixture.ts` (around line 474: `cpSync(master.scratch, scratch, { recursive: true, preserveTimestamps: true })`), which copies the shared posted master world K24 introduced for each test. Suspected cause, **to be confirmed, not assumed**: a Git process left running in the master world's bare remote (`git gc --auto`, which Git may start detached after a push, or `git maintenance`) moves or deletes objects while the copy walks the folder.

## Outcome

The shared posted world is copied without a race on every platform, and the cause is named from evidence.

## Scope

- Write: `tests/box/bounty/github-fixture.ts` (the fixture), `tests/box/bounty/support.ts` only if the fix belongs there.
- Do not touch: product code; any assertion; any other test file.

## Method

1. **Reproduce or bound it:** run `bt15-guarantees.test.ts` in a loop (at least 30 times on this host) with the suite's settings, and look for background Git processes during the copy (for example list `git` processes before `cpSync`, or set `GIT_TRACE` in the master world). If it never reproduces here, say so and rely on the evidence you can gather (does the master world's bare remote ever run `gc`? check `gc.auto`, `gc.autoDetach`, `maintenance.auto` and whether loose-object counts cross the threshold after the fixture's pushes).
2. **Fix the cause, not the symptom:** if it is automatic garbage collection or maintenance, configure the fixture's repositories (the master's bare remote and repo, at creation) with `gc.auto=0` and `maintenance.auto=false` so no background Git ever runs there, with a comment naming this wave. If the evidence points elsewhere, fix that instead and explain. A retry around `cpSync` is acceptable only as a second line, never the fix.
3. **Prove it:** run the file 30 times after the fix with no failure; run the bounty suite once.
