# PF27: the tool describes both halves, and two fresh agents prove the solver side end to end

**Brief.** Written by the CTO on 3 November 2026, the last of the waves that replace PF12 (see [SOLVER-CLI.md](../docs/box-v4/SOLVER-CLI.md)). Needs PF22 to PF26. Before PF9, so the launch gate covers the solver side.

## Outcome

An agent with the tool installed knows both of its halves. Two fresh agents prove the solver side for real, at $0, in the sandbox:
- one posts a bounty in one language;
- one whose own filter takes that language discovers it, takes it, submits, and follows it to merged;
- a third whose filter takes only another language never sees it.

(The first draft used a bounty that needs a Mac. PF23, needs, is deferred, so the filter the proof exercises is the solver's own.)

## Scope

- Write: `packages/box-bounty/` (`describe`, the instruction block, help), the board's "For agents" words, `tests/box/bounty/`.
- Do not touch: payments.

## Build

1. **`describe`'s solving half:**
   - when taking a bounty is worth it: the facts, pays on merge first, attempts in progress;
   - when it is not;
   - how to schedule `discover`;
   - to work only in `take`'s workspace.

   The same voice as the posting half.
2. **The instruction block:** one short solving line beside the posting one, shown only when the owner allowed solving. K44's agents mostly ignored the block, so fewer words, not more.
3. **The "For agents" page:** the solving path in a few lines. Its look changes only with the owner's approval of the before-and-after (D-2026-11-02-site-looks-need-approval).
4. **One GitHub account, by the owner's choice** (3 November 2026: "Let's scrap the second GitHub account").
   - The sandbox runs on the owner's one account, so the poster and the solver are the same person there. No fork is made, and the board treats the merge as self-dealing.
   - **Three things are proven on the stand-in GitHub in tests, not on real GitHub:**
     - the fork path;
     - a payee other than the poster;
     - a merge that counts in the record and is charged by pay on merge.
   - **The Result names them as test-proven.** No second account is created or asked for.
5. **The proof, run by fresh sessions** started from an owner turn, in scratch folders, on the sandbox:
   - **the poster:** a task in one language, say TypeScript;
   - **the solver whose filter takes it:** told only "the owner allowed solving; you need income this week; you work in TypeScript";
   - **the solver whose filter does not:** the same, in Go.

   Record where each hesitates or guesses wrong. Fix blockers in this wave.

## Done when

- `node scripts/verify.mjs test:box-bounty test:platform test:kitchen` exits 0 on the final commit.
- **The proof:** it ran as written. The TypeScript solver reached merged, and the Go solver never saw the bounty. Each session's hesitations are recorded.

- **Approval:** the owner's approval of the "For agents" before-and-after, quoted.
- **Deploy:** the live board's `exceededCpu` is read before and after. Deploying needs the owner's word.
