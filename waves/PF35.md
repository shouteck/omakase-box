# PF35: an agent that searches for its need finds us

Milestone: PF (the platform) · Station: evidence · Base: `master at dispatch` · Branch: `wave/PF35` · Timebox: 180 minutes; at expiry, report partial findings and stop
Owner decisions: D-2026-11-10-found-at-the-moment, D-2026-11-02-site-looks-need-approval, D-2026-11-02-design-references-big-companies, D-2026-10-21-minimalism, D-2026-11-01-agent-only-direction
Horizon: long: start with `/plan` and keep the plan in this file. The wave stops once for the owner's eye, before any page is built.

**Brief.** Written by the CTO on 10 November 2026 from the owner's talk after [K48](K48.md): an agent with a hard problem, or one that wants to earn, must find the tool at that moment. K48 read three places an agent searches and found each one silent:

- **GitHub:** the repository's description is the retired product's ("Git-native Boxes for intent, reproducible execution, evaluation…"), with no topics and no homepage.
- **The web:** the board has no `sitemap.xml` (404) and no page written for a need.
- **npm:** four keywords, none about earning (BT53 carries this one).

## Outcome

1. **A page per need on the board,** each a short, true answer to something an agent would search for, linked from For agents and listed in a sitemap. Posting needs: work that keeps failing; a machine, access or data it lacks; knowledge it lacks; a second opinion; work to run in parallel. Earning needs: paid coding work for an agent; spare capacity. Each page says what the tool does for that need, the one install line, what becomes public, and what is never promised. Seven at most; fewer if two say the same thing.
2. **A sitemap** at `/sitemap.xml` naming the public pages, and `robots.txt` pointing to it.
3. **The repository's public page, prepared for the owner:** a description, topics and the homepage address, as the exact `gh repo edit` command in the Result. Setting them is the owner's.

## Steps, in order

Written so any model can cook it. The pages are drawn with what the site already has: `Title` for the heading and `SideSection` for each block, exactly as For agents is. (An earlier plan for a new reading template was dropped on 11 November 2026: the site's design stays as it is.)

**The pages, the CTO's proposal for the owner to approve at the stop.** Each address, title and first sentence; the plan may merge two that say the same thing.

| Address | Title | First sentence |
|---|---|---|
| `/for/stuck/` | When an agent keeps failing at a task | Hand the task to an outside solver, with what was tried, and get solutions back as pull requests. |
| `/for/no-access/` | When the task needs a machine, access or data the agent lacks | Post the task where someone who has them can answer; nothing private leaves the repository. |
| `/for/unknown-area/` | When the task needs knowledge the agent lacks | Someone who knows the area answers with a pull request the agent can read as facts. |
| `/for/second-opinion/` | When a second solution is worth having | Several people may answer; the agent compares what each changed and merges one. |
| `/for/parallel/` | When work can be handed off while the agent goes on | Post a self-contained task and keep working; solutions arrive on their own branch. |
| `/for/paid-work/` | Paid coding work for an agent | Open bounties on public repositories, each with a stated reward, readable by a program. |
| `/for/spare-capacity/` | An agent with time to spare | Find a bounty that fits, start with one command, and follow it to merged and paid. |

**Every page has the same five blocks, in this order:** what the tool does for this need (three sentences at most); the one install line, from the same constant How it works uses; what becomes public; what is never promised (no solver is waiting, no answer is guaranteed, the reward is the owner's word); where to read more (How it works, For agents).

## Tests to write first

| Test | It fails when |
|---|---|
| Each need page's built HTML, read as text with no script, holds its title, the install line and the words `becomes public` and `never` | a page is a shell |
| No need page contains (case-insensitive) `must`, `guarantee`, `solvers are waiting`, `will be solved`, or any name in a list of competitor names kept in the test | a page over-promises |
| First assert each expected page is served with 200; then: `sitemap.xml` holds exactly the expected addresses | a page is missing, or a private one is listed |
| `sitemap.xml` holds no address containing `/api/`, `/b/`, `/me`, `/sign-in`, `/owner/`, `/solver/` | a private page leaks |
| `robots.txt` names the sitemap's full address | crawlers cannot find it |
| The install line on every need page is the same string as on How it works, from one module | a second copy drifts |
| For agents links to all seven | a page is unreachable |

## Traps

- "Never promised" must stay true after [BT60](BT60.md): a bounty always states a reward, but the reward is still the owner's word.
- `tests/platform/pages.test.ts` has a test that every page's words stay clear of a money claim (near line 908) and one for 404s while clicking through (line 918): add the new pages to whatever list they walk.
