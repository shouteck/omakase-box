# BT97: Git's own safety checks, kept and pinned, each with its reference

Milestone: BT (the bounty tool) · Station: packaging · Base: `master at dispatch` · Branch: `wave/BT97` · Timebox: 240 minutes (a hosted run takes about 25); at expiry, report partial findings and stop
Owner decisions: D-2026-11-26-take-fsck-legacy-warnings
Horizon: medium: the layer under every Git call. Bug fix playbook; principles: boundary-discipline, encode-lessons-in-structure, prove-it-works.

**Brief.** Written by the CTO on 24 November 2026 from the walkthrough of the Git plumbing (`packages/box-bounty/git.ts`) with the owner, who asked that it be held to the references ("This is the place where things has to be correct"; "yes").

**Why.** Every defence in `git.ts` was checked against Git's documentation and its security advisories on 24 November 2026. These match:
- hooks off (`core.hooksPath=/dev/null`);
- the file-system monitor off (`core.fsmonitor=false`, the route of CVE-2022-24765);
- no submodule recursion (the advisories' workaround for CVE-2024-32002 and CVE-2025-48384);
- filters and merge drivers blanked for foreign content, with attributes pinned to the owner's `HEAD` (`GIT_ATTR_SOURCE`);
- `--no-ext-diff --no-textconv` and `diff.external=`;
- `ext::` left at Git's default of never, with `insteadOf` rewrites checked;
- merges given `-m`, and network calls `GIT_TERMINAL_PROMPT=0`;
- tokens kept out of Git's environment.

Three do not:

1. **The ownership check is switched off on every call.** `safeArgs` (`git.ts`) prefixes every invocation with `-c safe.directory=<repo>`, "matching how every kitchen git call is made".
   - Git 2.35.2 refuses a repository owned by another account, because its configuration can run programs (`core.fsmonitor`). `safe.directory` exists "for intentionally shared repositories", and `*` is "a complete opt-out of this security check" ([git-config](https://git-scm.com/docs/git-config); [CVE-2022-24765](https://github.blog/open-source/git/git-security-vulnerability-announced/)).
   - In owner mode the tool runs the repository's configured filters (`gitFilteredBlob`, `create`'s snapshot). In a repository someone else owns, that configuration is theirs.
   - The override is the kitchen's environment (AGENTS.md: `.git` belongs to the owner's account; agents may run as another), not the product's.
2. **Strangers' objects are fetched unchecked.**
   - `collect.ts` fetches `refs/pull/<n>/head` into the owner's repository, and `take` clones a stranger's repository, with no `fsckObjects`.
   - `fetch.fsckObjects` aborts a fetch on malformed objects and on known attacks such as a malicious `.gitmodules` or a `.git` path. It is "ignored if seen in the repository-level config (this is a safety measure against fetching from untrusted repositories)", so it must be given on the command line ([git-config](https://git-scm.com/docs/git-config); [git-fetch](https://git-scm.com/docs/git-fetch)).
3. **Git versions with known clone exploits pass silently.**
   - `GIT_LEAST` is 2.40, the least the tool works on.
   - CVE-2024-32002 and CVE-2024-32004 are fixed in 2.45.1 ([GitHub Blog](https://github.blog/open-source/git/securing-git-addressing-5-new-vulnerabilities/)), and CVE-2025-48384 in 2.50.1 and its backports ([advisory](https://github.com/git/git/security/advisories/GHSA-vwqx-4fm8-6qc9)).
   - The tool's own calls avoid each exploit's precondition (no recursive clone, no local clone of untrusted repositories). But after `take`, the agent runs its own Git in a stranger's workspace.

Also short of the references: `take`'s clone of stranger content relies on Git's default transport policy, rather than an explicit allow-list (`GIT_ALLOW_PROTOCOL`, [git](https://git-scm.com/docs/git)).

## Outcome

1. **The product respects Git's ownership check.**
   - `safeArgs` no longer adds `safe.directory`.
   - When Git refuses a repository as dubious ownership, the tool refuses with a new reason, `git-repository-not-trusted`: "Git does not trust `<path>`: it is owned by another account, and its configuration could run programs. Nothing was run. next: if you trust it, run git config --global --add safe.directory `<path>` yourself".
   - The kitchen's own Git calls keep their `-c safe.directory=…`, as AGENTS.md prescribes. The test environment that runs the product as another account sets `safe.directory` in its own global configuration, never in product code.
2. **Every fetch of a stranger's objects is checked.**
   - `-c fetch.fsckObjects=true` on the solution fetch (`collect.ts`), and `-c transfer.fsckObjects=true` on `take`'s clone (`take.ts`) and on its later fetches of the bounty branch.
   - A check that fails refuses with a new reason, `git-objects-rejected`, quoting Git's own message, and nothing is collected or taken.
   - The owner's own fetches (shared memory, the publish plan) are unchanged.
3. **`take`'s clone allows HTTPS only:** `GIT_ALLOW_PROTOCOL=https` in that call's environment. The address is the tool's own (`https://github.com/<repository>.git`), so nothing legitimate is lost.
4. **An old Git is named once.**
   - When the installed Git is older than the fixed releases in a pinned list, bare `omakase-box` and `take` say once: "your Git `<x>` is older than the releases that fix known clone vulnerabilities (`<list>`); the tool's own calls avoid them, but your agent's own Git commands in a bounty's workspace do not; upgrade from https://git-scm.com".
   - The list (`packages/box-bounty/git-advisories.json`) holds each advisory's id, address and fixed versions, read from the advisories themselves at the time of the wave.
   - `GIT_LEAST` stays 2.40.
5. **The defences are written down and pinned.**
   - `docs/box-v4/GIT-DEFENCES.md` has one row per defence: what it stops, the flag or variable, which calls carry it, and its reference.
   - `tests/box/bounty/git-defences.test.ts` reads the table and checks the real argument list and environment of every Git call kind, captured through the Git seam the tests already use. A defence that drops out of any call fails, naming the row and the call.

## Traps

- **Some old, legitimate repositories carry harmless historic oddities that `fsck` rejects** (a bad time zone in an old commit). For `take`'s clone of a whole repository, the refusal names this and quotes Git's message. Do not turn checks off to make a clone pass. The Result says whether any well-known public repository failed.
- **The kitchen's tests may run the product as another account,** which is exactly what the override hid. Give the test environment its own global `safe.directory` in a scratch `HOME`, never the product.
- **`GIT_ALLOW_PROTOCOL` applies to every subprocess of that call,** which is fine for `take`'s clone. Never set it for calls that reach the owner's own remotes, which may use SSH.
