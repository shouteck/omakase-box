# D3.1: verify a submitted patch in the owner repository and merge it

Milestone: D3 · Station: packaging · Base: master after D2.2 · Branch: `wave/D3.1` · Timebox: 4 hours

## Outcome

`box verify <submission>` (or the CLI verb the D2.2 wave shipped — reuse its naming) applies the exact submitted patch to a clean checkout of the owner repository at the Box's base commit, runs the owner-side checks — including the surrounding interfaces the package did not contain — and reports a verdict. On pass, the owner merges through ordinary Git with Box/attempt identity in the commit message. Every failure is classified: preparation defect (package lacked something), environment failure, or implementation failure against a published obligation.

## Scope

- Write: `packages/box-cli/**`, `packages/box-package/**` (owner-side verify), `tests/box/package/**`, agreement schema extension if owner checks need declaring (`ownerChecks` or equivalent).
- Read: the D2.1/D2.2 output, `packages/evaluation` patch-validation code (reuse if it fits), SUPPORTED-CASE.md owner-validation section.
- Do not touch: the D2.2 recipient contract, `.execution/**`, console/service code.

## Done when

- `node scripts/verify.mjs test:box-package` exits 0 on the final commit.
- End-to-end on the real artifact: the Request-A submission produced in D2.2 (or a fresh one re-derived the same way) verifies green: apply to a temp clone/worktree at the recorded base commit, owner checks pass, then an ordinary `git merge`/cherry-pick lands the change in a scratch owner history with Box/attempt identity in the message.
- A no-op or wrong patch is PROVEN to fail owner-side — the owner checks must include at least one assertion that the outcome actually happened (e.g. for Request A: the config content / applied headers on a non-localhost route and `/health` exemption), not just that the package's own checks ran. If that means adding an owner-side check to the fixture, do it.
- Negatives each tested: stale base commit, re-submitted identical attempt (replay policy: same attempt = idempotent accept or explicit reject — pick and document), patch touching non-editable owner paths, and a local-pass-but-owner-fail case (e.g. a change that satisfies the package evaluator but breaks an owner-only interface — if constructing one needs contrivance, a named missing-file/gap case suffices with reasoning).
- Failure classification is emitted per failure with the three labels above.

## Review lenses

- [x] **Security:** patch application boundary — path traversal in patch targets, apply outside worktree, forged attempt identity, privilege of doing owner-side writes. Reviewer attacks each.
- [ ] **User experience:** not applicable.
- [x] **Measurement fairness:** the classification labels feed D4's evidence — the reviewer checks a misclassified failure isn't possible silently (each failure names its class).
- [ ] **Second model family:** not available tonight; record.

- The merge is into a SCRATCH branch/clone, never into real master — real merges go through the reviewed wave process.
