# K5: verify speed 1 — stop repeating work

Milestone: K · Station: evidence · Base: `959b04f` · Branch: `wave/K5` · Timebox: 5 hours

## Outcome

`node scripts/verify.mjs` stops spending minutes on work already proven: a step that passed on this exact commit with a clean tree is reused instead of re-run (recorded as `reused` with its source run), and suites the branch never touched are skipped by `check` unless `--full` is passed. Nothing about what counts as a PASS changes — a reused step is a real recorded PASS on the same commit, and `--fresh` always runs for real.

## Scope

- Write: `scripts/verify.mjs`, `scripts/workspace.mjs`, `scripts/suite.mjs`, `package.json`, `tests/kitchen/**`, `templates/wave.md`, `docs/box-v4/KITCHEN.md`, `kitchen/roles/reviewer.md`
- Read for context: `.kitchen/runs/*/summary.json` schema (K4 reads them — reuse `kitchen-stats.mjs` helpers if extractable, else duplicate minimally), how suites map to paths (`scripts/suite.mjs`, `package.json`), how check selects suites today
- Do not touch: test content (no assertion changes), product code, `.execution/**`, `tests/containers/`

## Done when

- `node scripts/verify.mjs test:kitchen` exits 0 on the final commit, plus `node scripts/verify.mjs` (full) once on the branch.
- A step that already passed on this exact commit with a clean tree reports `reused` naming its source run, costs ~0 s, and counts as pass. `--fresh` runs it for real. A dirty tree or different commit never gets a reused result.
- A suite named in the invocation is not run a second time inside the same run when check already ran it.
- `check` runs typecheck + boundary check + only the suites whose paths the branch touched since master (diff-path → suite mapping lives somewhere readable); touching shared tooling (`scripts/`, `package.json`, lockfile, test config) runs everything; `--full` runs everything.
- Measured: `node scripts/kitchen-stats.mjs` before/after numbers — at least five verify runs each on the same commit, with spread — recorded in the wave Result. Keep the change only if the numbers support it (report either way).
- A deliberately broken test in a suite the branch did NOT touch is still caught by `--full` (prove it in a test or scripted demo, then revert).
- Changing one byte and committing invalidates every reused result for that branch.
- `KITCHEN.md` and `kitchen/roles/reviewer.md` gain the contract: the pass may rely on a recorded PASS for the same commit and spends its time on the diff, lenses and attacks; it runs `--fresh` when it doubts the record. `templates/wave.md` gains the `--full` before milestone-close/overnight-stop line.
- No assertion removed or weakened; STALL (K4) still works unchanged.

## Review lenses

- [x] **Security:** the reuse record is the thing being trusted — the reviewer tries to obtain a `reused`-PASS for a commit that never really passed (forged summary, wrong SHA, dirty tree, renamed branch, copy-pasted run dir).
- [x] **Measurement fairness:** the before/after numbers justify keeping this — reviewer re-measures on its own runs (not the cook's) and checks the counting is honest (a reused step's saved time vs claimed).
- [ ] **User experience:** not ticked.
- [ ] **Second model family:** not available on this host; record that.

## Notes for the worker

- Baseline (task graph): night of 5 Oct — 120 verify minutes in 398, 11 of 25 passing runs repeated already-passed suites (37 min), check ~106 s/run, auth suite ran 18 times. K4's page is your measuring instrument — pin the measurement window (e.g. a fixed list of run dirs) so before/after are comparable.
- The `.kitchen/runs/<ts>-<sha>/summary.json` record is the trust anchor — reuse must verify commit SHA, clean-tree flag and step verdict from it, not from filenames.
- Path→suite mapping: keep it small and explicit (a table in suite.mjs or a constants file); unknown/unmapped paths must fail safe — run the suite.
- Think about staleness: a reused check result must also be invalid if the files it covers changed *within* the same commit-identity claim (they can't — same commit = same tree; but a dirty tree must never reuse).
- `verify.mjs` is the acceptance command; keep the diff reviewable. STALL counting (K4) and reuse interact: a `reused` step is a pass for streak purposes only if it was a real PASS on this commit.
