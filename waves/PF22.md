# PF22: the board answers "new since", with the facts an agent needs to weigh a bounty

Milestone: PF (the platform) · Station: packaging · Base: `master at dispatch` · Branch: `wave/PF22` · Timebox: 150 minutes; at expiry, report partial findings and stop
Owner decisions: D-2026-11-03-solver-in-the-tool, D-2026-11-01-pay-on-merge
Horizon: short. Feature playbook; principles: subtract-before-you-add, prove-it-works

**Brief.** Written by the CTO on 3 November 2026, the first of the waves that replace PF12 (see [SOLVER-CLI.md](../docs/box-v4/SOLVER-CLI.md)). The board's part only; the tool's solver commands follow in PF24 to PF26.

## Outcome

A solver checking on its own schedule asks the board "what is new since my bookmark" and gets each new bounty once. Each answer carries the facts that change whether a bounty is worth taking.

## Scope

- Write: `packages/box-platform/src/feed.ts`, `mcp.ts`, `query.ts` as needed, `tests/platform/`.
- Do not touch: the CLI, payments, charging, the site's pages.

## Build

1. **"New since":** the feed and `find_bounties` take a forward bookmark. Each new bounty is returned once, in a stable order, across pages and restarts. Today's cursor pages backwards from the newest. Every answer carries an `ETag`. The stated polling floor becomes 15 minutes for scheduled agents.
2. **Attempts in progress:** for each bounty, open draft pull requests with their author, age and whether they have commits, beside the open and all-time counts. Facts only.
   - **This is new data:** the board does not store `draft` or a commit count today (`refresh.ts`).
   - **What the refresh must read:** `draft` comes in GitHub's pull request list the refresh already fetches. "Has commits beyond the empty one" may need one more request per open draft.
   - **The plan measures** that extra reading against the refresh's GitHub budget and Workers Free's subrequests. If it does not fit, the plan stores `draft` only and says why. A schema change needs a migration file, run before the deploy, as PF19's was.
3. **The owner's time to decide:** median days from a bounty's first pull request to its merge or close, over that owner's bounties, beside the existing payment record.
4. **The poster's own pull request:** a fact when the only open pull request is by the poster.
5. **`pays_on_merge`'s words:** say "the reward equals the one the owner approved for pay on merge here" (PF20), not "within their limit".

## Done when

- `node scripts/verify.mjs test:platform test:kitchen` exits 0 on the final commit.
- **Paging:** a test pages "new since" across a restart and a new bounty arriving mid-page: each bounty exactly once, none skipped. A crafted bookmark is refused by name.
- **Each new fact:** a test fails if its value is made fixed. Each filter test first shows the row is really there.
- **Budget:** 500 checks every 15 minutes is measured on the stand-in, as requests and rows read, against Workers Free's daily limits.
- **Deploy:** the live board's `exceededCpu` is read before and after. Deploying needs the owner's word.
