# D2.1-proto: compare three ways of selecting Box source

Milestone: D2 · Station: packaging · Base: current master · Branches: `proto/D2.1-a`, `proto/D2.1-b`, `proto/D2.1-c` (throwaway, never merged) · Timebox: 3 hours total

## Outcome

A written comparison, in this wave file, of three small throwaway implementations that answer the same question: given the approved Request A agreement for `examples/private-shop`, which files does the Box folder get? The winner's *idea* feeds the real D2.1 brief; all prototype code is discarded. This wave merges nothing but this file.

## The task each attempt must solve

Input: the Request A agreement (editable `config/response-security.json`; runnable closure is `src/policy/loader.ts` + `src/policy/strict-json.ts` + the config; `zod` declared; `src/private/*` must never be exported) and the `examples/private-shop` tree. Read `docs/box-v4/delegation/SUPPORTED-CASE.md` first — its runnable-closure table is the ground truth.

Each attempt produces a folder and must pass the same check: copy the produced folder to a clean directory outside the repo, `pnpm install --frozen-lockfile` (or an equivalent minimal install of just `zod`, `typescript`, `vitest`), then `tsc --noEmit` and a tiny vitest check that calls `loadResponsePolicy`/`applyResponsePolicy`. Report for each: exact file list produced, whether the clean check passed, share of `examples/private-shop` source disclosed (files shipped / total source files), owner preparation effort (what a human had to write by hand), and whether `src/private/*` leaked.

## The three attempts

- **A — owner manifest + import-closure check.** The owner writes a manifest listing files; the tool verifies the manifest is closed under imports (every import of an included file resolves inside the set or to a declared package/stub) and that no excluded/protected path is in the set.
- **B — TS-program selection.** Start from the editable paths and declared entrypoints, walk the TypeScript compiler's module resolution to derive the file set automatically; anything reachable-but-excluded is a named gap.
- **C — manifest + type-only stubs.** Like A, but files outside the editable surface that are imported may be replaced by generated type-only stubs (declarations, no implementation) instead of being shipped or failing.

One at a time on this machine. Keep each attempt small — a single script plus fixture scaffolding is enough; this is not the product CLI.

## Comparison (worker, three throwaway attempts)

All three attempts produced a folder for Request A and ran the identical clean-directory
check (`proto/clean-check.mjs`): copy the produced folder to a fresh dir under `%TEMP%`
(outside the repo), `pnpm install --frozen-lockfile`, `pnpm exec tsc --noEmit`,
`pnpm exec vitest run evaluator/request-a.test.ts` (calls `loadResponsePolicy` +
`applyResponsePolicy` incl. HSTS gating and `/health` exemption), plus a private-byte
scan. Fixture total = 15 source files under `examples/private-shop` excluding
`node_modules/`, `dist/`, `reference-solutions/`.

### Attempt A — owner manifest + import-closure check — branch `proto/D2.1-a`, commit `a1853969e863c6b7bcc6f20e0bfeced7abfd1157`

- Produced files (7): `package.json`, `pnpm-lock.yaml`, `tsconfig.json`, `evaluator/request-a.test.ts`, `src/config/response-security.json`, `src/policy/loader.ts`, `src/policy/strict-json.ts`
- Clean check: **PASS** (`check-a.log`: install 41 pkgs, tsc exit 0, vitest 2/2)
- Disclosed share: **3/15** owner files (20%)
- Owner prep: hand-written 3-entry manifest with Box-path mapping + declared `zod` + excluded prefixes (~22 lines JSON). Correctness of the list is on the owner.
- `src/private/*` leak: none.
- Negatives verified: a manifest shipping `src/server.ts` fails naming undeclared `fastify` + `src/selection/api.ts` NOT-SHIPPED; a manifest dropping `strict-json.ts` fails naming the unclosed import.

### Attempt B — TS-program selection — branch `proto/D2.1-b`, commit `b85bdaa47a4d26e4d5c8c14ca86ad951612fef46`

- Produced files (7): **byte-identical selection to A** (same 7 files)
- Clean check: **PASS** (`check-b.log`: tsc exit 0, vitest 2/2)
- Disclosed share: **3/15** owner files (20%)
- Owner prep: ~9-line agreement — entrypoints `[src/policy/loader.ts]`, editable mapping for `config/response-security.json`, declared `zod`, excluded prefixes. **No file list.**
- `src/private/*` leak: none.
- Gap evidence (`node select.mjs src/server.ts`): with `server.ts` as an added root the compiler walk reaches `src/selection/api.ts` and `src/private/eligibility.ts`; the tool names `eligibility.ts` as a reachable-but-excluded GAP with the importing chain — the "preparation gap" the station card demands, produced automatically.
- Caveat found: `config/response-security.json` is not import-reachable — non-module editable inputs must come from the agreement, not the walk.

### Attempt C — manifest + generated type-only stubs — branch `proto/D2.1-c`, commit `6a1f9611b9cd7fd5c714ac41b06d28bb377eb56d`

- Produced files (11): A's 7 + `src/server.ts`, `src/selection/api.ts` (read-context, compilable), `src/private/eligibility.d.ts` (generated), `types/fastify.d.ts` (generated shim)
- Clean check: **PASS with sanitized stubs** (`check-c.log`: tsc exit 0, vitest 2/2). **Honest failure recorded** (`check-c-raw.log`): raw `ts.transpileDeclaration` output embeds `PRIVATE_ELIGIBILITY_CANARY = "SYNTHETIC_PRIVATE_ELIGIBILITY_CANARY_M0"` — a private value byte inside a "type-only" stub — and a bare `any` module shim fails `noImplicitAny` on context files. Both needed fixes before the pass.
- Disclosed share: **5/15** owner files (33%) + the protected module's exported *shape* (interface `SyntheticSubject`, `derivePrivateOptions` signature incl. field names like `monthlyPriceCents`) via the sanctioned `.d.ts`.
- `src/private/*` leak: none after literal-stripping (no canary values, no body identifiers, no `.ts` under `src/private/`); declaration names disclosed by design.
- Owner prep: A's manifest + 2 `stubPolicy` entries.

### Recommendation for the real D2.1 brief

**Use B's compiler-derived closure as the spine, wrapped in A's manifest/agreement surface.**
Evidence: B produced the identical correct package to A with strictly less owner input
(no hand file list to get wrong), and it names reachable-but-excluded gaps automatically —
which is exactly the unsupported-coupling/preparation-gap classification the station needs.
B's one blind spot (non-module editable files like the JSON config) is covered by keeping
the agreement's explicit editable mapping. Keep A's closure check as the verifier on the
derived set — the two compose naturally: derive with the compiler, verify closed + clean.

**Defer C's stubbing to an explicit opt-in for read-context files only, never runnable
deps.** It works (server.ts + api.ts compile against generated stubs, doubling useful
context) but adds a real leak vector — `transpileDeclaration` copies const initializers
verbatim — and a disclosure surface (the whole exported shape of a protected module).
If D2.1 keeps stubs, it must require literal-stripping, a private-byte scan, and an
owner-visible list of what each stub discloses.

Also learned for the real implementation: pnpm cannot write a lockfile for a non-member
dir inside this workspace — the real exporter must resolve the Box lockfile in a staging
dir outside the repo, as these scripts do.

### Playbook / principles applied

- `playbooks/prototype.md`: throwaway scripts under `proto/`, three variants behind one
  shared check, decision + artifacts are the output, code discarded.
- `principle-exhaust-the-design-space`: ran all three genuinely different mechanisms on
  the same fixture/check rather than picking one on paper; the C raw-stub failure is a
  finding the paper design would have missed.
- `principle-prove-it-works`: every claim is backed by a real clean-directory install +
  compile + test run (logs committed per branch), plus negative runs proving the tools
  actually reject bad selections — not just that they accept good ones.
