# K11: the kitchen's stats page stays fast as run records grow

Milestone: K (kitchen) · Station: evidence · Base: master at the commit that adds this file · Branch: `wave/K11` · Timebox: 45 minutes; at expiry, report partial findings and stop

## Outcome

`node scripts/verify.mjs test:kitchen` is green on this host again, and stays green as more runs are recorded.

**What the CTO found on 11 October 2026.** `test:kitchen` failed twice in a row on master at `a7a2794`, a commit that changed only wave files and documents. One test fails: `tests/kitchen/kitchen-stats.test.ts`, "exits 1 naming the broken limit on a fabricated root, 0 on the real repo", on its 30-second timeout. Run by hand on the real repository, `node scripts/kitchen-stats.mjs` exits 0 and prints the right page, but takes 29.8 seconds. `.kitchen/runs` holds 252 run records and the page starts `git` for each (`scripts/kitchen-stats.mjs` lines 136 and 141), so its time grows with every verify run. The same suite passed earlier that day at `f9402d7` in 98 seconds, with four fewer records. The off-machine run is unaffected: a fresh checkout has no run records.

Nothing the page reports is wrong. It is slow, and the test's limit is where the slowness shows.

- **The page does not start a process per record.** Whatever it needs from Git (which commits are on master, which branch a run belonged to) is read in a fixed, small number of calls however many records there are. State the number before and after.
- **Measured, both ways:** the page's wall time on the real repository before and after, three runs each, with the spread; and on a fabricated root with ten times today's record count, to show the time no longer grows with it in the way it did.
- **The page prints the same thing.** Its output on the real repository before and after the change is identical apart from lines that carry the run just made. Save both and diff them; say what differed.
- **The test's time limit is not raised to make it pass.** If, after the fix, the test still needs longer than its limit for a reason that is not record count, say why and stop.
- A test pins the property: a fabricated root with many records is processed with a bounded number of Git calls (counted, not timed, so it cannot flake on a busy machine).
