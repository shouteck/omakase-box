# PF54: Repository authority for new CLI-posted bounties

Milestone: platform · Station: packaging · Base: `71f873ee` · Branch: `devin/1795379505-cli-post-authority`
Host: Devin Linux; model identity not independently observed. Owner authorized implementation and push, no PR.

## Brief

New unmarked CLI-format issues must not be listed merely because anyone can open a public issue. Trust GitHub's issue `author_association`: OWNER/COLLABORATOR need no additional read; MEMBER requires one successful read confirming the format's bounty branch exists. All other/missing associations are refused and logged. Budget exhaustion holds admission for retry. Existing rows keep refreshing unchanged, including rows admitted before this rule; this intentionally leaves historic unauthorized admissions in place. Prepared issues retain PF53 admission/approval; session/listed imports, take, payment and merge are outside scope.

## Plan

Bug-fix playbook and packaging station read. Boundary Discipline puts the shared admission gate before storage on both search and hint/lookNow, not in the format parser: the parser cannot know existing-row status or read GitHub. No schema/migration or extra owner/collaborator read.

1. Add PF54 failing search/hint regressions using the real API/stand-in, covering authority, branch read counts, budget retry and existing rows.
2. Gate new unmarked CLI admissions at search/storeIssue and pass the existing GitHub budget object through; document agent-facing posting authority.
3. Commit, run BT/platform coverage through verify and the test-edit gate, review the diff, record results and push the branch without opening a PR.

## Done when

- Search and hint/lookNow exercise OWNER, COLLABORATOR, MEMBER, CONTRIBUTOR, FIRST_TIME_CONTRIBUTOR, NONE and missing association.
- MEMBER requires an existing branch; one additional read occurs on initial admission only. Missing branch, budget exhaustion and GitHub failure cannot list the bounty; retries can admit it later.
- An existing row keeps refreshing regardless of current association/branch; PF53 tests and normal owner CLI posting remain green.
- `env HOME=$HOME/kitchen-home node scripts/verify.mjs test:platform` and `node scripts/test-edit-gate.mjs --base origin/master --wave PF54` pass.

## Lenses

- [ ] Security: no search/hint authority bypass; failed branch proof never admits; existing-row exemption is explicit.
- [ ] User experience: refusal reason is logged, docs state who can post without changing solver/payment behavior.

## Changed expectations

- packages/box-platform/standin/standin.ts::issueJson — Existing CLI fixtures previously omitted GitHub's issue author_association and implicitly represented trusted posters. Default their payloads to OWNER so those established journeys retain that premise under the new admission rule; add an explicit association override (null omits it) for PF54 hostile/missing cases. No existing test assertion is changed.
- packages/box-platform/standin/replay.ts::issues — The local CLI replay's GitHub adapter also omitted association. Derive OWNER only for the fixture repository's owner login and NONE for strangers, preserving legitimate local CLI posts under the new rule. PF54 pins both identities; no existing test assertion changes.

## Result

Reproduction before the production change, using real search and /api/hint against localhost GitHub: PF54 yielded `24 failed | 6 passed (30)`. Unauthorized issues were stored, MEMBER branch proofs were never read, and the two-read budget admitted MEMBER before proof. The same cases run against the fix. Search budget retries observe its existing 15-minute cadence; the test advances 20 minutes rather than assuming the failed search resets its search_tried_at timestamp.

Initial implementation passed all 30 cases. Diff review found that a search page containing multiple new MEMBER posts could lose its successful proof when a later branch read exhausts the budget, because normal search writes wait until page end. Flush pending writes immediately after a newly proven MEMBER admission, preserving listed_seq order and progress on the two-read Worker budget. An additional multi-MEMBER regression covers three scheduled searches at that unchanged cap. The final check also covers the CLI replay adapter's owner/stranger payloads.
