# PF53: Prepare and approve a packaged branch without the CLI

Milestone: platform · Station: packaging · Base: `20aad9bf` · Branch: `devin/1795376351-agent-branch-post`
Owner decisions: explicit PF53 brief. Horizon: long. Host: Devin Linux; model identity not independently observed.

## Outcome

A credential-free prepare call checks declared paths and returns the CLI issue format and bounty branch. After the agent pushes and opens the issue with its own GitHub access, import verifies the public branch tip and complete tree before storing a pending posted bounty. Only an OWNER/COLLABORATOR approval comment makes it discoverable. The agent must check all tip-tree paths and every path touched by commits not on the remote default branch before pushing: board checks cannot undo publication or prove a caller supplied a complete history.

## Plan

Feature playbook read; architect skipped: the user settled the design and existing pending lifecycle supplies the precedent. Boundary Discipline keeps path matching/issue rendering pure; Laziness Protocol reuses pending approval and existing posted targeting rather than introducing a parallel bounty kind.

1. Extract shared pure built-ins/.boxignore matching and issue rendering, keeping CLI behavior and tests unchanged.
2. Add bounded, atomically limited, zero-GitHub-read prepare; extend import to validate marked branch trees and store pending posted rows. Block marked discovery unless the matching approved row exists.
3. Add PF53 boundary/lifecycle tests, docs, run targeted existing CLI tests and platform verification, inspect the diff, commit locally only.

Throughput checkpoint: blocking first steps are the pure matcher/renderer; dependent endpoints and refresh must share one writer. Independent workstreams are n/a (one coupled lifecycle). Shared mutable state is the existing pending row plus independent atomic prepare counter. Smallest safe decomposition is one owner, no parallel branch writers.

## Scope

Shared path/issue helpers, prepare/import/listing/refresh admission, pending detail guard, llms docs and PF53 tests. Do not change solver take, payment or merge logic. No migration expected; source=posted plus approval=pending and null importer already fit the schema. No push, deployment or live GitHub writes.

The pure extraction also requires moving the two existing never-ship guard-audit break targets in `kitchen/reviews/guard-breaks.json` to the new source file; their find/replace mutations and tests remain identical.

## Done when

- Prepare validates exact fields, 64 KiB body, at most 2000 paths, reward/text/path constraints and atomic independent 10/minute cap; forbidden paths mint nothing and GitHub receives zero calls.
- Prepared issues parse with the CLI format reader, reuse its renderer, and carry an extra HTML comment outside the version-2 block.
- Import refuses missing/mismatched tips, malformed/truncated trees, forbidden paths, symlinks/submodules and invalid .boxignore. Imports remain pending, hidden, null-attributed, OWNER/COLLABORATOR-only, and expire at 14 days.
- Search and hint cannot bypass admission; unmarked CLI behavior is unchanged. Approved branch metadata stays pinned to admitted commit/reward.
- `tests/platform/pf53.test.ts`, unchanged never-ship/CLI publication tests, `env HOME=$HOME/kitchen-home node scripts/verify.mjs test:platform`, and `node scripts/test-edit-gate.mjs --base origin/master --wave PF53` are green on the committed candidate.
