## Why

The tool already does more than the review assumed. `quoteForeign` (`notice.ts`) escapes C0/C1 controls, bidi overrides, zero-width characters and the BOM; every diff line prints as `solver change | "..."`; comments print as `other account |`; paths are quoted; `--no-ext-diff --no-textconv` keeps solver-selected programs out of the diff.

What is missing is the **frame**, not the character escaping:

- `look` prints the solver's lines in the same stream as the tool's own prose, immediately before `next: box bounty apply ...`. Nothing says the block above is data.
- There is no single renderer: a future print site can forget to quote.
- `--json` does not mark which fields are a stranger's.
- The session that reads is the session that holds merge authority.
- K44's owner-side and solver-side agents both named untrusted pull requests and prompt injection as a first fear (`GTM.md` §7).

No text sanitisation can make natural language safe. This wave reduces reachability and makes provenance unmissable; it does not make a reading agent immune, and must not say it does.

## Outcome

Every solver-derived string leaves the tool through one renderer, inside one labelled block. No print path can put it in instruction position. `look --export` gives a quarantined reading path. The stated limit is honest.

## The engineering answer

| # | Measure | This wave |
|---|---|---|
| 1 | **One renderer, one block.** `solverBlock(label)` / `solverLine(text)` replace scattered `quoteForeign` call sites. A fixed header says the text below is the solver's, data only, nothing was run; a fixed footer closes it; the footer token inside content is escaped so it cannot be forged. | build |
| 2 | **`--json` provenance.** Additive: every solver-derived field carries `source: "solver"`, and a top-level list names them. Shape documented. | build |
| 3 | **Quarantined reading.** `look --export <path>` writes the diff plus a manifest (id, n, commit, sha256) under `.box/local/solutions/`, and prints only path, hash, counts and the header — no diff line. The default `look` keeps printing the block. Closing line: read in a session with no write access; choose and apply from your own. Advice, never a claim of enforcement. | build |
| 4 | **Deletion is a tombstone, not a missing ref.** Because any machine holding a chain pushes it back, `forget` writes a signed tombstone in the chain and a client refuses to push a chain older than it; local purge is separate; the stated scope is best effort. | later, not briefed |
| 5 | **Settings are tamper-evident.** Sign the owner settings, log every change, show it in `config`. Offline it cannot be tamper-proof, and the docs stop implying it is. | later, not briefed |

- Findings and limits:
  - **Departure, `--export` takes no path.** It is a switch. The tool picks `.box/local/solutions/<id>-<n>.diff` and `.json`, because the brief says the export goes under `.box/local/solutions/`. A path chosen by the caller could leave the never-ship directory, and would need the ownership-marker and component-walk handling a foreign directory demands. Each component is walked: a link or non-directory at `.box`, `.box/local` or `.box/local/solutions`, or a non-file where the export goes, is refused as `local-store-path-blocked` with a `next:`. Files are staged and renamed into place. `--export --json` is refused as `json-not-supported`.
  - **Departure, `source: "solver"` sits in a list.** It lives in the closing top-level `foreignFields: [{field, source}]` list, not inline on objects. Inline keys would break bt19's exact-shape assertions on `files` and `fromOthers`, and editing those would mean changing expected outcomes. Comment fields carry `source: "other account"`.
  - **Writes outside the brief's write list, flagged for the head chef:**
    - `packages/box-bounty/args.ts`: the `--export` option entry and the usage line. The one parser refuses unknown options, so measure 3 cannot ship without it.
    - `packages/box-bounty/owner-text.ts`: one `solverAccount` wrap on the merge-wait line. The output is the same for any GitHub login.
  - **Inline paths stay inline.** Paths a solver chose that the tool names inside its own fact sentences (apply's conflict and clean lists, report flags, merged notices) stay inline, quoted by `showPath`, and are not block-framed. A quoted path in a comma list is not in instruction position, and framing every one would multiply lines.
  - **What the frame does not stop.** The escaping covers exact and near copies of the tokens (case and spacing folded). A homoglyph copy, such as a fullwidth bracket, is not escaped. It still sits inside a quoted line behind `solver change | "`, so it cannot stand alone as the footer. No escaping makes natural language safe; BOUNTY.md and CONTRACTS.md R7 say so.
