# K60: a setup step may take longer on the hosted Windows runner, and a dead package mirror cannot cancel the Linux job

Milestone: K (kitchen) · Station: evidence · Base: `master at dispatch` · Branch: `wave/K60` · Timebox: 120 minutes (a hosted run takes about 26 minutes); at expiry, report partial findings and stop
Owner decisions: D-2026-11-10-k49-answers (the hosted run is the acceptance); the owner's order of 11 November 2026 ("proceed with the recommended chronological sequence of the upcoming waves and do not stop")
Horizon: short. Hillclimb playbook: a before and an after from named runs.

**Brief.** Written by the CTO on 11 November 2026 from two hosted failures found while accepting BT56. Facts, read from the logs:

- **Hooks have their own limit, and K59 did not touch it.** Run 43024146368 (master, the K59 merge commit `7fcbc8b`): `verify (windows-2025)` failed with `Error: Hook timed out in 10000ms` in `bt8c.test.ts` and twice in `pf26.test.ts`. K59 raised `testTimeout` to 60 s on Windows; vitest's `hookTimeout` (a `beforeAll` or `beforeEach` that builds a fixture) is a separate setting and is still its default, 10 s.
- **A dead apt mirror cancels the whole Linux job.** Run 43035172554 (BT56's Result commit), attempts 1, 2 and 3: `verify (ubuntu-24.04)` was cancelled in "Install Chromium for browser-backed tests" every time, 10 minutes into `playwright install --with-deps chromium`, which was fetching nine font packages from `azure.archive.ubuntu.com` (each `Ign:` after about 38 s). The verify step never ran. The same job had passed on the earlier commit of the same branch. Nothing of ours failed; the acceptance rule counts a missing check as no pass, so a mirror outage blocks every merge.
- Also seen, not fixed here: on run 43027294715 attempt 1, Windows failed once with `EPERM ... syscall: 'rm'` removing a temp folder in `github.test.ts` after the test's own assertions (the folder was still held open by another process). Named in BACKLOG.

## Outcome

On Windows a hook may take 30 s (the other systems keep Vitest's 10 s), pinned by a test beside K59's. The Linux Chromium install is split: the browser itself is fetched first and must succeed; the system fonts and libraries are a second step that is bounded (5 minutes, one retry) and may fail without ending the job, because the browser-backed test (`k16-record.test.ts`) still runs and fails by itself if a library is missing.

- Read for context: [K59](K59.md), the two logs above, `tests/kitchen/k16-record.test.ts` (what needs the browser)
- Do not touch: any test's expected outcome or its own timeout; `scripts/verify.mjs`; which tests run; the `testTimeout` rule

- The Result states that one run cannot prove a hook flake is gone, and quotes the slowest hook time on Windows if the log shows one.

Keep the existing comment, updated.

## Traps

- The libraries step must not hide a missing browser: the browser step stays fatal and separate.
- Do not raise the hook limit on Linux or macOS, and do not add a hook timeout to a test.
- `continue-on-error` on a step shows that step as passed even when it failed: say in the Result what the log showed for it.
