# K62: rule 2 as a check, the test-edit gate (H8 of K51d)

Milestone: K (kitchen) · Station: evidence · Branch: `wave/K62` · Timebox: 180 minutes
Owner decisions: on 12 November 2026 the owner left the order and handling of the K51d hypotheses to the CTO; H8 is first by the order in [K51d](../kitchen/reviews/K51d-how-we-test.md).

**Why.** AGENTS.md rule 2 ("never edit a test's expected outcome to make a candidate pass") is a sentence asked of the same agent that writes the code. The practitioner sources in K51d section 2b agree that the judge must be out of the writer's reach and the enforcement deterministic (agents delete, skip and weaken tests; hooks and checks are deterministic, instructions are advisory). In this kitchen the CTO writes both, so the achievable part is: make every edit to an existing test visible and require it to be said, with a reason, in the wave file the owner reads.

## What it does

`scripts/test-edit-gate.mjs`, run by `verify` before any step (a refusal, exit 2, not a pass). On a `wave/<ID>` branch it compares the test files with the merge-base with master and flags:

- a test file deleted, a test removed (a rename counts as a removal and an addition);
- a test newly skipped (`.skip`, `.skipIf`, `.todo`, `.fails`), including a new test that is skipped on a system;
- an assertion dropped or changed (`expect(...)`, `expect*(...)` helpers, `refused(...)`, `assert*(...)`) — formatting alone is not an edit, added assertions and added tests never are;
- a raised time limit (a test's or a describe's own `timeout`);
- a changed or deleted snapshot, a change to `scripts/test-timeout.mjs` or `scripts/vitest.config.mjs`;
- `.only` anywhere: never allowed, not listable.

Each flag must be listed under `## Changed expectations` in `waves/<ID>.md`, one line `- <file>::<test title> — <reason>` (paths for the file-level kinds), with at least a few words of reason. The failure text prints the exact lines to add. Off a wave branch it says it did not apply; with no master to compare with it refuses by name.

## Limit, stated

Whoever can edit this script, the wave file and `verify` can get around it. It does not make rule 2 unbreakable; it makes a break show up in the Result the owner reads, and makes the check not depend on remembering the rule. The owner's own protections (branch rules, a reviewer) are what would make it binding, and are the owner's.
