# BT61: a program gets every answer as data, refusals included

Milestone: PF (the platform) · Station: packaging · Base: `master at dispatch` · Branch: `wave/BT61` · Timebox: 240 minutes; at expiry, report partial findings and stop
Owner decisions: D-2026-11-10-found-at-the-moment, D-2026-10-14-tool-convention
Horizon: long: start with `/plan` and keep the plan in this file

**Brief.** Written by the CTO on 10 November 2026 from [K55](K55.md). Seen on the packed build that day:

- `box bounty look 3 --json`, refused: nothing on standard output, a sentence on standard error, exit 3. A program has to parse the sentence to learn which refusal it was and what to do.
- `box bounty create --json`: refused, "`--json` is not available on box bounty create yet". The id of a new bounty, the number of a posted issue and the result of an `apply` can only be read out of prose.
- `--json` exists on `status`, `look`, `config` and `discover` only (BT19, owner, 15 October 2026).

Tools built for agents that are in wide use give machine output on every command and make an error the same kind of document as a success (Arcjet's CLI, June 2026; Beads' `--json` throughout). Long-running agents script their tools; this is for them.

## Outcome

Every bounty command takes `--json` and prints exactly one JSON document on standard output and nothing else there. A refusal or a usage error under `--json` is also one document, with the refusal's existing name, its sentence, and its next step as separate fields. Exit codes do not change. Without `--json`, not one character of any command's output changes.

## Scope

- Write: `packages/box-bounty/json.ts`, `args.ts` (the option table), `packages/box-cli/src/bounty.ts` (where a refusal is printed), each command's result type where it lacks a field the text already states, `docs/box-v4/BOUNTY.md` and `CONTRACTS.md` (the documents and their schema names), `FIRST-FIVE-MINUTES.md` (one line), a new `tests/box/bounty/bt61.test.ts`
- Read for context: [BT19](BT19.md) (the existing documents, `fromOthers` and the rule that others' text sits only in fields marked as theirs), [BT43](BT43.md) (the reading boundary), [BT40](BT40.md) (every refusal names its next step: 246 sites), [BT26](BT26.md) (the test that fails when text states a fact the JSON lacks), `tests/box/bounty/json-agreement.test.ts`
- Do not touch: any refusal's name, condition, exit code or side effect; any text output; the existing four documents' fields (additions only)

## Done when

- Accepted as the rulebook then says ([K50](K50.md) if merged), with `test:box-bounty` and `test:kitchen`.
- **First step, cited in the Result:** read the current guidance tools for agents follow (Arcjet's write-up, the `--json` conventions of `gh`), and run an agent-CLI linter over the packed tool if one can be run without sending anything outside; list what it reports and which findings are taken.
- **One refusal shape for every command,** named and versioned like the existing documents (`box-bounty/refusal@1`): the command, the refusal's name, the message, the next step, the exit code. Under `--json` it goes to standard output, so one read gets the answer either way; standard error stays empty. A test drives one refusal per command, and one usage error, and parses each.
- **The split of a refusal into message and next step is mechanical,** from the "; next: " every refusal already carries (BT40), not hand-written per site. A test enumerates every refusal site by the same walk BT40 used and fails if one has no next step to split.
- **Every command has a document:** `create`, `post` (and `--preview`), `apply`, `close`, `take`, `submit`, `find`, `describe`, `allow`, `deny`, `hook`, `setup`. Each carries at least the facts its text states: the agreement test (BT26) is extended to every command and must fail when text names a fact the document lacks. Shown failing once.
- **A stranger's text keeps its boundary:** in every new document, text written by someone else appears only under the fields marked as theirs; the reading-boundary tests run over the new documents with the hostile strings they already use.
- `create --json` no longer answers `json-not-supported`; that refusal name is retired and the removed-name guard knows it.
- **Text output is byte-identical:** a test runs each command without `--json` before and after on the same fixture and compares bytes.
- `help` and each command's `--help` name `--json` once; the tool's budget for words per command (BT17) still holds.

## Lenses

- [x] **Security:** a refusal's message can hold a path or a name a stranger chose. Under `--json` it must be a JSON string and nothing more: try a name with a quote, a newline, a control character and a closing brace, and show the document still parses and the field holds the same characters.
- [x] **User experience:** a fresh session asked to post a bounty and report its issue number from a script uses `--json` and reads the number from a field, not from a sentence.

## Notes

- Follows `gh` and the tools read in K55: one document on standard output, exit code as the verdict, no decoration.
- Not in this wave: printing JSON by default when standard output is not a terminal. Agents read our plain text well and it was designed for them (BT17); a silent change of format would break every skill written against it. `--json` stays something a caller asks for.
- After the first release (it adds, it removes nothing), so it does not hold the publish.
