## Why

The rules "no command fails silently" (AGENTS.md) and **PL3** ("Every outcome is a named state with a next step"; `docs/box-v4/CONTRACTS.md`, platform section) say refusal messages carry `next:`. They mostly do not. A CTO scan of master `9cffd4e` with the TypeScript parser found:

| | Sites |
|---|---|
| `new BountyRefused(reason, message)` and `invalid(reason, message)` calls in `packages/box-bounty/*.ts` and `packages/box-cli/src/*.ts` | 246 (one is `invalid`'s own definition in `gh.ts:89`) |
| message already contains `next:` | 4 |
| message names a command but not as `next:` (for example `— box bounty find "<words>"`, `End it with box bounty close <id>`) | 60 |
| message names no step at all (for example `already-ended`, all 23 `github-response-invalid`, `github-cli-missing`, `missing-why`) | 182 |

An agent that hits a refusal has to guess what to do. One fixed word, `next:`, lets it find the step every time, as it already does in `status`.

## Outcome

Every refusal the tool can print carries a true `next:` step, and a test fails if a new one does not.

## Scope

- **Write:** the message arguments of refusal sites in `packages/box-bounty/*.ts` and `packages/box-cli/src/*.ts`; the refusal line in `packages/box-cli/src/node-check.ts` (`node-too-old`, which is not a `BountyRefused` but is a refusal); the new `tests/box/bounty/bt40.test.ts`; the one regular expression named under "Changed expectations".
- **Do not touch:** any reason name, exit code, condition, control flow or side effect; any other product file; `docs/` (the CTO updates CONTRACTS.md at close); `BountyUsage` usage messages (they already print the command's usage form).

## The rule, in order

Apply these in this order at every site.

1. **The step follows the word `next:`.** For a one-line message, append `; next: <step>` at the end. For a message built as lines (`[...].join('\n')`), add a final line `next: <step>`.
2. **Keep the existing wording.** Do not rephrase the fact part of a message. The one exception: when the message already names its step in another form, turn that clause into the `next:` clause instead of repeating it. For example, `find needs words to look for — box bounty find "<words>"` becomes `find needs words to look for; next: box bounty find "<words>"`. Never keep both.
3. **The step is something the reader can do now.** Use a real command with the arguments the site knows (`${record.id}`, `${n}`, the flag that was wrong), or the exact thing to change and where. Prefer what the site has in scope over a placeholder. When the step needs the owner, say so: `next: the owner runs box bounty allow <owner/name>`.
4. **The step must be true at that site.** Read the code above the throw. Do not write "nothing changed" or "rerun" unless the code shows it holds. If the site already wrote something (for example `persistRecord` before the throw), the step must fit that state. A step that reads as a verdict ("this solution is bad") is not allowed; it states what to run or change.
5. **A hard stop's step is never a way around it.** For never-ship paths, private repositories and the secret scan, the step is what the reader can do inside the rule: drop the path, end the bounty, or ask the owner. It never suggests changing a hard stop, which cannot be changed.
6. **Commands must exist.** Every `box bounty <word>` you write uses one of: `allow`, `apply`, `close`, `config`, `create`, `deny`, `describe`, `find`, `help`, `hook`, `look`, `post`, `status` (the dispatcher's branches in `packages/box-cli/src/bounty.ts`; `owner` is a removed name, not a command). `box bounty <command> --help` prints that command's usage, so it is a valid step for an argument mistake.
7. **Held states too.** `publish-held`, `merge-held`, `owner-allow-needed` and `owner-answer-needed` exit 0 by design and carry an owner block. Leave the owner block exactly as it is and add one final `next:` line for the agent, for example `next: pass the owner block on in its words; box bounty status ${record.id} shows when the answer lands`. Check that this matches what `status` really shows for that bounty.
