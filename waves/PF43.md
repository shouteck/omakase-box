## Shortest credible launch path

1. Get permission to cross-list an existing public GitHub issue with a stated reward; do not spend on seed rewards or campaigns. At the check the [public feed](https://open-bounty-board.box-platform.workers.dev/bounties.json) had zero listings. Use PF44: the importer stages the issue, the owner approves with the exact comment on GitHub, and only then should it be public on the board and feed.
2. Keep the existing [PF6](PF6.md#outcome) pilot gate: verify approval and visibility, submission, merge detection, payment-state tracking and the never-ship stop. Use sandbox evidence for mechanics that would otherwise require a real payment. The owner pays the winner directly if owed; Omakase does not guarantee payouts, and a real payment is not a launch prerequisite.
3. Keep the existing safety and launch-prep order in [STATUS.md](../STATUS.md#next). Send installers to How it works, solvers to the board, and invited maintainers to the original issue. [K41](K41.md) can use the existing install line; neither it nor PF6 needs a homepage change.
