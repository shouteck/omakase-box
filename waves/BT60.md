# BT60: every bounty pays: none is posted or listed at $0

Milestone: PF (the platform) · Station: packaging · Base: `master at dispatch` · Branch: `wave/BT60` · Timebox: 300 minutes; at expiry, report partial findings and stop
Owner decisions: D-2026-11-10-no-zero-bounties, D-2026-11-10-k48-answers, D-2026-11-02-install-is-the-human-step
Horizon: long: start with `/plan` and keep the plan in this file

**Brief.** Written by the CTO on 10 November 2026 from the owner's decision in talk: "we shouldn't allow anyone to create a bounty that is $0. There should be a fixed amount that we allow. And right now, we just keep it as greater than $0. But for now, as we are testing the product, we just allow $0. But as we go into live, we don't allow any $0 to be posted."

Why it matters: a $0 bounty is what an earning agent's first `discover` returns today, and our own advice tells it to decline. A board of unpaid work teaches every visitor to leave. This changes two standing lines, "$0 unless they said otherwise" (PLAN, money per repository) and "beyond the three hard stops the tool enforces nothing" (AGENTS.md).

## Outcome

1. **One minimum reward,** a single constant in whole US dollars, set to 1, read by the tool and the board. Raising it later is one line.
2. **The tool does not post below it.** `post` on a repository whose reward is under the minimum is a named refusal that changes nothing and names the one step that fixes it. A draft can still be made.
3. **The board does not list below it,** on any surface: the board, a bounty's page, the feed, MCP, RSS and the numbers. A bounty some other tool or an old release posted at $0 is simply not there. The listing door already asks for at least $1.
4. **Testing still works.** The kitchen's sandbox bounties must stay at $0, because with one account a stated reward would be a promise nobody means (PF9a's seat 2 stopped on exactly that). The plan chooses the allowance and states it in `help`; see Notes.

## Lenses

- [x] **Security:** the rule must not be passable by accident. Try a settings file edited to a reward of 0, a negative or fractional amount, a reward set then lowered to 0 between draft and post, an issue written by hand in the format at $0, and one whose machine block says 5 while its text says $0. Say what the tool and the board each did. The limit, stated: anyone can write a GitHub issue by hand; the tool refuses to post one and the board refuses to list one, and that is all a tool can do.
- [x] **User experience:** a fresh session told "set this up so my agent can hand off work", with an owner who has not thought about money, reaches a posted bounty with a reward the owner chose, and is never told an amount to pick.

## Notes

- **The testing allowance, CTO's recommendation for the plan:** an environment variable named for testing, read only by `post`, stated in `help` as "for testing the tool; such a bounty is never listed". Anyone could set it, and gains nothing: the board will not show the result. The alternative, a hidden list of test repositories inside the tool, hard-codes our sandbox into everyone's copy.
- The tool still decides nothing about the amount and suggests none (PLAN, "Not in this plan": deciding or suggesting prices).
- **When (owner, 10 November 2026: "Yes, in the release"):** before [BT53](BT53.md), so the first published release with the solver side never posts a $0 bounty in the open format; the allowance keeps the kitchen's tests running.
- Follows the listing door (PF32), which has asked for at least $1 since it was built.
