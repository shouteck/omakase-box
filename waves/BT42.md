## Why

K44's fresh agents saw the instruction block and still never ran `box bounty describe`. Two gave reasons that came from the wording, not from judgement:

- one read the tool as handing work "to outside solvers **for a fee**", from the words "what it costs";
- another called it "an outside service".

Nothing in the block says that posting is free, that a bounty is an issue on this repository's own public GitHub, or that the owner's one-time permission governs it. K44 proposed putting the owner's live settings in the block. The CTO chose **one constant line** instead, because the block sits in files committed to the owner's public repository (AGENTS.md, CLAUDE.md). Live settings would change a tracked file whenever a setting changed, and would publish the settings.

## Outcome

The block an agent sees unasked states, in constant words, that:

- posting is free;
- a bounty goes only to this repository's own public GitHub issues;
- the owner's one-time permission applies, and `box bounty config` shows it.

It no longer contains wording that reads as a fee.

## The change

1. **`packages/box-bounty/wording.ts`, `RULES_LINES` only.** Rewrite the four fixed lines so that they:
   - keep: what the tool does (hand a task to an outside solver and bring solutions back as facts), that `box bounty describe` says when it beats doing the work yourself, and that using it is always the agent's call;
   - drop: "what it costs", and any other phrase that reads as a price;
   - add the facts above in plain words. A starting point, which the cook may tighten:

     ```
     box bounty can hand a task you cannot or should not do to an outside solver
     and bring solutions back as facts. Posting is free: a bounty is an issue on
     this repository's own public GitHub, and the owner's one-time permission
     applies (`box bounty config` shows it). `box bounty describe` says when it
     beats doing the work yourself. Using it is always your call.
     ```
   - stay **constant**: no setting, amount, name, date or count in the lines. The existing state line ("a bounty is open …" / "… has a new solution …") is unchanged.
2. **Keep within BT17's budget** for `describe --rules`: 10 lines and 600 characters (`tests/box/bounty/bt17.test.ts:39`). If the new text cannot fit, shorten it; never raise the budget.
3. **The install line stays out** (BT12's hold until the owner publishes; that returns in PF6).
4. **Truth check.** Every claim in the new lines must already be true in the code:
   - posting has no fee: the tool charges nothing, and a reward is the owner's statement;
   - posting is only to this repository's own public GitHub (the hard stop; private repositories are refused);
   - posting needs the owner's permission (`allow`), and `box bounty config` shows it.

   Cite the code that makes each one true in the Result.
