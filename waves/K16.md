# K16: a demo video the kitchen makes by itself

Milestone: K (kitchen) · Station: evidence · Base: master at dispatch · Branch: `wave/K16` · Timebox: 120 minutes; at expiry the cook stops and reports where it is, whatever state that is

**Pre-brief.** Written by the CTO on 14 October 2026 for the kitchen as the owner runs it: a terminal agent on this Windows host, which has no screen to capture and cannot drive a desktop. The owner wants a video of the flow that people can watch, without a cloud session, without a tool that controls their desktop, and without recording it by hand. A kitchen wave: it cooks only when named.

## Why this shape

A terminal agent cannot film a screen, but it does not need one. Playwright is already a development dependency here and records video from a browser that has no window. A browser page can show the replay's real output as it is produced, and the same browser can go to each real GitHub page the run creates. One command, one video, nothing installed on the owner's machine beyond what the project already uses, and no credential beyond the GitHub sign-in this machine already has.

## Outcome

`node kitchen/demo/record.mjs` runs the BT11b journey for real in the sandbox and leaves one video file a person can play, in which they see each command and its real output, each real GitHub page at the moment it matters, and one plain line before every step saying who is acting. Anyone can check the video against a transcript and the live pages it names.

**Before anything is built, a start check, reported first**

- The cook confirms, by running them, that this machine can do the real run with nobody asked: `gh` is signed in; the sandbox repository is allowed for bounties; a Playwright browser is installed or can be installed by the project's own installer; `node kitchen/demo/bt11b-replay.mjs --real --auto` completes. If one is missing the cook stops there and reports which. It does not ask the owner to act as part of the wave, and it does not install anything machine-wide.

**The recording**

- One command, `node kitchen/demo/record.mjs`, with the replay's own modes passed through: `--real` (the default here) and `--standin`.
- It starts the replay in its unattended mode and a browser with no window, recording video. The browser shows a plain terminal-like page that receives the replay's output as it is produced, line by line, exactly as printed, with the replay's "who is acting" line set apart so a viewer can follow.
- **Each real page is shown when it matters, in the state it was in then.** When the replay prints a `PAGE <url>` line, the browser goes to that address at that moment, stays long enough to read, scrolls to the part that matters where the page is long (the `pay-to:` line in a pull request, the closing comment on the issue), and returns to the output. Pages are not collected afterwards and shown in their final state.
- **It opens no payment link**, and the recorder refuses to navigate to any address that is not a `PAGE` line from the replay on the sandbox repository.
- The first seconds are a title card in plain words: what this is, the date, the tool's commit, that it is a real run in a test repository with the owner's own agents as solvers, that no real money is paid, and that what looks like a terminal is the replay's real output shown in a browser and not a filmed terminal window. The last seconds list what the run left on GitHub by exact name.
- One video file, at a size and pace a person can read (the Result gives resolution, length and file size). The format Playwright produces is enough; converting to another format is done only if a converter is already present, and nothing is installed for it.
- With `--standin` the same command makes a terminal-only video with no network and no credential, and says so on its title card.

**So that a reviewer who cannot watch a video can still check it**

- Beside the video the command writes: a still image at every step and at every page shown; the full transcript of that run; and an index giving, for each step, its time in the video, its line of "who is acting", the still's file name and any address shown.
- The Result quotes the index. The pass reads the stills and the transcript and says, step by step, whether the video shows what the transcript says happened.

**Where the output lives**

- In an ignored folder under `kitchen/demo/`, named for the run. Nothing binary is committed. The Result gives the exact path, and the transcript and index of the run the pass checked are committed as text.
- Whether the video is published anywhere (the README, a release, the sandbox) is the owner's decision and not part of this wave.

**It keeps working**

- A test runs the recorder with `--standin` at short pauses and checks that a video file, the stills, the transcript and the index are produced, that the index covers every step the replay printed, and that no address outside the allowed kind was visited. It reaches no network.
- Each real run posts a fresh test bounty in the sandbox and cleans up what it opened, as the replay already does. The Result lists what is left on GitHub by exact name.
- `kitchen/demo/RECORDING.md` gains a first paragraph saying this command is the usual way, and the cloud session is only for someone who wants a filmed desktop.

**Cases that must fail, each a named refusal that changes nothing:** `gh` not signed in or the sandbox not allowed, before anything is posted; a `PAGE` line naming another repository or the payment link; an output folder that already exists and is not this command's.

## Review lenses

- [x] **Security:** the pass checks every still and the transcript for anything that should not be public (a token, a path under the owner's home folder that says more than it should, the owner's settings), tries to make the recorder visit an address of its choosing through a hostile `PAGE` line and through text a solver wrote, and confirms the run touched only the sandbox.
- [x] **User experience:** a fresh agent that has never seen the tool is given only the stills in order and the index, and says what the product does, who did what, and what the owner is told at the end. Three runs, sentences word for word. Anything it gets wrong is a finding about the demo, not about the agent. The owner is not asked to watch anything as part of the wave.
- [x] **Measurement fairness:** the video shows one real run, unedited: no step is cut, re-ordered or re-run, pauses are the only thing added, and the title card says what is and is not real. The Result says so and names anything that departs from it.
