# PF48: use the branded MCP endpoint

Milestone: platform · Station: packaging · Base: `master` · Branch: `wave/PF48`

## Outcome

Use `https://omakasebox.dev/mcp` for new connections in the installed Skill,
the site's copyable URLs and onboarding. Keep the Worker URL working for
existing connections; do not change the MCP transport or the CLI's board API
default. No deployment, release or external listing submission.

## Done when

- The built CLI installs and refreshes its managed Skill with the branded URL.
- Both website discovery pages and onboarding show the branded URL.
- Both hosts answer MCP requests directly; document how existing clients switch.

## Changed expectations

- tests/box/bounty/pf6.test.ts::the skill is a trusted front door to local execution and read-only discovery — Pin the new canonical MCP URL in the installed copy; it remains read-only and requires no sign-in.
- tests/platform/pages.test.ts::PF6: answering explains discovery, safe work, both submission paths and owner payment — Pin the branded URL in the existing copyable discovery instructions without changing any other solver steps.

## Result

- Followed the minimal-change principle: no Worker routing, CLI API configuration,
  or Skill ownership logic changes. The old URL is a compatibility address, not
  a second default.
- Live check, 19 November 2026 UTC: both hosts accepted initialize,
  notifications/initialized, tools/list and a read-only get_numbers call
  without redirects. Server identity, tool schemas and public results matched.
  No production state was changed.
- The two discovery anchors leave room for sticky navigation so the endpoint
  is visible after following the links.
- Verified on Devin Linux: the scoped bounty tests exercised fresh Skill
  installation and replacement of the previous URL. The browser tests and
  manual Chrome run confirmed both discovery links, both clipboard values and
  unchanged feed copy. The pre-change Skill/onboarding expectations failed
  against the old copy.
- The unmerged PF6 listing drafts in [PR #36](https://github.com/shouteck/omakase-box/pull/36)
  are outside this branch. Integrate the canonical URL into that PR's registry
  draft, listing copy and generated Skill before publishing those drafts.
