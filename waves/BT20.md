# BT20: drafting needs no GitHub

Milestone: BT · Station: packaging · Base: master at dispatch, after BT19 · Branch: `wave/BT20` · Timebox: 90 minutes; at expiry the cook stops and reports where it is

**Brief.** Written by the CTO on 15 October 2026 from K21's first proposed wave (`kitchen/reviews/K21-architecture.md`, findings S6 and S10); the owner agreed the queue that day. Detailed for a cook without deep reasoning. Line numbers are as of master `adb4d20`; search by name.

## Why

`create` makes a private draft, yet it calls the GitHub layer:

- `createBounty` in `packages/box-bounty/create.ts` calls `previewGitHub(...)` to describe what posting would publish. That costs a `gh auth status`, a `repos/<repo>` API call and a `git fetch` on every draft (K14 measured `create` at 28 Git and 3 gh starts).
- What it shows can be wrong by the time the agent posts: K21 created a draft ("nothing new is published"), committed a change, and `post --preview` then showed one commit going public. The real preview, `post --preview`, is computed at the moment that matters.
- The normal output (BT17) shows the plan only under `--full`, or a "Publication plan unavailable" line when GitHub cannot be reached.
- `create.ts` also imports `looksBinary` and `scanText` from `github.ts`, though those are plain text functions, so drafting depends on the whole GitHub module.

## Outcome

`create` starts no `gh` process and makes no network call; it never states what posting would publish. The secret-scan text functions live in their own module, and `create` no longer imports `github.ts`.

## Scope

- Write: `packages/box-bounty/create.ts`, a new `packages/box-bounty/scan.ts`, `packages/box-bounty/github.ts` (the moved functions leave), `packages/box-bounty/index.ts`, `packages/box-cli/src/cli.ts` (the `create` output), `tests/box/bounty/**`, `docs/box-v4/BOUNTY.md`.
- Do not touch: the scan rules or their patterns; what `post --preview` shows; `create`'s never-ship handling; the create-time scan's behaviour (it still scans the selected working files and records findings).

## The changes

1. **Remove the preview from `create`.** `createBounty` returns the finalised result with no `publicationPreview`. In `cli.ts`, the `create` branch drops the lines that print it (the `--full` block's plan and the "Publication plan unavailable" line). The `next:` line already says `box bounty post <id> (--preview shows what becomes public)`; keep it.
2. **Move the scan text functions to `scan.ts`:** `SecretRule`, `SECRET_RULES`, `randomEnough`, `ScanHit`, `scanLine`, `scanText`, `scanPatch`, `binaryPatchPaths`, `binaryBytes`/`looksBinary`. Pure move: no change to any function body. `github.ts` and `create.ts` import them from `./scan.js`; `index.ts` re-exports them from there so the public names are unchanged.
3. **Check:** after the move, `grep -n "from './github.js'" packages/box-bounty/create.ts` prints nothing. If `create.ts` still needs something from `github.ts`, stop and report what and why rather than moving more.
