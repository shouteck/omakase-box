# K50: every wave is verified on three systems before it merges

Milestone: K (kitchen) · Station: evidence · Base: `master at dispatch` · Branch: `wave/K50` · Timebox: 180 minutes; at expiry, report partial findings and stop
Owner decisions: D-2026-11-10-k49-answers, D-2026-10-11-public-origin
Horizon: long: start with `/plan` and keep the plan in this file. Hillclimb playbook: a before and an after.

**Brief.** Written by the CTO on 10 November 2026 from [K49](K49.md). Three facts:

- The full verify takes about 5 minutes on GitHub's Linux machine and 20 to 31 minutes on this host, where it also times out under load (PF33: three runs; BT44: four).
- The hosted run fires only after a merge to master, on Linux only. Linux-only faults reach master unseen (BT51-ci), and macOS has never run the suite or the install.
- `pnpm audit --prod` shows 2 high advisories through `zod`, which `packages/box-cli/package.json` lists and nothing imports.

The repository is public, so hosted minutes are free on all three systems.

## Outcome

Pushing a `wave/*` branch runs the full verify and the platform suite on Linux, Windows and macOS, and the packed package's install test on all three. **The hosted run on the wave's commit is the acceptance run** (owner, 10 November 2026: the local run "is actually taking out a lot of our development time"); local runs are for the files just touched. The production dependency audit is clean and stays checked.

- Read for context: `scripts/verify.mjs`, `scripts/suite.mjs`, [K8](K8.md), [K10](K10.md), [BT12](BT12.md), [BT51-ci](BT51-ci.md), BACKLOG "Linux-only test faults", "bt43.test.ts:966", "Cloud-host browser route"
- Do not touch: what verify checks; any test's expected outcome; the release workflow

## Done when

- A push to a `wave/*` branch starts the run; a push that touches only inert files (the existing `paths` list) starts none. Shown on `wave/K50` itself.
- Three systems, each reported apart. A test that cannot run on a system is skipped by name beside its assertion with the reason, and the run prints the count skipped per system; a silent skip is a failure of this wave.
- **The check still bites:** on a scratch branch, break one guarantee (for example the never-ship rule) and show all three systems go red; then a fault only Linux shows (a hook written without `chmodSync`) and show Linux red while Windows is green. Delete the scratch branches.
- macOS: the install test (`bt12-install`) passes there, or the Result names exactly what fails. This is the first macOS evidence the project has; report it as found, not as expected.
- `node scripts/pnpm.mjs audit --prod` exits clean after `zod` leaves `packages/box-cli/package.json`, and a step fails the run on a new high or critical production advisory. First show the step red with `zod` still listed.
- Before and after, from named runs: minutes to a verdict for one wave, local against hosted; the number of local full runs K50 itself needed.
- **The rule, rewritten in KITCHEN.md's Verification section and `kitchen/roles/cto.md`:** acceptance is the hosted run, green on all three systems, on the wave's exact commit SHA, read with `gh run list --branch wave/<id>` and quoted in the wave file with its run id. A local `node scripts/verify.mjs` stays the tool for file-scoped checks and is no longer required in full before a merge. A red, cancelled or missing hosted run is not a pass; if GitHub's machines are unavailable, a full local run is the fallback and the wave file says so. AGENTS.md rule 1 already says "a green `node scripts/verify.mjs` run on the commit SHA" and stands as written. AGENTS.md and KITCHEN.md together stay under 20 KB.
- The hosted run keeps `.kitchen/runs/` as an artifact long enough for the wave to close, and `kitchen-stats` either counts hosted runs or says plainly that it counts local ones only.
- This wave itself is the last one accepted the old way: `node scripts/verify.mjs --full test:box-bounty test:kitchen` exits 0 locally on the final commit, and the new hosted run is green on the same SHA.

## How to read a hosted run (goes into `kitchen/roles/cto.md`)

```
gh run list --branch wave/<id> --limit 5
gh run view <run id> --json conclusion,headSha,jobs
gh run view <run id> --log-failed
```

Acceptance: `conclusion` is `success`, `headSha` equals the wave's final commit, and all matrix jobs are `success`. Quote the run id and the three job conclusions in the wave file.
