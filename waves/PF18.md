## Build, in this order

1. **Test mode, for real, as robustly as it can be.** On a deployed throwaway board with Stripe's test keys, real webhooks and a real browser, each run recorded in a table: flow, what happened, whose word.
   - **The owner's steps, as written:** run the `DEPLOY.md` steps and the restricted key's permission list against test mode. A missing permission fails here, not live.
   - **Solver:** connect through Stripe's page; `account.updated` sets ready; a solver who stops halfway; **disconnect** (`account.application.deauthorized`), which PF11 did not prove.
   - **Owner's card:** saving it on Stripe's Checkout page in a real browser, and finishing authentication there, which PF11 did not prove; the limit; the switch.
   - **One click:** click, pay on Stripe's page, back; closing the page before paying; the page expiring; two clicks at once.
   - **On merge:** a merge pays once; one over the limit; more than one solution landed; the solver is the poster or has access; a solver not ready; a duplicate merge notice; a lost row.
   - **Stripe's test cards:** declined, insufficient funds, expired, authentication required, and a late failure.
   - **After the money:** refund, and **a dispute's real webhook,** which PF11 did not prove. A forged or replayed event is refused.
   - **What breaks:** a wrong key, a revoked key, and Stripe unreachable each end in a named state with no money moved.
   - **Countries:** connect and charge a test account in each country the board offers, not a sample. A country that fails leaves the list.
   - **A guard broken once:** each guard above has a test that fails with it removed, as PF11 did.
   - **The honest table:** what test mode proves, and what only live can (real money movement, payouts reaching a bank, a live account's limits, Stripe's review of the platform, real fraud checks).
2. **Say who Stripe cannot pay, where a reader decides.** Stripe pays solvers in a list of countries (`COUNTRIES` in `PayOnMerge.jsx`, 44 today, K46's refusals and PF13's reach behind it). Move the list to `pay-ways.ts`, one source.
   - **How it works, solver's step 3,** and **the One click and On merge cards or the detail under them:** one plain line: Stripe's ways need a bank account in a supported country, and a solver elsewhere is paid by hand. It must not read as a defect or a promise.
   - **The whole list,** folded, on How it works, generated from the one source; `/me/` keeps its picker from the same source.
   - **The feed and MCP:** the same fact in `how_to_get_paid` and the legend, so a solver's agent learns it before it does the work.
   - **The tool's merge note:** a solver not connected already sees by hand; add nothing that blames a country the tool cannot see.
   - Words are checked against Stripe's own pages on the day, cited. Where a page and a run disagree, the run wins, and the Result says so.
3. **Say what this board has.** "Stripe or PayPal" on the One click card and "connect Stripe or PayPal" on How it works come from `ways_set_up`: Stripe only, PayPal only, both, or the plain words with no key. The tool's merge note already names only what is set up; confirm it. Sweep the site and feed for other places that name PayPal as available. `/me/`'s PayPal section reads "not set up" already; confirm how it looks.
4. **The owner's list, in `DEPLOY.md`.**
   - The restricted key: **every permission the board's calls need, listed from the code,** not from memory: read each `stripe(...)` call. A restricted key that lacks one fails only when that call runs, so step 1 proves the list.
   - The webhook address and its events, already there; check them against `applyEvent`.
5. **The owner's steps.** These are the owner's alone; the CTO never sees or types a key.

## Traps

- **A way that says it is set up must work.** The order is: key first, then read `/api/ways`, then read the page. If a key is wrong, remove it, and the board returns to "not set up" by itself.
- **The key can charge any saved card to any connected account;** the limit and payee are enforced by the board's code, as `DEPLOY.md` says. No log, page or error may carry it (`redact` in `stripe.ts`).
- **Test mode hid this once:** the K46 and PF13 notes: a stand-in that accepts what the real service refuses. Live differences are listed in the Result as unproven: real charges, payouts to a solver, a live webhook's delivery, and a live account's limits.
- **No word implies a promise.** The money-claim check covers every changed page.
- Keep PayPal's code and words ready: a PayPal key alone must still give "PayPal" and both give "Stripe or PayPal".
