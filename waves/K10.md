# K10: the off-machine run tests the product we are building

Milestone: K (kitchen) · Station: packaging (the suites) and evidence (what the run may claim) · Base: master at the commit that adds this file · Branch: `wave/K10` · Timebox: 45 minutes; at expiry, report partial findings and stop

## Outcome

Every code push to master is checked off this machine on the suites that cover the bounty tool, and the run stops depending on things about to change under it.

**Why now.** The CTO looked at the off-machine runs on 10 October 2026 at the owner's request. The run is green on the latest code (`1d1c32b`). But it does not run a single suite of the product in milestone BT: `test:box-trace` and `test:box-bounty` are not in its list, and `test:box-package` was excluded in K8 for one case-sensitivity test. It spends its three minutes on the earlier platform (portal, end-to-end browser, acceptance, runner, compiler, analysis). And two notices on every run say the ground will move: the runner label `ubuntu-latest` moves to a new Ubuntu from 19 October 2026, and the three GitHub actions used are on a deprecated Node version.

## Scope

- Write: `.github/workflows/verify.yml`; `scripts/suite.mjs` and test files under `tests/box/**` only as far as needed to make a product suite run on Linux (see below); `docs/box-v4/KITCHEN.md` only if the sentence about off-machine runs becomes wrong.
- Read for context: `waves/K8.md` (why each suite is in or out), `waves/C1.md` and `waves/BT1.md` Results (what the new suites need: Python, Git), `kitchen/stations/packaging.md`.
- Do not touch: product code under `packages/**`; any test's expected outcome; the list of suites the host's own `verify --full` runs.

## Done when

- **The product's suites run off-machine and pass:** `test:box-trace` and `test:box-bounty` are in the workflow's list. If either needs something the runner lacks (the `python` command name, Git identity, a temp-folder assumption), provide it in the workflow, not by weakening a test. Say what was needed.
- **`test:box-package` runs off-machine, or the reason it cannot is narrower than a whole suite.** K8 excluded the suite for one test that only holds on a case-insensitive filesystem. Mark that one test as host-only by the platform it needs, with the reason beside it, so the other 58 run on Linux. Do not change what it asserts. If that turns out to be more than a small change, leave the suite excluded, say why, and stop.
- **The runner is pinned** to a named Ubuntu version instead of `ubuntu-latest`, so the migration cannot change the result between two pushes. State the version and why.
- **The actions are on versions that do not raise the Node deprecation notice,** each pinned to a released major version. If a current version does not exist for one, leave it and say so.
- **Nothing is silently narrowed.** The earlier-platform suites stay in the list in this wave. The workflow's comment block still names every suite that is excluded and why.
- **Proved on a real run, twice:** one run on the wave branch that is green with the new suites visibly executed (their names and counts in the summary line), and one deliberate break of a `test:box-bounty` assertion on a scratch branch that turns the run red, then is deleted. Record both run links in the Result. Delete the scratch branch on the remote afterwards (it is this wave's own).
- `node scripts/verify.mjs test:kitchen` exits 0 on the final commit on the host.
- The run stays inside the job's ten-minute limit; report the new duration against the old (about four minutes).

## Notes for the worker

- Bug-fix playbook, with the investigation steps first: reproduce each new suite on Linux before changing anything. The workflow can be exercised on the wave branch by temporarily adding that branch to its trigger; remove that before the final commit.
- Pushing the wave branch and a scratch branch to the private `origin` is within the kitchen's authority. Nothing goes to any other remote.
- Do not wait on a run longer than its own limit; if a run hangs, cancel it and say so.
- Whether to stop running the earlier-platform suites off-machine is a separate decision for the owner (it would make the run faster and remove a browser install that may break on a new Ubuntu). Do not make it here; report how many minutes those suites take so the decision can be made.
