## Outcome

**Why now.** The CTO looked at the off-machine runs on 10 October 2026 at the owner's request. The run is green on the latest code (`1d1c32b`). ## Done when

- **The product's suites run off-machine and pass:** `test:box-trace` and `test:box-bounty` are in the workflow's list. If either needs something the runner lacks (the `python` command name, Git identity, a temp-folder assumption), provide it in the workflow, not by weakening a test. Say what was needed.
- **`test:box-package` runs off-machine, or the reason it cannot is narrower than a whole suite.** K8 excluded the suite for one test that only holds on a case-insensitive filesystem. Mark that one test as host-only by the platform it needs, with the reason beside it, so the other 58 run on Linux. Do not change what it asserts. If that turns out to be more than a small change, leave the suite excluded, say why, and stop.
- **The runner is pinned** to a named Ubuntu version instead of `ubuntu-latest`, so the migration cannot change the result between two pushes. State the version and why.
- **The actions are on versions that do not raise the Node deprecation notice,** each pinned to a released major version. If a current version does not exist for one, leave it and say so.
- **Nothing is silently narrowed.** The earlier-platform suites stay in the list in this wave. The workflow's comment block still names every suite that is excluded and why.
- **Proved on a real run, twice:** one run on the wave branch that is green with the new suites visibly executed (their names and counts in the summary line), and one deliberate break of a `test:box-bounty` assertion on a scratch branch that turns the run red, then is deleted. Record both run links in the Result. Delete the scratch branch on the remote afterwards (it is this wave's own).
- `node scripts/verify.mjs test:kitchen` exits 0 on the final commit on the host.
- The run stays inside the job's ten-minute limit; report the new duration against the old (about four minutes).
