**Brief.** Written by the CTO on 10 November 2026 from [K49](K49.md)'s question 3 and the owner's answer: do it if it is an order of magnitude smaller than the project. Measured that day: **it is.** Every call the tool makes to GitHub's API goes through one function, `gh()` in `packages/box-bounty/gh.ts` (352 lines), as `gh api`, plus `gh auth status` and `gh version`. No other file starts `gh`. Pushes and fetches use plain Git over HTTPS with Git's own sign-in (`remoteGit`). The project is about 15,800 lines of source and 19,500 of tests; this is one transport of a few hundred lines and its tests.

**Why:** long-running agents in cloud sandboxes are usually given a GitHub token and no `gh` program. Today the tool refuses them (`github-cli-missing`). This replaces the 12 October decision that `gh` is required.

## Outcome

With `gh` installed and signed in, nothing changes. Without it, a token in the environment (`GH_TOKEN`, then `GITHUB_TOKEN`, the names `gh` itself reads) is enough for every command on both sides. The mechanism: a second transport behind `gh()` that makes the same request over HTTPS to `api.github.com` and hands back the same status, headers and body, so every caller is untouched. The limit: GitHub.com only, as today.

**How it works today** (`packages/box-bounty/gh.ts`): `gh(root, args)` at line 105 finds the `gh` program, checks its version once, and runs it through `launch` (line 239). `api()` (line 253) builds `['api', '--hostname', 'github.com', <endpoint>, '--include']`, plus `--method` and `--input <file>` for a payload, and gives the output to `splitResponse` (line 153), which expects a status line, headers, a blank line, then the body. `publicRepository` (line 289) also runs `gh auth status`. `remoteGit` (line 314) runs plain Git against `https://github.com/<repository>.git`.

3. **Choose the transport once per process,** a new function `transport(root)` in `gh.ts`, cached:
   1. `gh` resolves and `gh auth status --hostname github.com` succeeds → `'gh'` (today's path, untouched);
   2. else `process.env.GH_TOKEN`, then `process.env.GITHUB_TOKEN`, non-empty after trimming and holding no whitespace → `'token'`;
   3. else refuse `github-not-signed-in` with one message that names both ways: `sign in with gh auth login, or set GH_TOKEN to a GitHub token; next: do one, then rerun the same command`.
   A token present with `gh` present but signed out gives `'token'`. `gh` missing and no token keeps today's `github-cli-missing` wording, with the token route added to its `next:`.
4. **The direct transport,** a new file `packages/box-bounty/gh-direct.ts`, called from inside `gh()` when the transport is `'token'`. Copy the shape of `board.ts` lines 80 to 83: a child `node -e <script>` given its request on standard input, so the call stays synchronous like every caller expects.
   - The parent translates the `gh api` arguments it already has: endpoint → `https://api.github.com/<endpoint>` (`graphql` → `https://api.github.com/graphql`); `--method` → the method (default `GET`, or `POST` when there is `--input`); `--input <file>` → the file's bytes as the body.
   - Standard input to the child: `{ url, method, body, token, timeout }`. **The child's `env` is `{}` (plus `SYSTEMROOT` on Windows, as `board.ts` does).** The token travels only on standard input.
   - The child: `fetch(url, { method, body, redirect: 'manual', headers: { authorization: 'Bearer ' + token, accept: 'application/vnd.github+json', 'x-github-api-version': '2022-11-28', 'user-agent': 'omakase-box', 'content-type': 'application/json' } })`. A 3xx answer is returned as it is and never followed. It prints `HTTP/1.1 <status>\r\n<each header>\r\n\r\n<body>`: exactly what `gh api --include` prints, so `splitResponse` and `classifyGitHubFailure` are untouched.
   - Before spawning, the parent checks the URL's host is exactly `api.github.com`; anything else is a refusal `github-host-refused`. Ignore `GH_HOST`, `GH_ENTERPRISE_TOKEN` and proxy variables: the child has no environment to read them from.
   - The parent maps the child's result to what `launch` returns: `status` 0 when the HTTP status is under 400, else 1, with the same `stdout`; a spawn error or timeout as `error`. Then the existing failure path classifies it.
   - `gh version` and `gh auth status` are not called on this transport. `signedAccount` (`api(root, 'user')`) is the sign-in check.
5. **Git with the token,** `remoteGit` in `gh.ts` and any other Git call that reaches `github.com` (search `https://github.com/` and `remoteUrl` in `packages/box-bounty`; `chain.ts` line 400 fetches by URL too). When the transport is `'token'`, pass the environment of step 1 to that one Git call through `gitOutcome`'s `env` parameter. When the transport is `'gh'`, pass nothing new.
6. **Never where it can be read.** `redact` (`gh.ts` line 88) already masks `ghp_…` and `github_pat_…` shapes; do not rely on it. The token must not be put into any string at all: not an error message, not `--json`, not a record, not the settings. The test in row 6 searches for it.
7. **Words.** Search `never sees, stores or asks for a credential` over the repository; rewrite each to: with `gh`, the tool never sees the sign-in; with a token, it reads it from the environment, sends it only to GitHub, and never stores or prints it. Update the requirement lines in `wording.ts`, `render.ts` and `FIRST-FIVE-MINUTES.md`: `gh` signed in, **or** a token in `GH_TOKEN`.
8. **The sandbox run** as Done when says. Start that one process with the token taken from `gh auth token` straight into its environment (for example `GH_TOKEN="$(gh auth token)" PATH=<a path without gh> <tool> …` in one shell line); never echo it, never write it to a file.
