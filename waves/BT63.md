# BT63: the command is `omakase-box`

Milestone: PF (the platform) · Station: packaging · Base: `master at dispatch` · Branch: `wave/BT63` · Timebox: 300 minutes; at expiry, report partial findings and stop
Owner decisions: D-2026-11-10-one-name, D-2026-11-10-command-name, D-2026-10-14-tool-convention
Horizon: long: start with `/plan` and keep the plan in this file

**Brief.** Written by the CTO on 10 November 2026 from the owner's decisions that day: the product has one name, omakase-box, and the command follows it. Read on npm the same day: Box, the storage company, publishes its official command-line tool as `@box/cli` with the command `box`, described as shipping official agent skills; a second package named `box` installs the same command. On a machine with either, `box bounty` runs Box's tool or ours, whichever was installed last, and an agent's model has read far more about theirs. "bounty" is also a leftover: since the older platform was retired, the tool does nothing else.

**Why now:** only 0.1.3 is public. After the next release every skill, instruction file and script written against `box bounty` sits on machines we cannot update.

## Outcome

An agent types `omakase-box post`, `omakase-box status`, `omakase-box discover`, `omakase-box setup`: the command is the product's name and the word "bounty" is gone from it. Everything the tool prints, the skill, the instruction block, the guide and the site say the new command. For one release `box bounty <command>` still works and says once per machine that the name changed (owner, 10 November 2026), unless the install check below shows the old name cannot ship safely.

## Scope

- Write: `packages/box-cli/` (the entry, the manifest's `bin` in `pack.mjs`), `packages/box-bounty/` (every printed command, usage line, next step, the skill text, the instruction block, `setup.ts`), `packages/box-platform/app/` and `src/` where the site or feed prints a command, `FIRST-FIVE-MINUTES.md`, `README.md`, `AGENTS.md`'s own "Handing work off" block, `docs/box-v4/BOUNTY.md`, `CONTRACTS.md`, `tests/` (expected command text only)
- Read for context: [BT7c](BT7c.md) and the removed-name guard (how a retired command name is refused by name), [BT17](BT17.md) (each command's word budget), [BT42](BT42.md) (the instruction block is constant: its one rewrite is here), [PF16](PF16.md) (`box setup`, the skill), [PF6](PF6.md), [BT62](BT62.md)
- Do not touch, and say so in the guide: **names other programs or stored data depend on.** The issue label `box-bounty`, the issue title's `[box bounty <id>]` prefix, the machine block and its format name, the JSON documents' schema names (`box-bounty/status@1`), the Git names for the branch and the shared record, the project's `.box/` folder, the settings folder, and the `BOX_BOUNTY_*` environment variables. Renaming any of these strands bounties already posted or records already written.

## Done when

- Accepted as the rulebook then says ([K50](K50.md) if merged), with `test:box-bounty`, `test:platform` and `test:kitchen`.
- **First, the install fact, on a scratch machine profile:** with `@box/cli` installed globally, install our packed tarball with the old `box` command still in its manifest, and again without it. Record exactly what npm does in each case (an error, an overwrite, a warning) on Windows and Linux. If keeping `box` makes the install fail or silently takes over Box's command, the old name is not shipped: stop and bring that to the owner with the evidence, since it changes "kept for one release".
- **The sweep is by search with a count, not a sample.** On 10 November `box bounty` appears 371 times in the tool's source, 214 in its tests and 13 on the site. The plan lists the patterns (`box bounty`, `box setup`, a bare `box ` at the start of a command, `box.cmd`), the count before, and the expected remainder with each hit named: the title prefix, the label, the old-name notice, history in wave files. A hit outside the list fails the wave.
- A test runs every command and fails if any line the tool prints names the old command, outside the one notice. Seen failing first.
- The old form, while kept: `box bounty <anything>` does exactly what `omakase-box <anything>` does, same output apart from one line the first time on a machine saying the command is now `omakase-box`; under `--json` the notice is not in the document. `box` with no `bounty` says the same line and exits as before.
- `npx -y omakase-box setup` still works from an empty machine; the skill and the instruction block it writes say the new command; a machine that has the old skill gets it replaced, and `setup --remove` removes either.
- The PowerShell note in the guide names the right `.cmd`.
- The tool's own word budgets (BT17) hold with the longer name; any that does not is listed, not loosened without saying.
- One real run on the sandbox (`kitchen/sandbox.md`) with the new command only: post, take, submit, apply, close. The sandbox's own instruction block is rewritten by the tool, and the Result says so.
- The posted issue's "how to answer" steps name the new command; the title prefix and label are unchanged, and a bounty posted by 0.1.3 is still read, listed and closed. Tested with a stored 0.1.3 issue body.

## Lenses

- [x] **Security:** a second command name is a second way in. Check both names reach the same code with the same checks, that the old name cannot be used to skip the notice-free `--json` rule or any refusal, and that `setup` never overwrites a file under the old skill's folder that is not ours.
- [x] **User experience:** a fresh session with only the new skill installed posts a bounty on the sandbox without ever typing `box`; one given an old instruction block that says `box bounty` still succeeds and learns the new name from the notice.
