# BT54: the secret scan reads a patch exactly

Milestone: PF (the platform) · Station: packaging · Base: `master at dispatch` · Branch: `wave/BT54` · Timebox: 90 minutes; at expiry, report partial findings and stop
Owner decisions: none
Horizon: short

**Brief.** Written by the CTO on 10 November 2026 from [K48](K48.md), which reproduced the first fault; the second is from BT43's pass 6 (BACKLOG). Both are in `scanPatch` and `binaryPatchPaths` in `packages/box-bounty/scan.ts`. Bug-fix playbook: reproduce first.

## Outcome

Every added line of a patch about to be published is scanned and filed under the file it is in. The mechanism: file headers are read only where Git writes them, between `diff --git` and the first `@@` of that file, and a hunk's lines are counted from its `@@` header, so no line inside a hunk can be taken for a header. The limit: the scan still reads only what the stated rules match (binary files, base64, split tokens stay as BACKLOG says).

## The two faults

1. **A content line starting `++ ` is skipped.** In a patch it reads `+++ …`, which `scanPatch` takes as a file header: the line is not scanned, and every later hit in that file is filed under the wrong name. Seen on 10 November 2026: a key on a `++ ` line gives no hit; a key on the next line is reported in a file named `x`. A wrong name also means the owner's safe-to-publish list cannot match it and the hold names a file that does not exist.
2. **A quoted file name keeps its octal escapes.** Git quotes a name with unusual bytes as `"caf\303\251.txt"`; the scan strips the quotes and keeps the escapes. The owner is told of a file that does not exist; safe-to-publish cannot match it; such a binary goes missing from "not scanned".

## Steps, in order

Written so any model can cook it. Lines are as read on 10 November 2026; find the quoted text if they drifted.

1. **Tests first.** Create `tests/box/bounty/bt54.test.ts` with the table below. For the secret, copy a key-shaped string that an existing scan test already uses (`tests/box/bounty/bt8c.test.ts`); do not invent one, or a rule may not match it and the test proves nothing. Each test's first line asserts that the same key on a plain added line is a hit, so a failure can only mean the fault. Run them and see rows 1, 2, 5 and 6 fail.
2. **Rewrite `scanPatch`** (`packages/box-bounty/scan.ts`, line 90) as a small state machine. Keep its signature and what a hit looks like. Variables: `path`, `lineNo`, `oldLeft`, `newLeft`, `inHeader`.

   | Line | When | Do |
   |---|---|---|
   | starts `diff --git ` | always | `inHeader = true`; `path = '(unknown)'`; `oldLeft = newLeft = 0` |
   | starts `+++ ` | only while `inHeader` | if the rest is not `/dev/null`: `path = fileName(rest)` |
   | starts `--- ` | only while `inHeader` | if `path` is still `(unknown)` and the rest is not `/dev/null`: `path = fileName(rest)` (a deleted file has `+++ /dev/null`) |
   | matches `^@@ -\d+(?:,(\d+))? \+(\d+)(?:,(\d+))? @@` | while `inHeader`, or while `oldLeft === 0 && newLeft === 0` | `oldLeft` = first count or 1; `newLeft` = second count or 1; `lineNo` = new start − 1; `inHeader = false` |
   | first character `+` | `newLeft > 0` | `newLeft -= 1; lineNo += 1;` scan the rest of the line |
   | first character `-` | `oldLeft > 0` | `oldLeft -= 1` |
   | first character a space, or the line is empty | `oldLeft > 0 && newLeft > 0` | both `-= 1`; `lineNo += 1` |
   | starts `\` | any | ignore (`\ No newline at end of file`) |
   | anything else | any | ignore |

   The point: inside a hunk the counts say what a line is, so `+++ x` with `newLeft > 0` is an added line whose text is `++ x`, and is scanned.
3. **`fileName(text)`,** a new private function beside it: trim; if it starts and ends with `"`, undo Git's quoting (below); then strip one leading `a/` or `b/`. Undo quoting by walking the characters into a byte array: `\\` → `\`, `\"` → `"`, `\t`, `\n`, `\r`, `\a`, `\b`, `\f`, `\v` → that byte, `\` followed by three octal digits → that byte, any other character → its UTF-8 bytes; then decode the array as UTF-8.
4. **`binaryPatchPaths`** (line 111): read a `Binary files … differ` line only while in a header (track `diff --git` and `@@` the same way), and take the name with `fileName`. Handle both shapes: `Binary files a/x and b/y differ` and `Binary files "a/…" and "b/…" differ`; for a new file the first name is `/dev/null`.
5. **Ask Git not to quote what it need not.** In `packages/box-bounty/publish-plan.ts` at the two `gitOutcome(root, ['diff', '-p', '--no-renames', …])` calls (lines 450 and 456) put `'-c', 'core.quotepath=false'` first, as line 473 already does for `ls-tree`. Then non-ASCII names arrive plain, and only names holding a quote, a backslash, a tab or a newline are still quoted, which step 3 decodes.
6. **The end-to-end test** (row 9), then run the whole `test:box-bounty` suite: every existing scan test passes with no expectation edited.
7. **Attack it** (the Security lens' list), one line each in the Result. **Verify and merge.**

## Traps

- `gitOutcome` inserts `--no-ext-diff --no-textconv` after the word `diff` (`git.ts` line 213, `operationIndex`). After adding `-c core.quotepath=false` in front, confirm with one debug run that those two flags are still inserted; if `operationIndex` does not skip `-c <value>`, fix it there with a test, not by dropping the flags.
- A hunk header may omit a count (`@@ -3 +3 @@`): that means 1, not 0.
- A mode-only change and an empty new file have a header and no hunk: no hits, no crash.
- The diff is made with `--no-renames`, so there are no `rename from` lines to parse. Do not add rename handling.
- Do not touch `SECRET_RULES`, `scanText` or `scanFields`.
