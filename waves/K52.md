# K52: the public repository holds the product, and its history stays in Git

Milestone: K (kitchen) · Station: evidence · Base: `master at dispatch` · Branch: `wave/K52` · Timebox: 120 minutes; at expiry, report partial findings and stop
Owner decisions: D-2026-11-10-clear-the-repository, D-2026-10-11-public-origin
Horizon: short

**Brief.** Written by the CTO on 10 November 2026 from [K49](K49.md)'s question 4 and the owner's answer: "I agree with your recommendations. You can clear it before launch." Measured that day, three folders in the working tree are not the product:

| Folder | Tracked files | Size | What it is |
|---|---|---|---|
| `.execution/` | 2,759 | 18.8 MB | The retired platform's evidence and hand-offs; frozen by rule 8 |
| `docs/legacy/` | 37 | 0.6 MB | The retired platform's documents; frozen by rule 8 |
| `kitchen/platform-prototype/` | 74 | 0.3 MB | K43's clickable prototype; pins a framework version with critical advisories; never deployed |

A visitor, or a solver's agent cloning the repository, meets these before the product. **This wave removes files beyond its own scratch, so it waits for the owner's "go" on its pre-cook card.**

## Outcome

The three folders are gone from master's working tree in one commit. Nothing is lost: every file stays in Git history, the commit before the removal carries a tag that names it, and the README says in two lines where to find it. No history is rewritten and nothing is force-pushed, so a clone still downloads the old objects; what changes is what a reader sees and what an agent's search reads.
