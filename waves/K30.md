# K30: every stage's contract written down, and every guarantee proven or named as unproven

Milestone: K (kitchen) · Station: evidence (also packaging) · Base: master at dispatch, after K29 and BT32 · Branch: `wave/K30` · Timebox: 210 minutes; at expiry the cook stops and reports what it has
Owner decisions: none

**Brief.** Written by the CTO on 18 October 2026 from the roadmap the owner approved that day (PLAN.md, "The roadmap: one loop, six stages, two foundations"). An investigation: **it changes no product code and no test.** It produces the stage contracts, a map from every guarantee to its proof, and the list of guarantees and scale targets that nothing proves yet; the head chef briefs the hardening waves from that list. Detailed for a cook without deep reasoning.

## Why

The owner wants the product "properly defined" and its processes able to scale, without "random flake". PLAN.md's engineering table states, per stage, the states it moves, the guarantees it must never break, the code that holds them and a scale target. Stating is not proving: nobody has checked that each guarantee has a test that would fail if it broke, or that each scale target is measured. After K29 the repository holds only the product, so this is the first time the whole of it can be audited as one thing.

## Outcome

`docs/box-v4/CONTRACTS.md`: for each of the six stages (create, post, track, review, decide, pay) and two foundations (memory, the owner) plus the platform, a precise contract; and `kitchen/reviews/K30-contracts.md`: each guarantee mapped to the test or tests that prove it, each scale target mapped to a measurement, and the list of what nothing proves, ranked.

## Scope

- Write: `docs/box-v4/CONTRACTS.md` (new), `kitchen/reviews/K30-contracts.md` (new), `waves/K30.md` (the Result). Scratch outside the checkout.
- Read: PLAN.md (the roadmap and "Other rules of the product", the three hard stops); `docs/box-v4/BOUNTY.md`; `packages/box-bounty/**`, `packages/box-cli/**`; every test under `tests/box/bounty/` and `tests/kitchen/`; `kitchen/memory/` scripts.
- Do not touch: product code or tests.

## Method: four steps

**Step 1: the contracts (60 minutes).** For each stage and foundation, one section in `CONTRACTS.md` with exactly these headings, each filled from the code (cite file and function), never from memory:
- **Job:** one sentence, for which actor.
- **Commands and options** that belong to it.
- **Inputs and outputs:** what it reads and writes (record fields, Git objects and refs, GitHub calls, files, output lines).
- **States:** the record stages it moves from and to (from `record.ts`).
- **Guarantees:** numbered, one line each, each a property a test could check (for example "C3: no never-ship file enters the draft's captured files"). Start from PLAN.md's table and the hard stops; add every guarantee the code enforces with a named refusal.
- **Refusals:** every refusal reason name the stage can give (`grep -n "BountyRefused('" packages/box-bounty`), and what each protects.
- **Scale target:** from PLAN.md's table, made measurable (operation, size, limit).
Every refusal name in the package must appear in exactly one contract; list any that fit none.

**Step 2: the proof map (80 minutes).** For every numbered guarantee: the test file(s) and test name(s) that would fail if it broke, and **how you know** (the assertion that checks it, quoted). If a guarantee is only checked as a side effect, say so. For the most important guarantees (the three hard stops, "nothing a solver wrote is run", "only what is named becomes public", "the owner's yes before post and merge", "drafts never shared"), **prove the test bites**: break the product in a scratch copy outside the checkout (one line), run that test, show it fails, restore. For every scale target: the measurement that checks it (`k14-start-budget`, `bt17-measure`, `kitchen/memory/measure.mjs`, `storage/benchmark.mjs`) and its last recorded number, or "not measured".

**Step 3: the gaps, ranked (40 minutes).** One table: guarantee or target; stage; what proves it today (nothing, side effect only, stand-in only, Windows only); risk if it broke (a hard stop, an untrue statement to the agent or owner, or neither). Rank: hard stops first, then untrue statements, then the rest. Also list: tests that prove nothing in any contract (candidates to delete); refusal names that belong to no stage; code that serves no stage (the lean rule).

**Step 4: the hardening proposal (30 minutes).** Group the gaps into at most one wave per stage that needs one, each one paragraph: which guarantees it proves, which tests it adds, which tests it deletes, its dependencies. The head chef writes the briefs.
