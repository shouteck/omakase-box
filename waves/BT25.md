# BT25: the record module keeps the record, and the rest moves out

Milestone: BT · Station: packaging · Base: master at dispatch, after BT24 · Branch: `wave/BT25` · Timebox: 150 minutes; at expiry the cook stops and reports where it is

**Brief.** Written by the CTO on 15 October 2026 from K21's fourth proposed wave (`kitchen/reviews/K21-architecture.md`, S8, A2, A4); the owner agreed the queue that day. Detailed for a cook without deep reasoning: the target layout is below, function by function. **A pure move: no behaviour changes, no test expectations change.**

## Why

`packages/box-bounty/record.ts` (about 1,300 lines at K21) mixes six jobs: storing records, rendering every status and help text, the owner gate, money, the commands `postBounty` and `closeBounty`, and compatibility. It imports twelve modules of its own package and sits in five import cycles (K21 step 1's graph). Every later change has to read all of it. BT23 and BT24 have already shrunk it, so there is less to move now.

## Outcome

`record.ts` holds only the record: its types, loading and validating, writing, listing, stage changes and refs. Rendering, the owner gate, money and the two commands live in their own modules. No import cycle runs through `record.ts`. Every public name stays importable from `index.ts` as before.

## Scope

- Write: `packages/box-bounty/**`, `packages/box-cli/src/cli.ts` (imports only), test files' import lines only.
- Do not touch: any function body beyond what a move requires (an import path, a name qualified by a module); any test expectation; any output.

## The target layout

Check every name against master at dispatch; a name that has moved or been removed by BT23 or BT24 is skipped and listed in the Result.

Rules for the move:

1. Move one module at a time, then build and run the bounty suite (`node scripts/suite.mjs box --suite bounty`) before the next.
2. A private helper used by functions in two new modules goes to whichever module the lower-level one is in (`record.ts` beats the others), never duplicated.
3. `index.ts` re-exports every moved public name under the same name, so `cli.ts` and the tests could keep importing from `index.ts`; update direct imports of `./record.js` in other modules to the new module.
4. **One-caller wrappers (K21 A4):** after the move, `postBounty` is a two-line forwarder to `postGitHub`; keep the name (commands call it) but note it in the Result; `approveGitHub` in `github.ts` with its one caller `previewGitHub` may be folded into it only if BT20 left `previewGitHub` with one caller. Nothing else is folded in this wave.
5. **Cycles:** write a small script outside the checkout (scratch) that reads the `import … from './x.js'` lines of every file in `packages/box-bounty/` and prints each cycle. Run it before and after; paste both outputs in the Result. After: no cycle includes `record.ts`. If a cycle remains between two of the new modules, report it with the import that causes it rather than bending the layout.
