# BT65: `omakase-box setup` acts only on exactly what it was asked, and `--help` writes nothing

Milestone: PF (the platform) · Station: packaging · Base: `master at dispatch` · Branch: `wave/BT65` · Timebox: 90 minutes (a hosted run takes about 26 minutes); at expiry, report partial findings and stop
Owner decisions: D-2026-11-02-one-command-setup (setup is the one command a person runs); the owner's words on 12 November 2026: "agree, please proceed and fix it", after agreeing that the marker rule for a skill file stays as designed, that nothing stricter is built for edits to our own file, and that the help text says so
Horizon: short

**Brief.** Written by the CTO on 12 November 2026 from a defect found in BT53's "pack and try" step. Facts, read from the code and from a run:

- `setup` is dispatched before the normal option parser, by one hand-written line in each entry file (`packages/box-cli/src/box.ts`, the published one, and `packages/box-cli/src/cli.ts`, the kitchen build): `rest[0] === '--remove' ? runSetupRemove() : runSetup()`. Anything else after `setup` runs the real setup: `--help`, `-h`, a typo of the undo flag (`--remov`), a stray word.
- Found by running `<command> --help` for each of the 16 commands the README names against the packed 0.2.0: 15 printed usage; `setup` answered "already on this machine" and rewrote our skill file in the real home folder (identical text). Earlier versions with `setup` (since PF16, 0.1.1) have the same check.
- BT12 recorded the rule this breaks: every subcommand answers `--help` with usage and exits 0, and an unknown option is refused with exit 2 naming the nearest real one.
- The owner's design (PF16) stands: `setup` writes only its own folder `omakase-box` under each found agent's skills folder, leaves a folder whose `SKILL.md` lacks our marker alone, says what it wrote, and `--remove` takes only a file carrying our marker away. Re-running refreshes our skill. The reference tools (Context7, Vercel's skills CLI, Firecrawl) manage the folder they created the same way; none documents protecting edits to it.

## Outcome

`omakase-box setup` acts on exactly nothing after it (the setup, as today) or exactly `--remove` (as today). `--help` and `-h` print what the command does and write nothing. Any other word is refused with exit 2, naming the nearest real option, writing nothing. The help text says that re-running refreshes our skill, that edits to it are replaced, and that a person's own skill belongs in its own folder. Every command's `--help` is pinned by a test as safe to run.
