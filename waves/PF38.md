# PF38: the board's pages carry the standard security headers

Milestone: PF (the platform) · Station: packaging · Base: `master at dispatch` · Branch: `wave/PF38` · Timebox: 120 minutes; at expiry, report partial findings and stop
Owner decisions: D-2026-11-02-site-looks-need-approval
Horizon: short

**Brief.** Written by the CTO on 10 November 2026 from [K49](K49.md). Read on the live board that day: the front page answers with `Cache-Control` and no security header at all. The JSON answers carry `x-content-type-options: nosniff`; the pages do not. The signed-in pages hold buttons that pay, record a payment and remove a card.

What already protects them: the session cookie is `Secure; HttpOnly; SameSite=Lax`, and every write checks the request's origin (`account.ts:60`). So this is hardening, with no known hole behind it.

## Outcome

Every page the board serves carries: a content security policy that names where scripts, styles, images, frames and form posts may come from; a rule that no other site may frame it; `nosniff`; a referrer policy; and transport security. The mechanism is the response headers themselves, set in one place. The limit, stated in the Result: a policy that must allow the framework's inline scripts is weaker than one with nonces, and the Result says which this is.

## Scope

- Write: one place that sets the headers (the assets' headers file if Cloudflare's static assets honour one, else the Worker), `packages/box-platform/src/api.ts` for the answers the Worker makes itself, `tests/platform/pages.test.ts`, `packages/box-platform/headers.mjs`, `packages/box-platform/local.mjs` only so it serves the same headers file
- Read for context: `wrangler.toml` (`run_worker_first`: which paths the Worker answers and which the assets do), `app/layout.jsx`, the pages' inline scripts (the signed-in page serves two inline scripts and seven files), `src/stripe.ts` and `src/paypal.ts` (where a browser is sent), [PF10](PF10.md), [PF31](PF31.md)
- Do not touch: how any page looks or reads; the cookie; the origin check

## Steps, in order

Written so any model can cook it. Facts as read on 10 November 2026: `packages/box-platform/wrangler.toml` serves the built pages from `out/` as static assets; the Worker runs first only for the paths in `run_worker_first` (`/api/*`, `/b/*`, the JSON and RSS addresses, `/mcp`, and a few more). So `/`, `/board/`, `/how/` and the rest are answered by Cloudflare's asset server without the Worker; the Worker's own JSON answers set their headers in `src/api.ts` line 23.

1. **Read and cite** (Done when, second bullet), and answer two questions in this file before writing code:
   - does Cloudflare's static assets for Workers honour a `_headers` file in the assets directory? (Its documentation says so; confirm on the day and on the local board.)
   - what does the framework's static export put inline? Open `out/index.html` and `out/me/index.html` and count `<script>` tags without `src` and any `style=` attributes. This decides how strict the policy can be.
2. **The test first** (row 1 below), against the local board, seen failing.
3. **The set of headers,** the same on every answer:

   | Header | Value |
   |---|---|
   | `Content-Security-Policy` | see step 4 |
   | `X-Content-Type-Options` | `nosniff` |
   | `Referrer-Policy` | `strict-origin-when-cross-origin` |
   | `X-Frame-Options` | `DENY` (and `frame-ancestors 'none'` in the policy) |
   | `Strict-Transport-Security` | `max-age=31536000` only if the live answer does not already carry one (read it with `curl -sI <board address>`) |
   | `Permissions-Policy` | `camera=(), microphone=(), geolocation=()` |

4. **The policy, built from what the pages really load.** Start from:

   ```
   default-src 'self'; script-src 'self' <inline allowance>; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self'; connect-src 'self'; frame-ancestors 'none'; base-uri 'self'; form-action 'self' <providers>; object-src 'none'
   ```

   - **Inline scripts:** a static export has no server to make a nonce per request. For each inline script found in step 1, compute its SHA-256 at build time and list the hashes in `script-src`; write a small build step (`packages/box-platform/headers.mjs`, run after the export) that scans every `out/**/*.html`, collects the hashes, and writes the `_headers` file. If the inline scripts differ on every build, the hashes are recomputed on every build: that is the point of the step. Only if hashing proves unworkable, fall back to `'unsafe-inline'` for scripts and **say plainly in the Result that the policy is then weak against injected script**.
   - **`<providers>`:** read `src/stripe.ts` and `src/paypal.ts`. If a page posts a form or redirects a browser to Stripe or PayPal, a redirect needs no allowance, a form post needs the provider's origin in `form-action`. List what you found.
   - `data:` in `img-src` is for the select arrow in `globals.css`.
5. **Where the headers are set.** Two places, one source:
   - `headers.mjs` writes `out/_headers` with one block for `/*`;
   - the Worker's own answers: in `src/api.ts`, the `json` helper (line 23) and wherever it returns `env.ASSETS.fetch(...)` for `/b/…` and profile pages (lines 157 to 160), wrap the response to add the same set. Keep the values in one small module both import, so they cannot drift (a test compares them).
6. **Report-only first, locally.** Serve the policy as `Content-Security-Policy-Report-Only` on the local board and walk every flow in Done when's fourth bullet with the browser console open. Each violation: fix the policy or the page, and list it. When the walk is clean, switch to the enforcing header. **Never deploy report-only.**
7. **The framing check:** a scratch HTML file on another local port with an `<iframe>` of the board: it shows nothing. Remove the file.
8. **The attacks** in the Security lens, each one line: what was tried, what the browser did.
9. **Looks:** take a screenshot of `/`, `/board/`, `/me/` before and after at 1440 and 390 (`docs/box-v4/design/shoot.mjs` shows how to capture). If they differ by a pixel, stop for the owner. **Verify, merge;** after the owner's deploy, run the header test against the live address once.

## Traps

- The local board (`local.mjs`) may serve `out/` differently from Cloudflare and ignore `_headers`. If so, make the local server read the same `_headers` file, so tests see what production sends, and say so.
- The pages fetch only their own origin (`/api/…`, `/numbers.json`), so `connect-src 'self'` should hold; if a page calls a provider's script (Stripe.js), it needs that origin in `script-src` and `frame-src`: find out in step 6, do not guess.
- Fonts are self-hosted (`@fontsource`), so no font host is needed.
- Do not touch the session cookie or the origin check.
- No expected outcome changes.

- **The design, and why it differs from the brief's step 5.** Two facts decided it: `_headers` never applies to a Worker's answer, and one line cannot hold about 45 script hashes. Also, a hash list written at build time would block every inline script of a build that forgot the step. So:
  - **Every address but `/_next/*` runs the Worker first** (`run_worker_first = ["/*", "!/_next/*"]`). `handle()` wraps every answer in `secured()` (`src/security-headers.ts`). A page's policy allows exactly its own inline scripts, by SHA-256 computed from the page as it is served. Every other answer gets the closed policy `default-src 'none'; frame-ancestors 'none'`. All get `nosniff`, `strict-origin-when-cross-origin`, `X-Frame-Options: DENY`, `camera=(), microphone=(), geolocation=()` and `max-age=31536000`.
  - **`/_next/*`** (Next's scripts, styles and fonts, served without the Worker) gets the same fixed set from `public/_headers`, which the build copies into `out/`. A test compares the two, so they cannot drift.
  - **Styles stay `'unsafe-inline'`:** the pages' `style=` attributes cannot be allowed by hash. Scripts never are.
  - **Not done:** report-only mode. The enforcing policy was walked locally, where a violation breaks nothing that matters, and the collector below catches any.
