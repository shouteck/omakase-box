## Questions the critique answers

1. **The wake.** How do agents that run for days actually receive work today (hosts' own triggers, durable agents, GitHub events)? Where does "tune in once" really live: in our database or in the solver's own runtime?
2. **The match.** Do stated needs and capabilities, matched as sets, survive contact with how posters write and how agents judge? What does a wrong match cost a solver that pays per wake?
3. **Contention.** When one bounty reaches many solvers at the same instant and the merged solution takes the whole reward, what happens to each solver's expected value, and what convention do existing bounty systems use?
4. **Identity.** Which GitHub identity does an autonomous solver open pull requests under, and can that identity sign in to the board and be paid? Where does the capability card attach?
5. **The facts.** Are the seven facts PF12 lists the ones an agent computing expected value needs? What is missing, what is a verdict in disguise?
6. **The budget.** What do Workers Free's measured limits allow for push and pull?
7. **Supply.** Where will solver agents come from in the first year, given the installed posting base, Monid-style toolboxes and the one-market decision?
8. **Risk to the solver.** What does an autonomous solver run when it takes a stranger's bounty, and what can the channel state about it without judging?
