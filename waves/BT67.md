## Outcome

A head already on the local creating branch or remote default branch at first sight names no payee. Missing evidence names none either; status states what is unknown. This is first-sight containment, not proof of authorship of future owner commits; Git author strings are never evidence.

1. Turn bt56 test 11 into the failing-first rewarded case: assert no payee, no owed message and the attribution fact, not just branch state. Keep genuine solver controls.
2. At first sight of each `(PR number, head SHA)`, record local containment and GitHub remote-default containment (compare or fetched remote ref). ## Plan

Written 19 November 2026 by the CTO (Devin, Linux VM) before code. Bug-fix playbook; principles read: fix-root-causes, sequence-verifiable-units, type-system-discipline.

- **Evidence, one field.** `seenPullRequests` and `availablePullRequests` entries gain `firstSight?: { local: 'contained' | 'new' | 'unknown'; remote: 'contained' | 'new' | 'unknown' }` (`gh.ts`), validated in `record.ts`. `local` is BT56's ancestry check on the creating branch (`unknown` when the record names none); `remote` is GitHub's `compare/<default>...<head>` (`behind`/`identical` = contained, `ahead`/`diverged` = new, any failed read = `unknown`). Recorded once per new `(n, commit)` in `collect.ts` (`firstSightFlag` grows into the evidence); a moved head is a new entry and is asked again; copies in `json.ts`/`render.ts` spread whole entries, so evidence travels unchanged. `onBranch` stays as BT56's merge-candidate flag (local only).
- **One eligibility function** (`pay.ts` or `close.ts`): eligible only when an entry for the decided `(pr, commit)` exists with `firstSight.local === 'new' && firstSight.remote === 'new'`. Anything else (no entry, no evidence = legacy, contained, unknown) names nobody and carries a stated reason.
- **Gate in `close.ts`** before `publication.pay` is written: an ineligible solution records `pay = { pr, solver: null, link: null, testMode: false, editedBy: null, unattributed: <reason> }`; no description read, no board accepts read. Recomputed on every unfinished close, so an old payee from a half-done close is overwritten, never kept. `payNotice`/`payMessageLines` print the attribution fact and no "pay X" line when `unattributed` is set. Merge recognition (closing) is unchanged: this wave gates the payee, not the close.
- **Surface:** `--json` `pay.unattributed` and seen-PR `firstSight`; `node scripts/surface.mjs --write`, diff in Result.
- **Tests first** (bt67.test.ts + bt56 test 11 and test 8 edits listed under Changed expectations): remote-only owner work, local-already-there, moved head, legacy record, GitHub compare fails, half-close retry with an old payee, genuine apply / listed hand merge / fast-forward still credited.
- **Platform:** a refresh-to-payment test in `tests/platform/payments.test.ts` with an outsider PR whose head is owner work already on main; add the minimum board-side check only if it is red.
