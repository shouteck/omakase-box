# K64: the proof map as a check, guarantee ids on tests (H2 of K51d)

Milestone: K (kitchen) · Station: evidence · Branch: `wave/K64` · Timebox: 240 minutes
Owner decisions: on 12 November 2026 the owner left the order and handling of the K51d hypotheses to the CTO; H2 is third in the order (after H8 and H6).

**Why.** K51b had to build an extractor and read about 190 test titles to learn which tests defend a hard stop, because nothing in a test says which guarantee in CONTRACTS it proves. The K30 proof map (a document) went stale. This makes the map mechanical: a comment line above a test, `// @guards P1 R3`, and a script that reads CONTRACTS and the tests.

## What it does

- `scripts/proof-map.mjs [--check] [--json] [--root <dir>]`: reads the guarantee ids and their "hard stop N" labels from `docs/box-v4/CONTRACTS.md`, the `@guards` comments from `tests/**/*.test.ts`, and `kitchen/reviews/proof-gaps.json`. `--check` fails (exit 1) when an annotation names an id CONTRACTS lacks, an annotation sits above no test, a **hard-stop guarantee has no test** (even if listed), a guarantee with no test is not on the untagged list, or a listed one now has a test (the list only shrinks). Exit 2 when CONTRACTS is missing or holds no guarantees.
- The ids are in comments, not titles: a rename would read as a removed test to the K62 gate.
- It runs in every `verify` through `tests/kitchen/k64-proof-map.test.ts` (row 10 runs it on this repository), and the two files it reads are in `KITCHEN_TEST_READS` and the hosted workflow's `paths`.
- CONTRACTS gained two things: **C1** is now labelled hard stop 1 (create side), and a short **"the board" section with BD1**, hard stop 2's board side (a private repository is never listed, rendered, stored or offered), which had no guarantee id although ten tests defend it.

## Changed expectations

None: 113 tests in 33 files gained a comment line; no assertion, title or limit changed (the K62 gate, run on this branch, found nothing).

## Result

Done on 12 November 2026.

- **Tests first:** 11 rows in `tests/kitchen/k64-proof-map.test.ts` (synthetic repositories for each rule, a refusal row, the real repository, the reach lists). All 11 seen failing before the script existed; rows 10 and 11 stayed red until the tagging and the reach lists were done.
- **The map today:** 63 guarantees (62 plus BD1), **13 with a tagged test, 50 not yet tagged**; 141 tags on 113 tests. The 8 hard-stop guarantees: C1 20 tests, P1 3, P2 9, P4 27, R3 5, D4 12, O1 19, BD1 10 (each at least one; P1 and R3 are the thinnest and the places a break audit, H3, should look first).
- **How the tags were chosen:** from K51b's reading (its judged list) and from the tests that name a hard-stop refusal reason, mapped by reason to a guarantee id (`github-private-repository` to P1, `answer-never-ship` to R3, and so on); the secret-scan tests to P5, two to M3. Ambiguous tests (for instance `github-history`'s "refuses a link at a tracked path") were left untagged. This is a curated set, not the K51b count of 85.
- **The 50 untagged guarantees are "not yet tagged", not "unproven":** a test may prove one. The list is in `kitchen/reviews/proof-gaps.json` and can only shrink. Tagging them is slow, careful reading and is left as incremental work (each wave that touches a stage can tag its guarantees).
- **Found on the way:** CONTRACTS still says "all 133 names", the code constructs 170 refusal reasons; the solver side (`take`, `submit`, `discover`) has no guarantees section at all (BACKLOG).
