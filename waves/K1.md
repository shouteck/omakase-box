# K1: verify on the host without Docker

Milestone: K · Base: master at the lean-kitchen merge · Branch: `wave/K1` · Size guess: 3 hours

## Outcome

With no database container running, `node scripts/verify.mjs --only test:box-contracts test:box-auth` exits 0 on a committed tree after a frozen install, twice in a row, and leaves nothing behind.

## Scope

- Write: `scripts/verify.mjs`, `package.json`, `pnpm-lock.yaml`, `pnpm-workspace.yaml` (only if an install-script allowance is unavoidable; see notes), `tests/box/auth/support.ts`, `scripts/suite.mjs`, `scripts/vitest.config.mjs`
- Read for context: `scripts/docker.mjs`, `scripts/toolchain.json`, `tests/box/**`
- Do not touch: `services/**`, `apps/**`, `packages/**`, any test assertion, `scripts/box-verification/**`, `tests/box/verification/**`

## Done when

- `node scripts/pnpm.mjs install --frozen-lockfile` succeeds and `packages/box-contracts` resolves `zod` (today it is missing from the lockfile).
- `scripts/verify.mjs` starts an embedded Postgres by default (`embedded-postgres` as a root development dependency, pinned to a Postgres 17 release) on a loopback port, in a temp directory it deletes afterwards. `--db=docker` and `KITCHEN_PG_URL` keep working.
- The Box test database helper accepts the URL verify provides (loopback only), has no database cap, and drops the databases it created when the suite ends.
- The Outcome run passes twice. Afterwards there is no leftover Postgres process, temp data directory or database.
- Must fail: pointing `BOX_TEST_DATABASE_URL` at a non-loopback host is still rejected by the helper.
- Run the full `node scripts/verify.mjs test:box-contracts test:box-auth` (with `check` and `build`) once and record the result. Failures confined to `*-live.test.ts` files are reported, not fixed in this wave.

## Notes for the worker

- The helper hard-codes `APPROVED_FIXTURE_DB_HOST`, a run-database prefix and `MAX_RUN_DATABASES = 12`. Those protected a preserved container that no longer exists. The database is now disposable, so replace them with a loopback check and cleanup.
- `tests/box/auth/fixture-transport.test.ts` tests the old container relay and is part of `test:box-auth`. If it cannot pass without that relay, stop and report what it needs; do not delete or weaken it.
- Remove the `BOX_VERIFICATION_PROFILE` branches from `scripts/suite.mjs` and `scripts/vitest.config.mjs` only if nothing else reads them. Otherwise leave them and say so.
- `pnpm-workspace.yaml` sets `minimumReleaseAge` and `strictDepBuilds`. Prefer a dependency version that needs no policy change. If an install-script allowance is unavoidable, add only that one package and say so in the report.
- Docker Desktop stays running on this machine for the legacy test stack; "no database container" means verify must not start or use one.
