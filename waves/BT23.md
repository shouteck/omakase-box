# BT23: old record shapes are converted in one place, and the leftover words go

Milestone: BT · Station: packaging · Base: master at dispatch, after BT22 · Branch: `wave/BT23` · Timebox: 150 minutes; at expiry the cook stops and reports where it is

Detailed for a cook without deep reasoning: every conversion is listed, and so is every reader that goes.

## Why

The record (`.box/bounties/<id>.json`, `BountyRecord` in `packages/box-bounty/record.ts`) still carries the vocabulary of designs the product has left: stages nothing moves a record into any more (`verified`, `undone`, `expired`), attempt outcomes from when the tool ran checks (`check-failed`, `check-unrunnable`, `check-not-run`), a singular `answer` from before several solutions, fields nothing writes (`replies`, `job`, `level`), and three separate places that decide what counts as a retired route. Every reader of the code has to hold all of it. Real old records do exist: this repository keeps five ended ones in `.box/bounties/` (`applied`, `rejected` and one `undone`, from the folder era), and they must still load and show in `status`.

## Outcome

Old shapes are converted to today's shape in one function when a record is loaded, and nothing else in the code mentions them. The never-written stages, outcomes and fields are gone from the types.

## Scope

- Write: `packages/box-bounty/record.ts`, and the modules that read the removed names (`github.ts`, `format.ts`, `owner.ts`, `look.ts`, `answer.ts`, `merged.ts`, `packages/box-cli/src/cli.ts`), `tests/box/bounty/**`, `docs/box-v4/BOUNTY.md`.
- Do not touch: **the `confirmed` stage and the pre-BT8 recorded-approval post path** (`githubApproval`, `legacyConfirmed` in `github.ts`). BT8 promised that a yes already written on a record stands (`record.test.ts`: "a pre-BT8 record at stage `confirmed` still loads and posts — the yes written on the record stands"), and the owner's rule is that the tool honours what it promised. They stay exactly as they are; the Result names them as the one compatibility path kept on purpose. Also do not touch: the five real records in `.box/bounties/` (they are the compatibility test; do not rewrite them by hand); the folder-draft reader that lets an old unposted folder draft post (BT15 kept it; BT24 decides its future); anything about the snapshot (BT24).

## The conversions, all inside the load function (`asRecord`)

Converted in memory when a record is read. A record written back by the tool afterwards is written in today's shape; that is intended.

| Old shape | Becomes | Why it is safe |
|---|---|---|
| `answer` (one block) and no `attempts` | `attempts: [ one attempt ]`, exactly as `attemptsOf` builds it today | the same values `attemptsOf` already produces; `attemptsOf` then becomes `record.attempts ?? []` |
| attempt outcome `verified` | `answered` | since checks were removed, both mean "a solution that can be applied" (`applicableAttempts` treats them the same) |
| attempt outcome `check-failed`, `check-unrunnable`, `check-not-run` | `set-aside`, a new single outcome meaning "recorded under checks and never green; not a default pick" | keeps today's rule that such an attempt is never picked without its number |
| stage `verified` | `answered` | the same reason |
| stage `undone` | stays an ended stage named `undone`, shown in `status` as "ended: the merge was reversed (an old record)" | one real record has it; it must keep its meaning |
| stage `expired` | removed from the type entirely | `git log -S "stage: 'expired'"` finds no write ever; a file with it fails to load as any unknown stage does |
| `replies`, `job`, `level` | dropped | nothing writes them; `job` was only printed on ended records, which fall back to the title, as `jobLine` in `cli.ts` already does |

After this, `AttemptOutcome` is `'answered' | 'set-aside'` and `OpenStage` is `'drafted' | 'confirmed' | 'waiting' | 'posted' | 'taken' | 'answered'`.
