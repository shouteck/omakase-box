# PF52: Agent-authorized pay on merge

Milestone: platform · Station: packaging · Base: `origin/master`

## Outcome

Approved imports can use the same verified-landing, direct-payment engine as posted bounties. An exact, case-insensitive `omakase approve <id> $<amount> on merge` comment authorizes this bounty without a repository switch. Plain approval retains the switch requirement. Manual and Checkout remain fallbacks. PayPal Vault adds an owner-saved payment rail, preferring Stripe where both rails work. No live payments or deployment.

## Plan

1. Store approval time, reward and explicit merge consent; share landing verification with listed pulls and preserve existing posted safeguards.
2. Expose agent-readable eligibility and setup links; update conditional payment copy and cover approval/merge/payment guards.
3. Add owner PayPal Vault setup/removal and idempotent automatic PayPal capture with rail selection.
4. Run platform and bounty verification, local poster-to-paid rehearsal, test-edit gate and a merge-tree check against PF51; commit and push without a PR.

Architect skipped: reuse the existing settlement engine and its idempotency rather than introduce a parallel bounty lifecycle. Model-the-domain: approval time, approved reward and per-bounty consent are durable facts, separate from provider outcomes.

Throughput checkpoint:
- Blocking first: approval and landing evidence before payment execution.
- Independent workstreams: n/a, one writer owns overlapping payment/refresh surfaces.
- Shared mutable state: serialize provider claims through the existing charges row.
- Smallest safe decomposition: Stripe/listed first, then Vault, then verification.

## Done when

- Approval, consent, time, landing, identity, reward, saved method, readiness and prior-payment guards are tested without real providers.
- Existing posted tests and listed manual/Checkout behavior remain intact.
- Agent facts name the available rail or explain blockers, including both human setup links.
- Required verification, local rehearsal, test-edit gate and PF51 conflict result are recorded.
