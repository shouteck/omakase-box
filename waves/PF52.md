# PF52: Agent-authorized pay on merge

Milestone: platform · Station: packaging · Base: `origin/master`

## Outcome

Approved imports and prepared agent branches can use the same verified-landing, direct-payment engine as posted bounties. Only an exact, case-insensitive `omakase approve <id> $<amount> on merge` comment authorizes automatic payment for an import. Plain approval stays owner-chooses/manual or agent-initiated pay; old repository switches authorize ordinary CLI-posted bounties only. Manual and Checkout remain fallbacks. A single saved rail is used directly; two saved rails require an account default or explicit via override. Fallback is off unless expressly enabled and never applies to via. No live payments or deployment.

## Plan

Add nullable Stripe ready_at, backfill old ready rows to cutoff, record observed ready transitions on callbacks/webhooks, and preserve old-Worker updates with an additive trigger. Automatic readiness compares Stripe ready_at / PayPal at to the actual merged_at; explicit pay and manual paths keep current-readiness behavior. Update migrated scheduled-worker regressions to zero charges for every existing merge, add timestamp boundary/late/unknown regressions, then verify platform + bounty + edit gate and push once. Model the Domain informed keeping ready_at as durable evidence distinct from today's ready boolean.

1. Store approval time, reward and explicit merge consent; share landing verification with listed pulls and preserve existing posted safeguards.
2. Expose agent-readable eligibility and setup links; update conditional payment copy and cover approval/merge/payment guards.
3. Add owner PayPal Vault setup/removal and idempotent automatic PayPal capture with rail selection.
4. Run platform and bounty verification, local poster-to-paid rehearsal, test-edit gate and a merge-tree check against PF51; commit and push without a PR.

Architect skipped: reuse the existing settlement engine and its idempotency rather than introduce a parallel bounty lifecycle. Model-the-domain: approval time, approved reward and per-bounty consent are durable facts, separate from provider outcomes.

- Shared mutable state: serialize provider claims through the existing charges row.
- Smallest safe decomposition: Stripe/listed first, then Vault, then verification.
