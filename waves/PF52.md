# PF52: Sessionless agent imports

Milestone: platform · Station: packaging · Base: `origin/master`

## Outcome

Agents can submit a public GitHub issue and whole-dollar reward without an Omakase session, then post the exact approval comment from an account that owns or can write to the repository. Sessionless imports require GitHub OWNER/COLLABORATOR association; merely opening the issue grants no authority. Session imports keep PF44's existing rules. A human still pays. No payment, take or merge changes, migration, deployment or live bounty.

## Plan

1. Reuse pending imports with a nullable importer, a bounded JSON endpoint and independent abuse counters.
2. Expire only anonymous pending imports after 14 days; preserve null attribution in detail and pages; document the interface.
3. Exercise the endpoint, visibility, comment approval, limits and expiry with the GitHub stand-in. Build, verify platform, check test edits, commit and push the branch.
4. Add shared additive attempt instructions to site and machine/MCP detail, preserving all existing fields; verify draft-to-ready polling for both posted and listed bounties without changing solver logic.

## Done when

- POST /api/agents/import accepts only issue/reward, never uses cookies or requires Origin, and returns the approval line and issue URL.
- Pending records have null importer, stay hidden from feed/MCP/board, and approve through comments from OWNER/COLLABORATOR only, not an unrelated issue author.
- Global 10/minute and half-hour-budget limits refuse requests; malformed inputs refuse with actionable facts.
- Refresh removes only sessionless pending imports at 14 days and logs the removal.
- Both detail JSON forms and MCP name the PR target, issue-closing text for imports, draft attempt (no reservation) and ready-for-review submit signal. Existing refresh logic polls those facts unchanged.
- Agent docs explain issue-account comment approval and human payment. New tests cover success, rejection, limits, attribution and expiry.
- `node scripts/workspace.mjs build`, `env HOME=$HOME/kitchen-home node scripts/verify.mjs test:platform`, and `node scripts/test-edit-gate.mjs --base origin/master --wave PF52` are recorded; environment failures are compared with master.

## Changed expectations

## Result

Implemented and locally test-verified on Devin Linux; no deployment or merge. Product candidate: `74dc6da1`.

- `/api/agents/import` reads at most 1024 bytes, accepts exactly issue/reward, ignores sessions/Origin and stores a null importer. One atomic 10/minute counter and the shared half-budget check protect GitHub reads. The original issue author's numeric id is retained but cannot alone approve a sessionless import: GitHub OWNER/COLLABORATOR association is required. Session imports retain PF44's author shortcut and OWNER/COLLABORATOR rules.
- Detail preserves null attribution and the page omits a nonexistent importer. Feed and /me have no listed_by consumer to change. No migration: both importer columns were already nullable.
- Refresh removes sessionless pending imports at 14 days through removeBounty and logs agent-import-expired. The initial implementation added a read and failed the existing refresh database-call limit (11 versus 10); batching expiry with the initial metadata read restored the unchanged limit. Expiry still runs when GitHub is paused.
- `llms.txt` documents the endpoint, approval from an account that owns/can write to the repository, human payment, limits and expiry. Actual polling remains unchanged: cron every minute, pending approval in the normal details refresh due every 15 minutes, subject to read budget. No one-minute promise.
- Existing site detail is `/api/b/<id>` (not `/api/bounties/<id>`); machine detail is `/bounties/<id>.json`, also used by MCP get_bounty. Site detail already exposed branch/default_branch/issue links; machine detail already exposed answer branch/base/closing text and how_to_answer. Both now add a shared attempt object without changing those fields. Posted PRs are polled by bounty branch; imported PRs are read from same-repository issue timeline references (Fixes is recommended, not the only recognized link; default-base guidance is not enforced by the timeline reader). Draft-to-ready changes the attempt count, not a separate submitted state. Solver/payment/merge logic is unchanged.
- `tests/platform/pf52.test.ts`: 25 cases cover success, discovery hiding, valid-cookie isolation, OWNER/COLLABORATOR approval, NONE/CONTRIBUTOR/MEMBER rejection despite issue authorship, invalid/empty/oversized requests, private issue refusal, rate (atomic under concurrency)/budget limits, expiry scope/boundary, and draft-to-ready polling and identical attempt guidance in site/machine/MCP detail for both sources.
