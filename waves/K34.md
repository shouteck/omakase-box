# K34: verification starts leave evidence even when completion never arrives

Milestone: K (kitchen) · Station: evidence · Base: master at dispatch · Branch: `wave/K34` · Timebox: 120 minutes; stop and report at expiry.

## Outcome

Implement K33 recommendation P1 only, approved by the owner's "go ahead with recommendation" on 19 October 2026. Each accepted verification invocation leaves a durable start record before check/build/suite work, so an interrupted run remains attributable. Kitchen stats distinguish this evidence from completion. No changes to PASS criteria, exit codes, step reuse or the other nine recommendations.

## Done When

- `node scripts/verify.mjs test:kitchen` exits 0 on a clean committed candidate; the pass completes its own invocation and inspects any reused evidence. This changes kitchen tooling, not product behavior.
- A small versioned `started.json` is written synchronously when a run directory is created, before dirty-tree refusal/check/build/suite work. It identifies the commit, start time, dirty-at-start flag and effective validated plan/flags; store only necessary non-secret facts, not arbitrary environment or unchecked command strings.
- Real child-process regression proves the marker exists before a controlled step finishes. A forced stop of only the test's own verifier leaves readable start evidence but no invented completion/PASS; capture an observable ready point, not a fixed sleep.
- Normal PASS, failing step and UNCOMMITTED refusal retain truthful final summaries and their current exit/reuse semantics. Start metadata must never overwrite completed summaries or become acceptance/reuse evidence.
- Stats read legacy summary-less directories, start-only directories, malformed start/summary data and completed records without crashing. A start-only record is labelled unfinished (running or interrupted), not proven dead; completion verdict/duration remain missing. Summaries remain authoritative when valid.
- Tests prove a start-only record cannot break the existing non-PASS stall streak, satisfy the acceptance budget, or be reused as a completed step. Include corrupt/mismatched start metadata if metadata is used for attribution.
- Compare before/after with an owned fixture: previously only a directory name survived an interrupted run; afterwards the marker supplies the planned invocation facts. Report the actual observation, not a claimed time saving. Keep historical denominators and unknown values honest.
- No unbounded per-record Git spawning, speculative liveness detection, broad signal/process-tree framework or unconditional exit handler that overwrites a valid verdict. Uncatchable termination cannot promise a final summary; surviving start evidence is the minimum invariant.

## Review Lenses

- [x] **Security:** metadata does not capture secrets or grant executable authority; interruption tests stop only their own children and cleanup only their own scratch; no incomplete evidence can grant PASS/reuse.

- [x] **Measurement fairness:** inspect actual before/after fixture records; unknown completion time is not zero; all attempts remain represented; no timing/performance claim from one observation.
