# BT55: a file's name cannot break the tool

Milestone: PF (the platform) · Station: packaging · Base: `master at dispatch` · Branch: `wave/BT55` · Timebox: 120 minutes; at expiry, report partial findings and stop
Owner decisions: none
Horizon: short

**Brief.** Written by the CTO on 10 November 2026 from [K48](K48.md). Two faults a solver's file name can cause, both in BACKLOG since October ([BT43](BT43.md) pass 6, [BT48](BT48.md)), neither yet reproduced through a command. Bug-fix playbook: reproduce first; a fault that does not reproduce is reported as such and left.

## Outcome

A solution containing a file with an unusual name does no lasting harm: after it is merged, `create` still works; after it is refused, nothing of it stays in the owner's working tree.

## The two faults

1. **A quote in a name stops every later `create`.** On git 2.43, `ls-tree -z --format=%(path)` still quotes a name that holds a quote character (`create.ts:308`), so once such a file is on the branch every `create` refuses `unreadable-path`. One merged file ends the tool's use on that repository until someone renames it. Git refuses such a name on Windows, so this shows on Linux and macOS only.
2. **On Windows a refused merge can leave a solver's file behind.** `rmSync` on Node 24.11.0 returns without deleting a non-ASCII name (`café`, Cyrillic, CJK, bidi), file or folder; `unlinkSync` works. `answer.ts:124` restores the working tree after a refused merge with `rmSync`, so a solver's non-ASCII file could stay in the owner's tree.

## Scope

- Write: `packages/box-bounty/create.ts`, `answer.ts`, one small checked-delete helper if two sites need it, a new `tests/box/bounty/bt55.test.ts`
- Read for context: `publish-plan.ts:472` (reads names with `--name-only`, which is not quoted; the likely model for the fix), `git.ts`, `tests/box/bounty/bt48.test.ts`
- Do not touch: the never-ship rules, what `apply` merges, the other `rmSync` calls unless the reproduction shows one leaves a file

## Done when

- `node scripts/verify.mjs test:box-bounty test:kitchen` exits 0 on the final commit, and the off-machine run is green after the merge: fault 1's test cannot run on Windows, so it carries a platform guard and the Linux run is its proof. Name that in the Result; do not call it verified from the Windows run.
- Fault 1: a test commits a file whose name holds a quote, then runs `create`; it fails on master's code on Linux (seen on a `wave/BT55` push's hosted run, or stated as not seen) and passes after.
- Fault 2: a test drives a real refused `apply` whose solution adds a non-ASCII file and a non-ASCII folder, then asserts the working tree and `git status` are as before. If master's code already leaves nothing, the Result says the fault does not reach a command and the code is left as it is.
- A delete that did not delete is a named refusal with a next step, never silence: assert the path is gone after removing it.

## Lenses

- [x] **Security:** a stranger chooses these names. Try: a quote, a backslash, a newline, a tab, a leading dash, a trailing dot or space, NFC against NFD spellings of the same name, a bidi override, and a name 255 bytes long. Say which Git or the file system refused before the tool saw them.

## Notes

- Follows Git: read names with `-z` and without `--format` quoting, as `git ls-files -z` consumers do.
- Tests that create non-ASCII temp files must remove them with the checked delete too, or they litter `%TEMP%` (BT48).
