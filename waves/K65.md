# K65: test the rule as data, the plumbing once (a pilot on never-ship)

Milestone: K (kitchen) · Station: evidence · Branch: `wave/K65` · Timebox: 240 minutes
Owner decisions: on 12 November 2026 the owner said the cause of slow tests is probably how the tests are written and what they test, not their machine, and to look for a faster way to write tests for this tool.

**The idea.** `never-ship.test.ts` built a whole Git repository for each path spelling (about a second each) to learn one thing: whether a rule names that path. The rule is a pure function (`BUILTIN_RULES[].match(path)`, `matchingSkeleton`, the owner list's matcher). Two levels say the same things faster and more sharply: **level 1**, the rules as data (a table of paths and the rule that must name each, a seeded property over case, prefixes and invisible characters, the owner list's grammar), pure and in milliseconds; **level 2**, one real repository holding a file for every route a path takes to the rule (tracked, untracked, nested, an upper-case alias, the owner's list), planned and finalised once, with every removal checked against level 1. The real journey tests stay; the per-spelling worlds go.

## The proof (the K51 method, run for real)

Each of 19 one-place breaks of the code was applied in a scratch worktree and the old and the new test file run against it (`kitchen/reviews/K65-breaks.md` has the method; the break table is the runner's output):

| break | what it does | old file red | new file red |
|---|---|---|---|
| env-dotfile | .env and .envrc files stop matching | 2 | 4 |
| env-suffix | *.env files stop matching | 1 | 4 |
| fold-lowercase | path folding stops lower-casing | 1 | 8 |
| fold-invisible | invisible characters stop being removed before matching | 0 | 3 |
| fold-lookalike | look-alike letters (Cyrillic and others) stop folding | 0 | 3 |
| secrets-exact-only | secrets-dir matches only a folder named exactly secrets | 1 | 4 |
| secrets-overmatch | secrets-dir also matches secret (secretary/) | 2 | 4 |
| key-ext-p12 | .p12 stops being key material | 1 | 2 |
| key-id-ed25519 | id_ed25519 stops matching | 2 | 6 |
| cert-ext-cer | .cer stops being a certificate | 1 | 2 |
| credential-npmrc | .npmrc stops being a credential file | 1 | 3 |
| dot-git-rule | the .git rule matches nothing | 0 | 3 |
| owner-pattern-fold | owner-list patterns stop folding | 1 | 2 |
| owner-path-fold | owner-list paths stop folding | 0 | 1 |
| owner-dir-anchored | owner dir pattern matches only at the top | 0 | 1 |
| owner-basename-anchored | owner basename pattern matches only at the top | 2 | 3 |
| plumbing-tracked | the snapshot stops applying the rules to the files it lists | 10 | 1 |
| plumbing-untracked | (mislabelled: the .box/bounties record accounting, not untracked files) stops applying the rules to the tool's own records | 0 | 0 |
| task-file-check | the --task file check stops applying the rules | 2 | 0 |

- **The new file catches every break the old one did, and five more:** invisible characters, look-alike letters, the `.git` rule, and two owner-list folds (rows where the old column is 0 and the new is not). Where a candidate old test went red, a new test did too: for all 19 breaks, no old per-spelling test is red without a new test red (checked by script).
- **One break neither catches, one only the old does:** `plumbing-untracked` (as labelled) is really the `.box/bounties/<id>.json` record accounting in `snapshot.ts`: tracked and untracked files go through the same loop (the `plumbing-tracked` row, caught by both). That accounting only names the tool's own records in the removal report; the protection is Git's ignore of `.box/local`. No test of either kind notices it: a small gap, in BACKLOG. `task-file-check` (the `--task` file check) is caught only by the two old `--task` tests, which stay.
- **Cost, relative, as shape not minutes:** the old file is 13 tests at about 9.9 s; the new file is 70 tests at 2.2 s, of which about 1 s is the one repository and about 0.9 s is fixed start-up. The old cost grows with every spelling added (a repository each); the new grows by a table row (a function call). The same shape holds on any machine.

## What changed

- **Added** `tests/box/bounty/never-ship-layers.test.ts` (70 tests, tagged `@guards C1`), and [docs/box-v4/TESTING.md](../docs/box-v4/TESTING.md) with a one-line pointer in AGENTS.md: the principle written down (which level a test belongs at, the cost model, the break proof for replacing or removing a test, hard stops need both layers, words).
- **Removed** eight tests from `never-ship.test.ts`, the ones the proof shows are subsumed. **Kept** the junction test, the link-escape test, "never names a removed file inside the bounty folder" (a leak check on the record) and the two `--task` refusals: they test something the layers do not.

## Changed expectations

- never-ship.test.ts::removes a secret that is tracked — replaced by the level 2 repository (tracked `secrets/api.key`) and the level 1 table; every break that turned it red turns the new tests red.
- never-ship.test.ts::removes an untracked secret — replaced by the level 2 repository (untracked `token.pem`, `.ENV`) and the level 1 table; same proof.
- never-ship.test.ts::removes a secret reached through a different letter case — replaced by level 1 (upper-case and mixed-case spellings, plus 40 seeded case variants of every row) and the upper-case file in the level 2 repository.
- never-ship.test.ts::removes a secret in a nested folder — replaced by level 1 (prefix directories, seeded) and `a/b/c/deep/` in the level 2 repository.
- never-ship.test.ts::removes what only the owner list matches — replaced by level 1's owner-list grammar tests and the owner-listed files in the level 2 repository.
- never-ship.test.ts::catches credential stores and key-material spellings — replaced by level 1's table (every spelling it used, plus more).
- never-ship.test.ts::catches env-file suffixes, key backups, cert bundles and secrets-dir variants — replaced by level 1's table, which also holds the benign names (`secretary/`) it asserted survive.
- never-ship.test.ts::folds owner-list patterns before matching, on both sides — replaced by level 1's folding test of the owner list.

## Result

Done on 12 November 2026. The proof table above is the evidence; the two levels pass on the unbroken code (75 tests across the two files), `scripts/workspace.mjs check --full` is clean, and the K62 gate lists the eight removals as read from this file.

- **This is a pilot, on one area.** It shows the method on the guarantee with the most tests (C1). The same split applies wherever a rule is a function the tests reach through a repository: the failure classifier, the scan, the folder and path checks, the settings and gate decisions. The principle for new tests: *test a rule where it lives, as data; test the plumbing once per route with a shared world; keep a few real journeys.*
- **Not done:** the other never-ship tests (`bt48`'s look-alike worlds, `bt8c`) were not converted; no product code changed.
