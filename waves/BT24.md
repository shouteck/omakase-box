# BT24: the snapshot is used while drafting, and no longer kept

Milestone: BT · Station: packaging · Base: master at dispatch, after BT23 · Branch: `wave/BT24` · Timebox: 120 minutes; at expiry the cook stops and reports where it is

**Brief.** Written by the CTO on 15 October 2026 from K21's snapshot decision (`kitchen/reviews/K21-architecture.md`, "Step 5 — the snapshot, decided on evidence"), the middle course; the owner agreed the queue that day. Detailed for a cook without deep reasoning.

## Why

`create` captures the working state (committed, uncommitted and untracked files) into a Git commit built on a scratch index (`createSnapshot` in `packages/box-bounty/snapshot.ts`). K21 split its uses in two:

- **While drafting** (still needed): the create-time secret scan reads the captured files, and the hand-off note lists what changed against the base (`composeNote` in `create.ts`). The capture is the honest list of the working state, including links and junctions handled correctly; `snapshot.test.ts`'s classification, no-mutation and junction tests protect it.
- **Kept afterwards** (no longer needed for new drafts): `writeNewRecord` in `record.ts` pins the commit at `refs/box-bounty/<id>` and stores `record.snapshot` (`commit`, `tree`, `baseCommit`). For a draft made today nothing reads them after `create`: `look` uses the publication commit (`record.github.commit`), `resume.commit` already holds the base, and `answer.ts` only prints the snapshot hash in a merge message. Only old records (folder drafts, pre-history publications) read them.

So every new draft leaves a third kind of commit in the owner's repository, a ref, and a record field that nothing uses.

## Outcome

A new draft leaves no snapshot ref and no `snapshot` field; the capture still runs during `create` and serves the scan and the note exactly as today. Old records keep their refs and fields and load, show and close as before.

## Scope

- Write: `packages/box-bounty/record.ts`, `create.ts`, `snapshot.ts` (only if the transient object changes, see below), `look.ts`, `answer.ts`, `tests/box/bounty/**`, `docs/box-v4/BOUNTY.md` ("The snapshot identifier" section).
- Do not touch: the capture's enumeration and classification (`classifySnapshot`); never-ship; the scan; `dropDurabilityRefs` (deleting an absent ref is harmless, and old records still need it); the folder-draft reader for old unposted drafts, which still checks its own recorded snapshot.

## The changes

1. **`writeNewRecord` stops pinning and storing.** Remove the `git update-ref refs/box-bounty/<id> …` line and the `snapshot` field from new records. `BountyRecord.snapshot` becomes optional (`snapshot?:`), documented as "old records only".
2. **The draft id.** `create.ts` builds the id from `sha256(snapshot.commit + title + createdAt)`. Keep that input (the commit still exists during `create`); nothing about ids changes.
3. **Readers of `record.snapshot`** fall back for new records:
   - `look.ts` (around line 56): `record.github?.kind === 'history' ? record.github.commit : record.snapshot?.baseCommit ?? (record.resume.kind === 'recorded' ? record.resume.commit : null)`; a `null` base keeps today's "no base" path.
   - `answer.ts` (around line 247): print the snapshot line only when the record has one.
   - Search for every other `record.snapshot` and `.snapshot.` read with `grep -n` and list them in the Result.
4. **Optional, the implementer's choice:** the capture may become a tree (`git write-tree` on the scratch index) instead of a commit, since a tree is enough for the scan and the note. Do it only if every `snapshot.test.ts` case stays green unchanged except the one named below; otherwise keep the commit and say why.

## Tests whose expectations change

These protected "the draft's facts survive Git's garbage collection", which is no longer a promise for new drafts because nothing after `create` reads them. Replace each; do not just delete it.

- `tests/box/bounty/record.test.ts` "create writes .box/bounties/<id>.json at stage drafted and pins the snapshot under a ref gc cannot prune" (around lines 41 to 58): becomes two tests. (a) A new draft writes the record at `drafted` with no `snapshot` field, and `git for-each-ref refs/box-bounty/` lists nothing for it. (b) An old record that has `snapshot` and a ref (hand-made fixture) still loads, its ref survives `git gc --prune=now`, and `close` removes the ref.
- `tests/box/bounty/snapshot.test.ts` "records an identifier Git itself resolves, and recreation reproduces the tree" (around line 70): becomes "the capture is a real Git object during create, and recreation reproduces the tree" (check the object inside the plan before finalising, not the record afterwards).
- `tests/box/bounty/bt15.test.ts` around line 188, the ref assertion: the same treatment as (a).

All other snapshot, classification, junction and no-mutation tests stay unchanged and green. List every changed line in the Result.
