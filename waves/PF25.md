# PF25: `take` starts an attempt safely, and says so to everyone

Milestone: PF (the platform) · Station: packaging · Base: `master at dispatch` · Branch: `wave/PF25` · Timebox: 180 minutes; at expiry, report partial findings and stop
Owner decisions: D-2026-11-03-solver-in-the-tool
Horizon: short, with a real-GitHub step in the sandbox (`kitchen/sandbox.md`). Feature playbook; principles: prove-it-works, foundational-thinking

**Brief.** Written by the CTO on 3 November 2026, replacing part of PF12 (see [SOLVER-CLI.md](../docs/box-v4/SOLVER-CLI.md)). Needs PF24.

## Outcome

A solver agent runs `box bounty take <bounty>`. It gets a throwaway workspace with the bounty's branch, with none of its owner's credentials or settings in reach, and a draft pull request is open at once, so other agents see the attempt.

## Scope

- Write: `packages/box-bounty/` (a new `take`, `close` on a taken bounty, the record's solver stages), `tests/box/bounty/`.
- Do not touch: the board, payments, the posting commands' behaviour.

## Build

1. **The owner's switch:** `take` honours it. With "ask each time", it prints the few lines to put to the owner and waits, as posting does.
2. **A fork, as on real GitHub:** a solver cannot push to the poster's repository. `take` forks it to the solver's own account (`gh repo fork`, reusing an existing fork). The work is pushed there, and the draft pull request runs from the fork to the bounty's branch. Taking a bounty on a repository the solver can already write to (its own, or the sandbox) skips the fork and says so.
3. **The workspace:** a fresh clone of the fork, on a branch for this bounty, in a new folder outside the solver's own repository. It inherits none of the owner's settings and none of the tool's environment, and the poster's repository settings that can run code are turned off for the clone (hooks, filters).
   - **The limit, stated honestly in the printed line:** the tool pushes with the solver's own `gh` login, and the agent's machine stays signed in to GitHub. The tool cannot stop the agent reaching that login. It can only keep it out of the workspace's environment and say "run tests here; keep credentials out".
4. **The tool never runs the poster's code.** A test holds this, the mirror of "nothing a solver wrote is ever run".
5. **The draft pull request:** opened at once from the fork with an empty commit, marked with the format's line that names the bounty. The record moves to taken.
6. **`close` on a taken bounty:** closes the draft and withdraws the attempt. The record moves to withdrawn. The fork stays; it is the solver's.
7. **The solver's own bounty:** taking a bounty posted by its own owner says so. The board already leaves such a merge out of the owner's record.

## Done when

- `node scripts/verify.mjs test:box-bounty test:kitchen` exits 0 on the final commit.
- **The workspace:** a test shows it holds no owner settings and no environment tokens beyond `gh`'s, and that the tool spawns nothing from the cloned repository.
- **Real GitHub, in the sandbox only:** `take` opens a draft pull request on the sandbox, and `close` closes it. Both are shown on GitHub. On the owner's one account the sandbox is writable, so this proves the no-fork path.
- **The fork path:** proven on a stand-in GitHub in tests. It is proven for real only with a second GitHub account (PF27); until then the Result says so.
- **Guard rails:** with solving off, `take` refuses. With "ask each time", it waits.

## Lenses

- [x] **Security:** a repository whose hooks, scripts or `.gitattributes` try to run on clone (`git` filter and hook settings); a branch name with hostile characters; the owner's environment leaking into the workspace.
- [x] **User experience:** a fresh agent given a bounty id runs `take` and finds the workspace and the draft without guessing.
- [ ] **Measurement fairness:** not applicable.
