# BT21: the edges hold, and closing up on GitHub says when it was not asked

Milestone: BT · Station: packaging · Base: master at dispatch, after BT20 · Branch: `wave/BT21` · Timebox: 150 minutes; at expiry the cook stops and reports where it is

**Brief.** Written by the CTO on 15 October 2026 from K21's fifth proposed wave and the owner's decision of that day. Detailed for a cook without deep reasoning: four separate fixes, each with its own test, done in the order listed.

## Why

K21 found writes at the edges that are not re-checked, and one question only the owner could answer (`kitchen/reviews/K21-architecture.md`, S9, S11, S13, A4):

- **Closing up on GitHub after permission changed.** When a bounty ends (a solution merged, or `close`), `syncGitHubDecision` in `packages/box-bounty/github.ts` comments on the issue, closes it and deletes the bounty branch, without reading the owner's current decision. **The owner decided on 15 October 2026:** the tool may still close up a bounty it opened, because it only finishes what was allowed and leaves no stale open issue, **but it says so.** Its own comment above the function also describes a waiting state that the code does not have; that comment is wrong and goes.
- **`config set instruction-file` can name a file inside `.git/` or `.box/`.** BT8b verified that a block appended to `.git/config` breaks Git in that repository, and one in `.box/bounties/<id>.json` corrupts the record. `instructions.ts` checks the file is inside the project, exists, is a plain file and not a link; it does not refuse the tool's or Git's own folders.
- **After `apply` aborts a clashing merge, the index can be left stale on Windows** (K15, BT14): the agent's own `git merge` then refuses until `git update-index --refresh`.
- **The same inside-the-project check is written twice:** `hook.ts`'s `checkedSettingsPath` and `instructions.ts`'s path check (around lines 21 to 37).

## Outcome

The tool still closes up a bounty on GitHub whatever the current permission, and prints one line saying it did so without being asked; instruction files can never be inside `.git/` or `.box/`; an aborted `apply` leaves the index fresh; and one function checks that a path is inside the project.

## The four fixes, in this order

**1. The closing-up line.** In `syncGitHubDecision`, read the owner's decision once with `readDecision(root)` (catch a refusal: a repository whose identity cannot be read counts as "not allowed"). When the decision is anything other than `allowed`, and the function actually changed something on GitHub (posted a comment, closed the issue, or removed the branch), emit one line through the same notice path `merged.ts` uses (`setMergeNoticeListener`'s listener):

`<id> — closed up on GitHub without asking: the issue is closed and the bounty branch removed; your standing answer here is <deny | ask me each time | not given>`

Nothing is emitted when nothing changed (a retry that finds it all done) or when the decision is `allowed`. The behaviour on GitHub does not change. Delete the comment above the function that describes a waiting state; replace it with two lines stating what the function does and that the owner decided on 15 October 2026 that it runs whatever the standing answer.

**2. Instruction files never inside `.git/` or `.box/`.** In `instructions.ts`, after the existing inside-the-project check and after resolving links, refuse when the path's first segment (case-folded, on the canonical path) is `.git` or `.box`, or when the path is inside `git rev-parse --git-dir` (a worktree's Git folder can live elsewhere). New reason `instruction-file-tool-owned`: "<path> belongs to Git or to this tool; an instruction file must be one your agents read. Nothing changed". It applies to `config set instruction-file` and to any later sync that reads a stored choice, so a value already saved in the owner's settings is refused at sync and named in `config`.

**3. A fresh index after an aborted `apply`.** In `answer.ts`, on the path where `git merge --abort` succeeds after a conflict (around the `ownerGitOutcome(repoRoot, ['merge', '--abort'], ownerAttrs)` call), run `git update-index -q --refresh` with the same owner Git settings, and ignore its exit status (it exits 1 when files differ, which is expected). One Git start, only on the conflict path.

**4. One inside-the-project check.** Extract the path walk (resolve the path, refuse links that leave the project, refuse anything outside the top folder) into one exported function, for example `insideProject(root, path)` in `instructions.ts` or a small `paths.ts`, and use it from both `instructions.ts` and `hook.ts`'s `checkedSettingsPath`. Each caller keeps its own reason names for its refusals. Before extracting, write down both current implementations' rules side by side in the Result; if they differ in any case, keep the stricter rule for both and name the case.
