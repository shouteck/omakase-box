## Starting hypothesis (CTO survey — verify, don't trust)

**Clear removals:** `.execution/`, `docs/legacy/`, `milestones/M0–M9` + B-series,
`tasks/task-graph.json`, `tasks/box-v4-task-graph.json`, `services/external-api/`,
`services/runner-controller/`, `apps/contributor-portal/`, `infra/` (compose, trusted.Dockerfile,

**Partial — audit each file:** `docs/` top level (bounty-era vs box-v4), `scripts/`
(`execution.mjs`, `verify-mvp.mjs`, `research:report`, `demo.mjs`/`smoke-bootstrap.mjs` reference
the portal — decide), `milestones/` (keep `box-v4/`), `research/` (see trap below), `tests/`.

**Stays whole:** `services/private-api` (not in scope — it is the shared Box-loop service),
`apps/private-console`, `packages/box-cli`, `packages/box-contracts`, `packages/box-package`,
`examples/`, `db/migrations`, `kitchen/`, core scripts (`verify`, `suite`, `workspace`, `pnpm`,
`host-test-runtime`, `doctor`, `boundaries`, `kitchen-stats`, box helpers).

**The trap that shapes this wave:** because `private-api` stays whole, every package it
transitively imports stays. CTO survey found private-api imports `packages/contracts`,
`packages/evaluation`, `packages/compiler`, `packages/planner`, `packages/analyzer`,
`packages/runner-protocol` — likely meaning **no legacy package is removable**. If your
independent reachability analysis agrees, say so in the inventory and keep them; do not delete a
package that private-api needs just to shrink the tree.

**Known traps:**
- `tests/contracts/fixture/private-shop.test.ts` reads `research/fixtures` — keep that fixture or
  relocate it into the test; don't break the suite.
- `tests/e2e/contributor/` and `tests/portal/`, `tests/runner/`, `tests/containers/` test removed
  things → go. Suites testing kept code (`tests/analysis`, `tests/compiler`, `tests/planner`,
  `tests/acceptance`, `tests/security`, `tests/contracts`) stay if their subject stays — a kept
  package with deleted tests is untested code.
- Suites are enumerated in three places, all must agree after removal: `package.json` scripts,
  `scripts/verify.mjs`/`scripts/suite.mjs` registry, `.github/workflows/verify.yml` (drop
  `test:containers`/`test:security`/`test:box-package` exclusion comments only if the suites
  themselves are gone; keep the exclusion note for any survivor).
- `scripts/boundaries.mjs`, `scripts/workspace.mjs`, `scripts/demo.mjs` name the portal and
  analyzer — update or remove the references.
- `AGENTS.md` rule 8 and any doc referencing removed paths must name the tag instead.
- The K8 workflow comment lists suite exclusions — after suites disappear, the run line shrinks;
  update it honestly rather than leaving ghost suite names.
