# BT57: a solution made with the tool says so, in one fixed line

Milestone: PF (the platform) · Station: packaging · Base: `master at dispatch` · Branch: `wave/BT57` · Timebox: 60 minutes; at expiry, report partial findings and stop
Owner decisions: D-2026-11-10-k48-answers, D-2026-11-10-found-at-the-moment, D-2026-11-03-solver-in-the-tool
Horizon: short

**Brief.** Written by the CTO on 10 November 2026 from the owner's talk after [K48](K48.md). The owner's main concern is that an agent finds the tool at the moment it needs it. Agents read other agents' public work while doing their own, and a pull request made with `take` and `submit` today carries no sign of what made it. One fixed line turns every use into a pointer, and into the repeated public text a future model learns a name from. The owner accepted a fixed line.

## Outcome

Every pull request `take` opens, and `submit` marks ready, ends with one fixed line naming the tool and the board's address. It is the same everywhere, written by the tool, and says nothing else.

## What changes

1. **The line.** One constant in `wording.ts`, appended to the draft's body in `take.ts` and kept when `submit` rewrites the first sentence (`attempt.ts:96`). The words: "Made with omakase-box: `<board address>/agents/`" (the product's name, D-2026-11-10-one-name, so the line does not change when the command is renamed). The address is the board this machine is set to; with no usable address, the line names the tool and the package only.
2. **Not enforced.** The solver's agent may edit or delete its pull request's text with its own `gh`; the tool does not put the line back or refuse without it. `help` says so in one clause.
3. **The posted issue is not changed.** It already links the board (PF33).

## Scope

- Write: `packages/box-bounty/wording.ts`, `take.ts`, `attempt.ts`, `render.ts` (the `help` clause), `tests/box/bounty/pf25.test.ts`, `pf26.test.ts` or a new `bt57.test.ts`
- Read for context: `packages/box-platform/src/refresh.ts` (how the board reads a pull request's body), `packages/box-bounty/pay.ts` (the `pay-to` line), [PF25](PF25.md), [PF26](PF26.md), [PF32](PF32.md)
- Do not touch: the posted issue's text, the machine block, the skill's text, the instruction block

## Steps, in order

Written so any model can cook it. Lines are as read on 10 November 2026.

1. **The words, settled here so the public line never changes:** `Made with omakase-box: <board address>/agents/`. It names the product, not the command, so [BT63](BT63.md) does not have to reword text already on GitHub. With no usable board address: `Made with omakase-box (npm: omakase-box)`.
2. **Tests first:** new `tests/box/bounty/bt57.test.ts`, the table below. Copy the setup of `tests/box/bounty/pf25.test.ts` (take) and `pf26.test.ts` (submit). See rows 1 to 3 fail.
3. **One source,** `packages/box-bounty/wording.ts`: export `creditLine(board: string | null): string`.
   - It accepts the address only if it matches `^https:\/\/[a-z0-9.-]+(?::\d{1,5})?$` (lower case, no path, no query). Anything else counts as no address. This is what keeps a hostile setting out of a pull request.
   - The address comes from `boardAddress()` in `board.ts` (line 34).
4. **`take`,** `packages/box-bounty/take.ts` line 139. Today the body is `DRAFT_BODY(id)`, or `DRAFT_BODY(id)` then a blank line then the `Fixes #N` line. 5. **`submit`,** `packages/box-bounty/attempt.ts` line 96: it replaces only the draft sentence inside the existing body, so the credit line survives with no code change. Prove it with row 2; change nothing unless that test fails.
6. **`help`,** `packages/box-bounty/render.ts`: one clause where `take` is described: "its draft ends with one line naming the tool; you may delete it". Check BT17's word budget for that command still holds (`tests/box/bounty/` has the budget test: search `budget`).
7. **Readers treat it as nothing.** Run rows 4 and 5 against `packages/box-platform/src/refresh.ts` (how the board reads a pull request's body for `Fixes #N` and `pay-to:`) and `packages/box-bounty/pay.ts` (`parsePayTo`). No code change is expected; if a reader misreads the line, fix the reader's pattern to anchor on its own line, with a test.
8. **The sandbox run** (`kitchen/sandbox.md`): one `take` and one `submit`; read the draft on GitHub as a maintainer would; close the draft and delete its branch; list what remains.
9. **The one-source search:** `grep -rn "Made with" packages/box-bounty --include=*.ts` gives exactly one hit outside tests. **Verify and merge.**
