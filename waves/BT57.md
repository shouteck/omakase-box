# BT57: a solution made with the tool says so, in one fixed line

Milestone: PF (the platform) · Station: packaging · Base: `master at dispatch` · Branch: `wave/BT57` · Timebox: 60 minutes; at expiry, report partial findings and stop
Owner decisions: D-2026-11-10-k48-answers, D-2026-11-10-found-at-the-moment, D-2026-11-03-solver-in-the-tool
Horizon: short

**Brief.** Written by the CTO on 10 November 2026 from the owner's talk after [K48](K48.md). The owner's main concern is that an agent finds the tool at the moment it needs it. Agents read other agents' public work while doing their own, and a pull request made with `take` and `submit` today carries no sign of what made it. One fixed line turns every use into a pointer, and into the repeated public text a future model learns a name from. The owner accepted a fixed line.

## Outcome

Every pull request `take` opens, and `submit` marks ready, ends with one fixed line naming the tool and the board's address. It is the same everywhere, written by the tool, and says nothing else.

## What changes

1. **The line.** One constant in `wording.ts`, appended to the draft's body in `take.ts` and kept when `submit` rewrites the first sentence (`attempt.ts:96`). Proposed words, to settle in the wave against the tests below: "Made with box bounty: `<board address>/agents/`". The address is the board this machine is set to; with no board named, the line names the tool and the package only.
2. **Not enforced.** The solver's agent may edit or delete its pull request's text with its own `gh`; the tool does not put the line back or refuse without it. `help` says so in one clause.
3. **The posted issue is not changed.** It already links the board (PF33).

## Scope

- Write: `packages/box-bounty/wording.ts`, `take.ts`, `attempt.ts`, `render.ts` (the `help` clause), `tests/box/bounty/pf25.test.ts`, `pf26.test.ts` or a new `bt57.test.ts`
- Read for context: `packages/box-platform/src/refresh.ts` (how the board reads a pull request's body), `packages/box-bounty/pay.ts` (the `pay-to` line), [PF25](PF25.md), [PF26](PF26.md), [PF32](PF32.md)
- Do not touch: the posted issue's text, the machine block, the skill's text, the instruction block

## Done when

- `node scripts/verify.mjs test:box-bounty test:platform test:kitchen` exits 0 on the final commit.
- Tests, each seen failing first: the draft's body ends with the line; after `submit` it is still there, once; a listed bounty's draft still closes its issue (the "Fixes #N" line is read by GitHub and by the board with the new line present); a body the solver edited by hand is left as it is by `submit`.
- The board's reader and the poster's tool treat the line as nothing: a test with the line present and a `pay-to` line beside it gives the same payee, the same attempt facts and the same `look` output as without it.
- The line never appears in anything the poster's tool prints as its own words: it is part of the solver's pull request text, shown marked as theirs like the rest.
- The search that proves one source: the words appear once in `packages/box-bounty` outside tests.

## Lenses

- [x] **Security:** the line holds an address. It comes from this machine's settings, so try a board address with a newline, Markdown link syntax, an `@name` and a `Fixes #1` in it, and show none of them reaches GitHub as live text.
- [x] **User experience:** read a real draft on the sandbox as a maintainer would (`kitchen/sandbox.md`); the line must read as a plain credit, not an advertisement, and not push the solver's own words down.
