# BT35: open bounties show their age, and a long wait is said once

Milestone: BT · Station: packaging · Base: master at dispatch · Branch: `wave/BT35` · Timebox: 90 minutes; at expiry the cook stops and reports where it is

**Brief.** Written by the CTO on 18 October 2026 from the roadmap's gap G3 (PLAN.md: "open bounties never age or prompt anyone"; stage **track**; actor: the posting agent and the owner; question: "should I keep waiting, or end this?"). Detailed for a cook without deep reasoning. The tool offers facts and never enforces: **nothing is closed, expired or changed automatically.**

## Why

A posted bounty can wait for weeks with no solution. Today `status` shows it like any other open bounty; nothing tells the agent how long it has waited, and nothing prompts a decision. K25's bounds and BT17's output rules still apply: one fact where it is needed, explanations said once.

## Outcome

Each open bounty in `status`, `box bounty` and `status --json` shows how long it has been open and how long since anything happened; and when a posted bounty has had no new solution for 14 days, the tool says so **once** for that bounty, with the two next commands, and never again for it.

## Scope

- Write: `packages/box-bounty/render.ts`, `json.ts`, `owner-text.ts` or wherever the open line is built, the `said` mechanism (BT17/BT22), `tests/box/bounty/**` (a new `bt35.test.ts`), `docs/box-v4/BOUNTY.md` (one paragraph).
- Do not touch: any stage transition; the hook's unasked line (it stays constant: K25); the instruction block.

## The design

1. **The facts.** For an open bounty: `posted` = the time of its `posted` event (or `createdAt` for a draft); `last activity` = the newest of the posted event and any attempt's collection time. Shown in the open line as `open 12 days; last solution 3 days ago` (or `no solution yet`), and in `status --json` as `openedAt`, `lastActivityAt` (ISO times; the agent computes durations). Durations in whole days, `today` under one day. The clock is the machine's; tests inject a fixed "now" (an environment variable read only in tests, documented as test-only, the way BT31-ci did).
2. **The once-said line.** When a **posted** bounty's last activity is 14 or more days old, the first `status` or `box bounty` that sees it adds one line: `<id> has had no new solution for <n> days — keep waiting, or end it: box bounty close <id> --reason "<why>"`. Record it with the BT17 `said` mechanism in the tool's state (`state.json`, BT22), keyed by bounty id, so it is said once per bounty, ever. A new solution arriving does not reset it (no nagging).
3. **Bounded.** The once-said lines count toward the overview budget: at most three in one command (the oldest first); the rest wait for later commands. `bt17.test.ts`'s budgets must hold; if a budget needs one more line, raise it by exactly one with the reason beside it.
4. **14 days** is a constant in one place with a comment citing this wave. Not an owner setting (the owner's surface stays `allow`, `deny`, `config`; a setting would need the owner's decision).

## Tests (`tests/box/bounty/bt35.test.ts`)

| # | Case | Expect |
|---|---|---|
| 1 | Draft created now | `open today; no solution yet`; no once-said line |
| 2 | Posted 13 days ago, no solution | `open 13 days; no solution yet`; no once-said line |
| 3 | Posted 14 days ago, no solution | the once-said line on the first `status`; not on the second; not on `box bounty` after |
| 4 | Posted 30 days ago, a solution 20 days ago | `open 30 days; last solution 20 days ago`; the once-said line once |
| 5 | Five such bounties | at most three once-said lines in one command; the other two on the next |
| 6 | `status --json` | `openedAt`, `lastActivityAt` present on every open bounty, ISO strings |
| 7 | Ended bounty | no age, no line |
| 8 | Nothing changed | the record bytes identical before and after every case (no automatic action) |
