Milestone: K · Station: evidence · Base: `831c549` · Branch: `wave/K4` · Timebox: 4 hours

## Outcome

`node scripts/kitchen-stats.mjs` prints one page of honest numbers from `.kitchen/runs` and Git, so the K5/K6/K7 speed waves measure instead of guess — and `scripts/verify.mjs` prints a plain `STALL` line when a branch keeps producing non-PASS runs, so a stuck agent parks instead of grinding. Both only read; nothing else to maintain.

## Done when

- `node scripts/verify.mjs test:kitchen` exits 0 on the final commit (new suite, wired the same way as `test:box-package`).
- `node scripts/kitchen-stats.mjs` prints: verify minutes per step (check, build, each suite), runs and failed runs per wave branch, wave duration (first commit to merge) where wave files/branches allow, and the three largest costs — computed from `.kitchen/runs` + Git only.
- On this host's `.kitchen/runs` (79 dirs spanning the 5 Oct night run) the page reproduces the known figures to within ~10%: about 120 verify minutes total on the night run, check about 45.
- The page also checks the kitchen's own limits and fails loudly (non-zero exit, named limit) when one is broken: `AGENTS.md` + `docs/box-v4/KITCHEN.md` over 20 KB combined, `kitchen/INBOX.md` over ten lines, `STATUS.md` over 60 lines. Today all three pass — prove a fabricated violation trips each.
- `verify.mjs` counts consecutive non-PASS runs and elapsed time on the current branch from its own `.kitchen/runs` history and prints a `STALL` line telling the agent to park the wave past a threshold (defaults: 6 consecutive non-PASS committed runs OR 90 minutes; both are flags). STALL never changes the verdict text or the exit code — a PASS stays exit 0, FAIL/UNCOMMITTED stay as today.
- A test feeding verify a fabricated run history sees STALL appear at the threshold and not before — both sides of each threshold.
- PASS, FAIL and UNCOMMITTED verdicts and exit codes are bit-for-bit unchanged: prove by running `node scripts/verify.mjs <one existing suite>` before/after on the same commit and comparing summary lines.

## Notes for the worker

- `.kitchen/runs/<timestamp>-<sha>/summary.json` is the schema of record — read a few to learn it before designing. Logs vary in shape across the night (K2-era runs vs D2-era); treat malformed/missing runs as data (count them, label them), never as zero.
- Wave duration: wave files record commit and merge SHAs; `git log` gives first-commit-to-merge per `wave/*` branch. A wave whose record is incomplete shows "missing", not a guess.
- The stall counter reads run history for the CURRENT branch/commit — decide the keying (branch name, commit, or wave) and document it; a dirty tree run must not count as a committed PASS.
- `scripts/verify.mjs` is the acceptance command — the smallest possible diff that adds the counter. No behaviour change except the STALL line printed after the summary.
- `test:kitchen` runs fast unit tests only (fabricated run dirs under temp); it must not spawn verify inside verify.
