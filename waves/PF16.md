## Why

Installing takes six lines today: clone, install dependencies, build, link, run. That is normal for a tool built from source and not for a released one: Beads, Bun, Stripe's and Vercel's CLIs take one line, because they ship something built. It also takes minutes, and every line can fail.

`packages/box-cli/pack.mjs` (BT12) already builds one self-contained package that declares `box`. Nothing ships it.

## Outcome

One line installs the tool, in seconds, by either route, and every later word stays true.

| Route | The line | Who acts |
|---|---|---|
| **A. A GitHub release** | `npm install -g <the release's package address>` | The CTO, on this repository, under this wave's "go" |
| **B. npm** | `npm install -g <the name>` | The CTO prepares; the owner chooses the name and publishes |

The site and the tool name the shortest line that really works. Route A ships in this wave; route B replaces it the moment the owner confirms the publish.

## Traps

- **What ships is the never-ship boundary.** The package holds one bundled file and the licence files, as `bt12-package` pins. Rebuild from the tagged commit, and check the bytes, not the source: a build on a dirty tree must refuse.
- **`latest` moves.** A printed address must not break when a new release lands, and an install must not pick up a release that failed its checks. Tag only a commit whose verify and off-machine run passed.
- **The line must not need the clone.** `box` from a package has no clone beside it: anything reading a path relative to the repository fails only here. Run the whole first journey from the package.
- **The agent's first run:** with a one-line install, a person running it in a terminal still has to tell the agent. Keep that line in the setup text.
- **Node's floor:** `npm install -g` on an older Node must end in the tool's named refusal, not a stack.
- **Permissions:** a global install can fail on a machine without rights to npm's folder. Name what is printed and the fallback; do not hide it.
- **Nothing in a committed block names a machine's path.**
- Route B's name is not claimed, reserved or published by the kitchen, not even to hold it.

## Plan

Agreed with the owner in plan mode, 2 November 2026. Feature playbook; `architect` skipped: `pack.mjs` and `bt12-install` already exist, and the release is one job around them.

1. **The line:** `npm install -g https://github.com/shouteck/omakase-box/releases/latest/download/box-bounty.tgz`, then `box bounty`. A fixed asset name, so the address never changes.
2. **`.github/workflows/release.yml`:** a `v*` tag builds on GitHub's machine, checks the tag against the package version, runs the packaging tests, and only then creates the release, so `latest` cannot move to a package that failed.
3. **Tag after verify, before merging:** the workflow runs from the tagged commit, so the real line and the fresh agent test the real release. A fault found means a fix and `v0.1.1`.
4. **The clone stays,** folded under "Build it from source". Its `box` fallback in the setup text prints only when run from a clone.
5. **Order:** kickoff, prove the package, the job, the words, screenshots and verify, the release, the fresh owner's agent, npm ready, the owner's approval, merge. Deploy on its own word, last.

6. **Owner, after the first fresh agent was blocked (D-2026-11-02-one-command-setup):** that agent's auto mode refused the install as code from outside, and "tell your agent to run box bounty" was one step too many. Firecrawl, Context7 and Stripe's CLI use one command that installs and registers the tool with agents. So: `box setup`, a new command by the owner's word, puts `box` on the machine and a skill in `~/.claude/skills` and `~/.agents/skills` (Codex, Cursor and Gemini CLI read the second, read on their docs that day). It writes only its own folder, leaves a folder not ours alone, says what it wrote, and `--remove` undoes it. Instructions in a project leave the setup text: they remain for other agents. The page's one line is the `npx` form with the release's address, then `npx -y omakase-box setup` once the owner publishes. Released as `v0.1.1`. This takes the simple form of PF6's skill; PF6 keeps the listings.

**Proved first:** the package installs from its file in about 2 seconds into a throwaway prefix, and `box bounty`, `allow` and `instructions` run from it.
