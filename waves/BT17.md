## Why

The latest recorded demo (`kitchen/demo/bt11b-real-transcript.txt`, recorded before BT13 and BT14, which shortened `status` and `config`) shows each command printing several times what the reader needs. The patterns:

- **The same principle restated on every call.** `allow` says "Merging is not gated" and that the settings "are not a lock against an agent that deliberately changes them"; `look` opens with two sentences on the solver's text, nothing run and nothing checked out; `status` repeats "a promise in the owner's name, paid by hand" every time.
- **Internal detail nobody acts on:** snapshot commit, tree and base hashes; "written <timestamp> to <settings path>"; "GitHub format block: matches-record (last issue-body observation …; local record governs)"; the record's path.
- **Several next steps saying the same thing:** a `next:` line, a `collect:` line, and every solution line repeating both commands.
- **A header on every `status`:** permission, reward, limit and what is left, before the bounty itself.
- **Defensive asides:** "(record only — never shipped)", "(--preview shows what …)", "Nothing has been posted; nothing has left this machine" twice in one output.

The convention is the rule of silence: `git commit` prints one line, `gh pr create` prints the link, detail sits behind `--verbose`, and what matters is said when it is new. Every line an agent reads costs it attention; a line repeated on every call teaches it to skip lines.

## Outcome

Each command's normal output is short enough to read at a glance and complete enough to act on: what happened, what needs attention now, and the one next command. Detail is one option away. Explanations are given once, when they are new.

## Done when

- `node scripts/verify.mjs test:box-bounty test:box-package` exits 0 on the final commit; the suites reach no network. The K14 start budgets are re-measured and stated.

**First, measured.** The cook runs the whole journey once, as K18 and K20 did, and records for every command its lines and characters of normal output, before any change. The Result carries the table.

**The contract for a command's normal output**

1. **One line saying what happened,** naming the bounty and, for a command that changes something, the repository it acted on.
2. **Only the facts that need attention now:** a waiting state, a warning, a hit, money owed, something the owner must hear. Nothing that is true every time.
3. **One `next:` line with one command.** Where there are two real choices, both on that one line. No second line saying the same.

**Where everything else goes**

- **Hashes, timestamps, file paths, format-block state, cached observations:** behind `--full`, which `status` already has, and the same option on every command that has such detail. The cook says whether `--verbose` is the better name, after the convention K20 found.
- **Standing explanations** (merging is or is not asked about, the settings are not a lock, nothing a solver wrote was run, a reward is a promise paid by hand): said **once**, the first time they apply in a repository, recorded so they are not repeated, and always available in `help` and `describe`. Where a fact matters every time (a waiting merge in ask mode, money owed), it stays.
- **Duplicate next steps and asides:** removed.
- **What a program would parse:** `--json`, if K20 recommends it and the owner chose it; otherwise not in this wave.

**What stays exactly as it is**

- The labels that mark a stranger's text as not the tool's own.
- The owner's block BT13 added, unless the relay check below shows a shorter one still carries every fact.
- A refusal's name and its one-line reason.

**A guard so it stays short.** A test runs the standard journey and holds each command's normal output to a stated budget in lines and characters, the way K14's test holds Git starts. Raising a budget is a reviewed change with a reason.

**Nothing an agent or owner needs is lost.** After the change:

- One fresh posting agent and one fresh collecting agent run the journey cold, with only the tool's output, on the sandbox. The Result gives every command they ran that the output had not named, and anything they looked for and did not find.
- The two-agent relay check from BT13, five runs per mode, still carries every fact to the stand-in owner.
- The demo transcript is re-recorded, and its before and after are compared step by step.

**Measured, after:** the same table, before and after, per command; the total an agent reads on each journey.
