# BT93: the hook tells the agent only facts and pointers, in its own sessions only, and never keeps it working

Milestone: BT (the bounty tool) · Station: packaging · Base: `master at dispatch` · Branch: `wave/BT93` · Timebox: 180 minutes (a hosted run takes about 25); at expiry, report partial findings and stop
Owner decisions: none
Horizon: short to medium. Bug fix playbook; principles: boundary-discipline, prove-it-works.

**Brief.** Written by the CTO on 24 November 2026 from the walkthrough of the session hook (`packages/box-bounty/hook.ts`). The owner: the hook matters, because agents otherwise do not know their solutions arrived, but it must not disturb them; learn from the references ("I agree with your 4 recommendations").

**Why.** The hook is off until the owner switches it on (`omakase-box hook on --host claude|devin --confirm`), behind an honest disclosure. Once on, it runs at:
- **session start,** with the open-bounty state;
- **each prompt,** when a solution has arrived since;
- **the agent's stop,** with the same, plus conflicts and the pay message.

It is bounded: GitHub at most once every 5 minutes, 8 seconds a call, 20 seconds a run. "Told once" is kept in a small state file.

**How established hosts and protocols notify an agent of something that happened elsewhere:**
- **Claude Code hooks:** `SessionStart` and `UserPromptSubmit` add context through `hookSpecificOutput.additionalContext` without blocking. `Stop` accepts the same field "for non-error feedback that continues the conversation", and can block. ([Hooks reference](https://code.claude.com/docs/en/hooks))
- **Cursor:** user-level hooks live in `~/.cursor/hooks.json` and project hooks in `.cursor/hooks.json`, which applies to everyone in the project. Its `stop` can return a follow-up message that keeps the agent going. ([Cursor hooks](https://cursor.com/docs/agent/hooks))
- **MCP resource subscriptions:** a change notification carries only *which* resource changed (`notifications/resources/updated` with a URI). The client reads the contents when it chooses. ([MCP resources](https://modelcontextprotocol.io/specification/latest/server/resources))
- **Codex:** its `notify` command runs on a finished turn and goes outward, to the person (desktop alerts), not into the agent's context. ([Codex hooks](https://developers.openai.com/codex/hooks))

The lessons: notify with **pointers, not contents**; inject at **natural breakpoints without forcing another turn**; and install in the **person's own scope**.

Measured against them, five things are wrong:
1. **The stop slot puts a stranger's text into the agent's context, unasked.** The disclosure promises "never shows a stranger's text (no titles, account names, branch names or issue bodies)". But the `finish` slot prints `payNotice` (`packages/box-bounty/pay.ts`), which carries the solver's account name and the payment link read from the pull request the solver wrote. Injected context is where a prompt injection would sit.
2. **The stop slot may keep the agent working.** On Claude Code, `additionalContext` on `Stop` "continues the conversation"; on Cursor, a `stop` follow-up does the same. Then a solution arriving makes a stopping agent take another turn, against the disclosure's "never blocks or waits on anything", and it costs a turn the owner did not ask for.
3. **It installs into the shared settings file.** For Claude Code, `hook on` writes `.claude/settings.json`, which is normally committed, so every collaborator's sessions run `omakase-box hook` though only the owner saw the disclosure. Without the tool, they get an error every session; with it, it runs with their GitHub sign-in. Claude Code's personal file is `.claude/settings.local.json`, which is not committed.
4. **Its state files sit outside the ignored folder.** `.box/hook-told.json` and `.box/hook-on.json` live beside `.box/local/` (which ignores itself), so they appear as untracked files: a `git add -A` commits them, and `post` treats untracked files as something to ask about.
5. **The disclosure leaves out a write.** At session start it refreshes shared memory (`refreshSharedMemory`), which can push this machine's owed chain events to the remote. The disclosure says only that it "contacts GitHub".

## Outcome

1. **Only facts the tool made, and pointers.** The `finish` slot's pay line becomes "a bounty ended with a merged solution and a reward of $X: the pay message is in omakase-box status `<id>`". No account name, no link, no text from a pull request.
   - A test checks every slot's output against a list of allowed shapes (ids, stages, counts, times, amounts, the tool's own commands).
   - The disclosure's "never shows a stranger's text" becomes true.
2. **The stop slot never forces another turn.**
   - What happened while the agent worked is told at the next prompt (`pause`) or the next session start. The `finish` slot writes its told marks but injects nothing that the host turns into a continuation.
   - The wave first reads each implemented host's current docs and records the verdict per host, with the source and date. Where a host's `Stop` context does not continue the conversation, it may stay.
   - The disclosure says which.
3. **Personal scope by default.**
   - For Claude Code, `hook on` writes `.claude/settings.local.json`.
   - For Devin, the personal equivalent its installed docs name. If there is none, the disclosure says plainly that the file is shared, and names who it reaches.
   - `hook on --shared` keeps writing the shared file, on the owner's explicit choice, and the disclosure then says every collaborator's sessions will run it.
   - `hook off` removes the entries from wherever `hook on` recorded writing them, including old installs in the shared file.
4. **The state lives beside the shared store:** BT96 moves the bounty store into Git's common folder first; `hook-told.json` and `hook-on.json` move beside that shared `box.db`, not under `.box/local/`. Existing files are moved once on the next run, with their content kept, so nothing is told twice and `hook off` still finds what it installed.
5. **The disclosure states every write:** at session start it may push this machine's pending shared-memory events to the project's remote, with the same once-a-minute throttle as `status`.

## Traps

- **Claude Code treats `.claude/` as a protected path:** writes there prompt the human. That is right for `hook on`, which the owner runs. Say so in the disclosure.
- **Moving the state must not lose a told mark,** or an agent is told twice. Copy, then remove the old file.
- **More hosts** (Cursor, Codex, Gemini CLI have hook systems) are not added here. A backlog line names them, with BT91's approach: a table checked against each vendor's docs.
