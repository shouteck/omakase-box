## Outcome

A GitHub-marked squash/rebase merge can close and earn payment without the original head surviving. Evidence is GitHub's merged state and merge-result commit, with validated bounty base and landing reachability, never patch likeness. A hand squash GitHub never marked merged stays unrecognised; status states that fact.

## Steps, in order

1. Read BT67's Result. Write the table cases red first; keep its attribution gate on every new recognition path.
2. On the board retain the normal original-head check. When a merged PR's head comparison is `diverged`, read its GitHub merge facts; require base = `box-bounty/<id>` in the right repository and a valid `merge_commit_sha` reachable from default. 3. In the CLI, add rewritten-head recognition from GitHub's merged state plus merge-result commit on the creating branch. Validate repository/base and pinned head; do not infer a rewritten landing from original-head ancestry. Preserve ordinary apply/merge/fast-forward paths and BT67's no-payee cases.
4. State the unrecognised hand-squash case and unknown-read case in status, with a next step. Follow `gh`'s merge facts; no commit-message claims or patch-id fallback. Update contracts and surface (`node scripts/surface.mjs --write`) if changed.

Record PRs, head/result SHAs, compares, CLI close and local board payment facts. Use the one sandbox account: different-payee charges stay stand-in tests. No real payment, live board listing or deploy; clean up owned resources.
