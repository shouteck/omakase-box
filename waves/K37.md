# K37: honest load context and per-wave verification costs (K33 P5, P10)

Milestone: K · Station: evidence · Base: master after K36 · Branch: `wave/K37` · Timebox: 120 minutes; report at expiry.

## Outcome

Verification records cheap available host-load context, stats flag comparable duration outliers as advisory load suspects without changing FAIL, and a reproducible per-wave total can be included at close. Complete P5/P10 without treating duration as CPU/agent cost or guessing the cause of a timeout.

## Scope

- Write: `scripts/verify.mjs`, `scripts/kitchen-stats.mjs`, a small shared helper under `scripts/` if needed, `tests/kitchen/`, `templates/wave.md`, the close/verification reporting sections of `docs/box-v4/KITCHEN.md` and `kitchen/roles/cto.md`, `scripts/suite.mjs`, `.github/workflows/verify.yml` for dependency coverage, `waves/K37.md` Result.
- Do not touch product, dependencies, global settings, process controls, existing run files, accepted verdict/reuse/stall/budget semantics, or historical K33 figures. No automatic retries, verdict reclassification or skip.

## Done When

- `node scripts/verify.mjs test:kitchen` exits 0 on a clean committed candidate; independent pass runs acceptance and recomputes fixture totals/outliers.
- New runs record platform/capacity and a cheap meaningful available load observation with time/units. Unsupported metrics (notably Node `os.loadavg()` on Windows) are explicitly unavailable, not reported as observed zero load. Do not sample environment, usernames, command lines or machine identifiers. Dirty refusals and interrupted start evidence remain truthful and readable.
- Stats preserve old/new/missing/malformed load fields safely. Advisory labels never imply the load caused a failure, change exit/verdict/reuse, or let an agent ignore a real failure. State that a rerun does not erase the first failed attempt.
- Compare duration only to a documented comparable cohort (same effective executed plan/profile and platform where known; exclude reused/incomplete/dirty observations and invalid durations). Use at least three earlier eligible observations, show n/median/range and source run IDs, flag strictly greater than 2x the median. No cohort means comparison unavailable, not zero or green. A candidate does not inflate its own baseline.
- A read-only machine-readable per-wave stats query supplies run count, summed known invocation wall-seconds, missing/incomplete count and source run IDs. Include failed/dirty/incomplete attempts, don't count a reused invocation as executed step time, and distinguish run wall-seconds from executed step-seconds if both shown. Define attribution (commits/branch bounds) so correction/sibling/shared commits don't silently double-count.
- Close template/procedure records `verify: N runs, total Ns` with missing counts, provenance and scope; local-only histories stay local and a fresh clone reports missing rather than fabricated zero. Use this wave's close as the first real example. Keep normal stats Git-process count bounded.
- Fixture regressions cover threshold boundaries, minimum cohort, reused/profile/platform mismatches, old/unsupported/bad load data, timeout and non-timeout failures staying failures, missing durations, ambiguous/unattributed commits, and exact totals independently recomputed by the pass. No speedup or causal-load claims.
- Update brief references/checks as required by K36's new convention; protect newly read rule/template paths in suite reach and hosted CI. Combined rulebook below 20,480 bytes.

## Review Lenses

- [x] Security: load capture is non-secret and advisory; no changed authority, automatic retries or acceptance bypass.
- [x] User experience: duration outlier vs observed load and missing history are distinct; close line is understandable and sourced.
- [x] Measurement fairness: independent arithmetic; comparable prior cohort; every attempt represented; missing is not zero; no CPU/agent-cost or cause inference.
