# K63: does a Dev Drive speed the Windows bounty run? (H6 of K51d)

Milestone: K (kitchen) · Station: evidence · Branch: `wave/K63` · Timebox: 60 minutes
Owner decisions: on 12 November 2026 the owner left the order and handling of the K51d hypotheses to the CTO.

An experiment, not a change: four paired jobs on one commit (`31e1381`, master), windows-2025, started together: the bounty suite (`verify --full test:box-bounty`) with the temporary folder on C: (two jobs) and on a ReFS Dev Drive made the way astral-sh/uv does it in its own CI (trusted, antivirus filtering off, remounted; two jobs). Hosted run 43212553612 on a throwaway branch, since deleted. The workflow file was never on master.

## Result

Closed on 12 November 2026. **No speed-up, and a behaviour change.**

| temporary folder | bounty suite, seconds | result |
|---|---|---|
| C: (1) | 1417 | pass |
| C: (2) | 1105 | pass |
| Dev Drive (1) | 1679 | one test failed: `github.test.ts` "isolates co-located runnable gh, git and node" (it copies or links `node.exe` and `git.exe` into a scratch folder) |
| Dev Drive (2) | 1336 | pass, but 9 skipped instead of 4 (`bt64`'s four case-spelling tests skipped, among others) |

- **The two jobs that differ only by chance (C: 1 and 2) differ by 28%.** A paired result of two each cannot show a smaller effect than that; what it does show is that the Dev Drive is not a large win, and its two runs were slower than the two on C:.
- **It is not drop-in:** ReFS changes what some tests can do (a hard link or copy of a running executable, case-spelling behaviour), so it would hide tests behind new skips on Windows or need the tests changed. For no measured gain, that is not worth doing.
- **Dropped.** The temporary folder stays where it is. The D: drive some older posts recommend is not on this image (the experiment's first step listed the drives; D: was absent, `TEMP` was `C:\Users\RUNNER~1\AppData\Local\Temp`).
- **The runner variance itself is a finding:** the same bounty suite on the same image took 879 to 1679 s over seven hosted runs. Any claim of a speed-up under about 30% needs more than a handful of runs.
