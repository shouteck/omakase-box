## Recorder prerequisite — future work, not implemented

The actual Matplotlib pipeline gave native stderr 4,316 bytes versus recorder 22,925: 18,609 extra bytes, and changed truncation. Ordering-only comparisons need an instrument that does not fully buffer native upstream commands before head sees them. Restoring native execution is necessary, but a naive line-streaming sorter cannot globally reorder arbitrary streams while preserving SIGPIPE. Design the display transform after the entire shell pipeline finishes, without putting a buffering observer in the upstream pipeline; unsupported or non-separable results fall back byte-for-byte. This is a constraint for engineering, not a claim it is already solved.

Before any model generation, compare native command and instrument in identical isolated filesystem states: raw stdout and stderr bytes, exit/pipeline statuses, surviving processes, output cap, locale, cwd and side effects. Control display must be native. Box may only reorder intact recognized result blocks, preserve every native match before the common cap, add no bytes and preserve native errors. Context/multiline/ambiguous/generated/stale cases fall back. Preserve all commands, receipts and failing counterexamples.

Suite must include the actual recorded Matplotlib combined grep/head/git-log command, but also newly generated adversarial commands: head 0/1/30, early downstream close, pipefail, grep no-match/binary/error output, stderr redirection/merge, &&/;/subshells, absolute executable paths, command substitutions, Unicode/locale, context and multiline matches, output larger than cap and producer delay. Generate fresh deterministic seeds after engineering is frozen; separate tuning cases from held-out cases. Assert both control/native equivalence and Box conservation after the pipeline, plus displayed priority identity. Repeat on every task environment and every new command family. Unsupported commands remain ordinary native commands. Any changed stderr, exit, side effect, or unexplained truncation stops before agents. Passing old replay alone is insufficient; passing a finite suite is not universal shell equivalence.

## Room, shorter tasks and what could fool us

Run a no-agent census before any future inference: pre-first-open searches; fix already visibly present; order changed; fix rank moved; promoted code unrelated to fix; truncation removes priority; state unknowable. Include no-room tasks, rather than select only successes. If almost all eligible contexts already show the fix first, the finding is ceiling in this corpus, not lack of utility. Existing gate-2 2–4 step locating medians explain why complete repairs are inefficient tests of this mechanism.

Unfamiliar private code, post-cutoff issues, and a weaker agent are distinct ways to create room. This repository is not automatically unseen: it is in this agent's context. Post-cutoff fixes do not prove the model has never seen the repository or issue. A genuinely held-out set needs independent task construction and sealing before any tuning, no source/gold exposure to experiment agent, frozen dependency/test/trace provenance and an unfamiliarity claim stated with its limits. Synthetic shorter navigation tasks buy cheaper contexts but narrow the answer; fabricated ambiguity can make ordering win by construction. Compare a no-runtime ranking baseline in any later claim that runtime evidence specifically adds value. No alternative model access, price or cheaper token count has been verified; changing model must be separately frozen and calibrated.

Cheapest confident wrong answer: call replayed gold-function opens “repair savings”, or select only searches whose fix was promoted, or treat repeated moments as fresh task evidence. Primary scope, denominators and conditional inference prevent those claims. Native instrumentation faults and missing private reasoning remain first-class validity gates, not caveats added after a favourable run.
