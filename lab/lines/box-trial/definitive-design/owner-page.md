# A cheaper answer about the Box — design only

9 October 2026. No repair agent, fork probe or instrument fix ran.

**Recommendation:** compare the next navigation decision from the same reconstructed search context, rather than more complete repairs. First prove native search behaviour without an agent and count usable saved situations. This can settle a navigation margin on those situations; it cannot prove repair savings or that the Box never hurts. If even its projected token allowance is too much, keep the free opportunity count and leave agent benefit undecided.

**1. Replayed next decision — recommended.** Show the same recorded conversation twice, changing only search order, and record whether the next command opens a function changed by the reference fix. Repeat both versions on sixteen situations to measure instability. Sample saved situations independently, with equal task weight; repeated decisions do not become new repositories. Stop at 64, 128 or 256 pairs. Projected costs are **0.8–4.6m, 1.4–8.4m and 2.7–15.8m reported tokens**, including repeats. If the two versions never differ, 128 pairs can rule out a change of **five percentage points**. Simulated stable decisions also often reach that conclusion; noisy decisions may remain undecided. A **10-point** improvement is reliably detectable in a low-noise scenario, around **20 points** in a noisy scenario; the conservative guarantee allowing any noise is **33 points** at 256 pairs. Missing access: history import needs a separately approved no-inference check. Replayed history lacks the original private reasoning state, so this answers a replay question, not resumed repair performance.

**2. Three-command continuations.** Allow recovery after the first decision. Measure whether the correct function is opened within three commands, commands and text before that open, and other promoted opens that may be detours. Same sample size and statistical rules; **8.2–40.3m tokens**, plus any new shared prefixes needed for real checkpoints. It can rule out five points when outcomes are stable, with a **33-point** worst-case detectable effect; smaller-effect power depends on its measured noise. Exact search-time forks are unestablished: our old live threads were ephemeral, and documented forks interrupt unfinished turns. This needs proven checkpoint support or an explicitly labelled reconstruction. It costs more and still says nothing directly about repair quality.

**3. Complete short repairs, repeated — reject for this budget.** Thirty-two task pairs plus eight extra repeat pairs measure successful repairs and capped token use, costing roughly **4.2–16.1m tokens** at recorded run lengths. Recorded variation gives conditional estimates of **10–31% detectable token change**, but there is too little repeat data to promise them. The conservative repair-success guarantee only detects about **80 points**; useful small quality equivalence is beyond this size. Planning for a 5% token change needs about **126–999 pairs**, before calibration extras. Unfamiliar short tasks or a weaker model could create room, but may change costs and the question; cheaper model access and savings are unverified.

For option 1 the owner can say: **helps** — “On these replayed searches, ordering made the next command more likely to open a fix function”; **equivalent** — “Any change on this navigation measure is smaller than five percentage points”; **harms** — “Ordering made that open less likely”; **undecided** — “The interval still permits a meaningful change either way.” The stopping rules limit false interval claims to 5% across all looks, assuming valid recording, labels and independent draws. A free no-room finding means “These saved searches offer little locating to save,” never “the Box cannot help elsewhere.”
