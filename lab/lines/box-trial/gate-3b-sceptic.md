## Strongest counterarguments

**Native order is not the original published order.** Fresh Gemini step 20 reproduces the pinned-image direct query `grep -rn "rational.*real" sympy/`: historical get_known_facts_cnf first, then third after two promoted ask.py matches. HEAD is the recorded pristine SymPy base, diff is empty, and every located source hash equals the frozen base source. However, the original published observation lists ask.py first, followed by ask_generated.py. Its same 28 textual matches have first historical target get_known_facts at rank 3; projecting the recorded priorities onto that original stream gives **3 -> 3**, not a regression. The replay's **1 -> 3** is a recreated pinned-native comparator result dependent on native traversal order, not a regression in the published original stream. GPT steps 25/26 reproduce **58 -> 59** in their first native grep stages. Downstream stdin stages are not an independent complete ordinary-pipeline baseline.

**Historical Gold is not necessary repair code.** The direct pinned-native target is generated assumptions CNF outside the failing-test trace. The historical patch changes generated helpers, runtime assumptions and documentation; changing one is not evidence that every successful alternative must edit it. Module-level assumption-rule edits are omitted from the function metric. The unchanged first original-stream target also illustrates how filesystem ordering can change which historical helper is counted. None of this turns the saved metric into a repair outcome. The result memo already limits that interpretation; retain the limitation prominently.

**Qualified names are ambiguous identities.** A cheap actual network-off native attack profiles a property getter call only (code first line 2), then searches its authored source. The wrapper marks the uncalled same-name setter's lines 9/10 too, because both resolve to `C.x`. Across the frozen trace scopes I found 48 qualified names with multiple source definitions, in seven tasks. These include property accessors, conditional alternatives and nested repeated definitions. This is an actual false marker, not just a hypothetical assertion failure. It weakens the instruction that every marked result is inside code the failing test ran. I did not retune or repair the instrument. The direct SymPy ask.py promotions and generated target are unique names, so this attack does not erase its recorded native demotion or authorize a live pair. Ambiguity can also affect Gold remapping, so the 5/11 count describes this instrument's identity rule.

**State reconstruction is bounded.** Recognized source mutations and Git state changes are replayed; failed/missing actions are retained as uncertainty. The replay skips expensive build/install/test actions, tracks prior skips, and extracts search portions with unknown flags. Later in-repository invocations after an environment skip can still be eligible; their receipts do not establish a complete historical filesystem or environment reconstruction. The mutation detector is a recognizer, not a general shell-effects proof. I verified the direct pristine source case separately because its state does not depend on a repaired trajectory. Six Sphinx searches cannot run without /tmp/prologbug and supply no positive evidence.

**Pipeline preservation has a narrower meaning.** Reordered, unmarked output enters downstream tools. Therefore a stdin grep's recorded native stream can already be Box-conditioned. Per-invocation conservation and rank do not show equivalence to the complete ordinary action, especially with head/tail, or what an agent would see/use. The compatibility tests exercise actual native behavior and preserve context groups; they do not justify universal compatibility for every shell command or format. No repair cost/solve claim follows.
