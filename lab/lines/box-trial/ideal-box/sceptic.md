Section 6.2 confirms an evaluated SBFL setting, adding top-five hints and test validation. No new performance claim should be imported without the different test access/validation setting. [AutoCodeRover §§4.4, 6.2](https://arxiv.org/html/2404.05427).

Bounded independent searches were `coding agent runtime coverage reorder search grep executed functions` and `agent search runtime coverage ranking transparent navigation`. Results included Entire, static retrieval papers and unrelated ranking pages; no inspected result established Kind 1. I did not turn every returned lead into a new literature survey. Failure to find a counterexample here cannot support “nobody does this.” Wallaby, Coco, coverctl and Supercov remain queried coverage/report interfaces in their inspected contracts; the general prevalence or novelty question stays open.

**Line overlap cannot universally identify function calls.** Coverage.py's FAQ explicitly distinguishes running `def` lines from calling functions. Importing a module can cover a function-definition line without entering its body; calling an outer function can execute a nested definition without calling the nested function. A parser interval intersecting such a hit gives a false execution mark. This is a source-backed logical counterexample, not a newly executed coverage experiment. [Coverage.py FAQ](https://coverage.readthedocs.io/en/latest/faq.html).

Conversely, Node's current `test:coverage` contract exposes a per-function `count` defined as times called. Thus “coverage can never establish exact function entry” would also be too strong; checked entry/count semantics can support it within the collector's coverage boundary. Name filtering still executes hooks and does not restrict test files; source mapping, exclusions and process attribution matter. [Node test runner](https://nodejs.org/api/test.html). Coverage.py retains static/dynamic contexts, with runner/pre-test work potentially in an empty context; filtering a test label can omit setup unless accounted for. [Contexts](https://coverage.readthedocs.io/en/latest/contexts.html). Go profiles expose ranges/counters and merge runs; anchored `-run` still executes relevant parents. Nothing checked recovers ordered call parentage from aggregate coverage. [Go coverage](https://go.dev/doc/build-cover), [Go command](https://pkg.go.dev/cmd/go). These attacks reinforce the survey's region-versus-entry qualification and unknown fallback.

**Availability is not a monotonic outcome guarantee.** Retaining all matches does not prevent a finite-budget agent from spending attention on irrelevant executed code placed first. Added marks consume text, and ambiguous mappings can mislead. The survey correctly leaves never-worse unproven; the runtime-agent papers cannot validate this different delivery. No Box outcome experiment was performed here.
