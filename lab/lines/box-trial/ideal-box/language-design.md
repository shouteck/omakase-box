# Coverage can be raw material, with qualified promises

The core can know commands, files, revisions and exits. Language helpers know runners, coverage formats, source mappings and syntax. The evidence below checks three ecosystems, not “every language.” No coverage tool was installed or run in this survey.

| Ecosystem / official documentation | Report and one-test isolation | What is lost or needs a helper |
|---|---|---|
| Python [contexts](https://coverage.readthedocs.io/en/latest/contexts.html), [run](https://coverage.readthedocs.io/en/latest/commands/cmd_run.html), [JSON](https://coverage.readthedocs.io/en/latest/commands/cmd_json.html), [subprocess](https://coverage.readthedocs.io/en/latest/subprocess.html) | Executed lines/branches, optional dynamic test contexts; JSON can expose contexts. Select one test with its runner, or filter recorded test contexts. Include fixture/setup execution honestly. | Line overlap is not exact function-entry proof: definition lines and nested regions can mislead. No call order/parentage. Subprocess patch/concurrency, parallel data and clean saving need configuration; combining data loses order and can lose attribution unless labels retained. |
| JavaScript/TS [Node test runner](https://nodejs.org/api/test.html) | Experimental test coverage; NODE_V8_COVERAGE raw V8 data and LCOV reporter. Select a file and unique full test name via test-name-pattern, including ancestors for nested tests. Pattern does not restrict files; test-file setup still runs. | Function/range counts can provide stronger evidence than line intersection, but formats vary. TS needs trustworthy generated→source mapping. No ordered call route. Child execution must produce attributable coverage; aggregate reports alone do not establish it. Default test/node_modules exclusions limit “did not run” claims. |
| Go [coverage](https://go.dev/doc/build-cover), [go command](https://pkg.go.dev/cmd/go) | Unit coverprofile has file ranges, statement counts, hit counts; integration builds use covdata. Select a test with anchored -run and -count=1; parent tests/setup can still execute. Dependency packages need coverpkg. | Blocks mapped to functions give region coverage, not universal exact entry events (e.g. empty functions). No call order/parentage. Child binaries need instrumentation and output collection. Merge retains hits, not sequence; run provenance must be kept separately. |

[Tree-sitter](https://tree-sitter.github.io/tree-sitter/) supplies a common parsing library; [queries](https://tree-sitter.github.io/tree-sitter/using-parsers/queries/1-syntax.html) are grammar/node-specific. A library spanning languages still needs grammars and correct function-boundary queries. Parsing finds syntax, not execution.

**Design inference:** use normalized run records containing command/test anchor, source revision/hash, file/range hits, exit/status, completeness, evidence kind and available process/context labels. Treat file plus starting line (and revision) as function identity; do not reuse a qualified name alone. Ambiguous mappings, stale source and incomplete coverage produce **unknown**, not execution marks. Source-map or parser mismatch must fall back to ordinary unmarked search.

Coverage plus parsing can underpin Q1, Q2 and Q4 **as covered-region evidence**. To promise the settled Box's exact set of functions called, require entry/count evidence whose semantics have been checked, or the existing function tracer. In particular, lack of a hit cannot mean “did not run” when instrumentation is incomplete. Q3 requires ordered entry/return/exception evidence and a per-language collector; a union of coverage points cannot recover a path.

Keep two interfaces distinct: **Box** = ordinary complete search with relevant results first and trustworthy minimal marks, preferably no added instruction; **facts on request** = Q2/Q3 and explicit Q4 queries, separate owner decision. Coverage reports and model-written diagnoses should not silently become extra context.

An open repository guarantees availability, not a never-worse repair outcome: ranking, false marks and added text can affect attention and cost. That remains a hypothesis to measure. The next prototype must retain every ordinary match, fix identity, verify answers against traces and count footprint; this page is a design qualification, not a completed prototype or measured three-language implementation.
