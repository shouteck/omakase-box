# Less-familiar code: feasible records, unmatched instrument

Free public records exist; this session cannot report that they are unavailable. This is a feasibility survey, not a familiarity-effect estimate. No secondary trajectory contents were inspected or model run started.

**SWE-bench Pro.** [Official repository](https://github.com/scaleapi/SWE-bench_Pro-os) distinguishes old V1 tasks and September2026 V2 revised validation. [Authors' trajectory instructions](https://github.com/scaleapi/SWE-bench_Pro-os/blob/main/traj/README.md) direct users to a public S3 bucket and say an AWS account is needed. Our unsigned listing and HEAD requests succeeded without credentials:15 model/run prefixes and a9,256,783-byte Ansible trajectory object are publicly accessible. Source receipts preserve the exact URLs and response metadata. The access statement in the README is therefore stricter than our observed anonymous access. Dated runs use250turns without a cost limit; paper runs used a$2limit. Mixing them would confound strength. Python projects include Ansible, OpenLibrary and qutebrowser; a multi-model public-record comparison is plausible. Old trajectories must be joined to V1 task/test/base definitions, not current V2 by an issue-like identifier. This needs a versioned manifest and a Pro-specific named-test capture adapter before any Box comparison; current150-task capture is SWE-bench Verified only. Private commercial cases remain outside these public observations.

**SWE-rebench.** [Authors' public trajectory card](https://huggingface.co/datasets/nebius/SWE-rebench-openhands-trajectories/blob/13fa32b010d4e0a691a48e0c5067de1f543b7ca5/README.md) describes complete Qwen3-Coder480B/A35B trajectories using OpenHands0.54, with task IDs joinable to public Docker environments, published success flags and agent-generated test validation. This supplies free records on broader code. It is a single-model dataset and its scaffold differs from our mini-agent cohort. A same-model cross-benchmark comparison would still mix scaffold, task collection, tests and familiarity. Recent collection dates and a decontamination aim do not prove that a model never saw a repository or fix. The frozen dataset tree at the card revision lists only card/config files; a live data revision and immutable task/environment join need to be resolved before selecting a secondary sample.

**Conclusion.** Familiarity is an open, technically feasible next records-only study, not a direction closed by lack of free data. This session's anticipation statistic is naming a gold file before visible output names it, with issue-supplied names separated; it cannot identify memorization. No familiar-versus-unfamiliar causal gradient is reported. The minimum next unit is a frozen ProV1 Python manifest of dated, common-scaffold models with anonymous downloadable records, followed by one named-test capture check before scaling. No live repair experiment follows automatically.
