## Title

1.20.0 fetch adapter sets cache: 'default' on every Request → TypeError: Unsupported cache mode on Cloudflare Workers

## Body

### Describe the bug

Since 1.20.0 the `fetch` adapter fills every `Request` it constructs with a fixed set of browser defaults (`DEFAULT_REQUEST_OPTIONS` in `lib/adapters/fetch.js`, introduced by #11141), including `cache: 'default'`.

Cloudflare Workers (workerd) only accept `no-store` / `no-cache` for the `cache` option and throw at `Request` construction for anything else. As a result **every** request made through the fetch adapter on Workers now fails before a single byte is sent:

```
TypeError: Unsupported cache mode: default
```

1.19.0 works, because it only passed the options it was given.

Related workerd limitation: https://github.com/cloudflare/workerd/issues/698, https://github.com/cloudflare/workerd/issues/2426.

Note: frameworks that shim `globalThis.Request` (e.g. `@opennextjs/cloudflare` strips `cache` inside its fetch handler) mask the bug there, which makes it surface only in queue consumers / cron handlers of the same Worker. That is how we hit it in production.

### To Reproduce

`worker.mjs`:

```js
import axios from 'axios'

export default {
  async fetch() {
    try {
      const res = await axios.get('https://cloudflare.com/cdn-cgi/trace', { adapter: 'fetch' })
      return new Response(`ok ${res.status}`)
    } catch (e) {
      return new Response(String(e))
    }
  },
}
```

`wrangler.jsonc`:

```jsonc
{ "name": "axios-cache-mode", "main": "worker.mjs", "compatibility_date": "2026-05-26" }
```

```
wrangler dev --local
curl http://127.0.0.1:8787/
# → TypeError: Unsupported cache mode: default
```

Same snippet with `axios@1.19.0` → `ok 200`.

### Code snippet

The relevant part of `lib/adapters/fetch.js` (1.20.0):

```js
const DEFAULT_REQUEST_OPTIONS = {
  cache: 'default',
  redirect: 'follow',
  referrer: 'about:client',
  // ...
};

if (isRequestSupported) {
  utils.forEach(DEFAULT_REQUEST_OPTIONS, (value, key) => {
    if (resolvedOptions[key] === undefined) {
      resolvedOptions[key] = value;
    }
  });
  // ...
}

request = isRequestSupported && new Request(url, resolvedOptions);
```

### Expected behavior

Options the caller did not set should not be sent to the runtime's `Request` constructor, or at least `cache` should be left undefined (the spec default is already `'default'`, so setting it explicitly buys nothing and breaks runtimes that reject it).

### Workaround

Pass an explicit mode the runtime accepts:

```js
axios.create({ adapter: 'fetch', fetchOptions: { cache: 'no-store' } })
```

### Comment 1 · NONE · 2026-09-08T21:20:53Z · AFTER the fix was opened

Confirming this on a different framework, with a detail that widens the blast radius described above.

We hit it on **Astro SSR via `@astrojs/cloudflare`**, which does *not* shim `globalThis.Request`. So it is not limited to queue consumers / cron handlers — it breaks **ordinary request handling**. Every outbound HTTP call from the Worker fails at `Request` construction:

```
TypeError: Unsupported cache mode: default
```

Production impact on our site: the booking availability endpoint and the company-lookup endpoint both returned HTTP 500 for every request, because five server-side modules go through axios. The widget still rendered client-side (where `cache: 'default'` is valid), so the symptom looked like "the calendar is broken" rather than "all server integrations are down" — which cost us time locating it.

Version check against the bundled file, same environment:

| axios | occurrences of `cache: 'default'` in `dist/node/axios.cjs` |
| --- | --- |
| 1.19.0 | 0 |
| 1.20.0 | 1 |

Worth noting for anyone else landing here: this arrives through a **minor** bump, and typical CI stays green because unit tests and builds do not perform outbound HTTP from the Workers runtime. Ours passed, and the regression reached production.

Workaround we applied: pin `1.19.0` exactly — `^1.19.0` resolves straight back to 1.20.0.

+describe('fetch cache compatibility', () => {
+  [undefined, 'no-store', 'no-cache'].forEach((cache) => {
+    it(`preserves ${cache || 'the native default'} cache behavior`, async () => {
+      let captured;
+      const response = await axios.get('/cache', {
+        adapter: 'fetch',
+        fetchOptions: cache === undefined ? undefined : { cache },
+        env: {
+          fetch(input) {
+            captured = input;
+            return Promise.resolve(new Response('ok'));
+          },
+        },
+      });
+
+      expect(response.data).toBe('ok');
+      expect(captured.cache).toBe(cache || 'default');
+    });
+  });
+
+  it('omits cache when the Request implementation rejects every explicit mode', async () => {
+    let capturedInit;
+
+    class CacheDisabledRequest extends Request {
+      constructor(input, init) {
+        if (init && init.cache !== undefined) {
+          throw new TypeError("The 'cache' field on 'RequestInitializerDict' is not implemented.");
+        }
+
+        super(input, init);
+        capturedInit = init;
+      }
+    }
+
+    const response = await axios.get('/cache-disabled', {
+      adapter: 'fetch',
+      env: {
+        Request: CacheDisabledRequest,
+        fetch() {
+          return Promise.resolve(new Response('ok'));
+        },
+      },
+    });
+
+    expect(response.data).toBe('ok');
+    expect(Object.prototype.hasOwnProperty.call(capturedInit, 'cache')).toBe(false);
+    expect(capturedInit.redirect).toBe('follow');
+  });
+});
