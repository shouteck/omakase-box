## Title

Generated man pages put flag and description on one line

## Body

Man pages from `doc.GenMan` / `GenManTree` print each flag's description on the same line as the flag. Long descriptions wrap back to the left margin. From restic's `restic-backup.1`, generated by `restic generate --man` (`MANWIDTH=80`):

```
     -n, --dry-run[=false]      do not upload or write any data, just show what
     would be done

     -e, --exclude=[]      exclude a pattern (can be specified multiple times)

     --exclude-caches[=false]      excludes cache directories that  are  marked
     with  a  CACHEDIR.TAG file. See https://bford.info/cachedir/ for the Cache
     Directory Tagging Standard
```

Expected is the usual tagged-paragraph layout:

```
     -n, --dry-run[=false]
            do not upload or write any data, just show what would be done

     -e, --exclude=[]
            exclude a pattern (can be specified multiple times)

     --exclude-caches[=false]
            excludes cache directories that  are  marked  with  a  CACHEDIR.TAG
            file. See https://bford.info/cachedir/ for the Cache Directory Tag‐
            ging Standard
```

This is a regression from cobra v0.0.6, which moved to go-md2man v2 (#977). `manPrintFlags` writes the usage on a tab-indented line after the flag. go-md2man v1 kept that line separate, v2 joins it with the flag into one paragraph. @MichaelEischer reported it in [#1049](https://github.com/spf13/cobra/issues/1049#issuecomment-708654517), but that issue was closed with the `.TH` fix.

To reproduce:

```go
package main

import (
	"os"

	"github.com/spf13/cobra"
	"github.com/spf13/cobra/doc"
)

func main() {
	cmd := &cobra.Command{Use: "demo", Short: "Demo command", Run: func(*cobra.Command, []string) {}}
	cmd.Flags().String("name", "", "Name of the thing")
	cmd.Flags().StringP("output-directory", "o", "", "Directory to write the generated files to, created if it does not exist yet")
	_ = doc.GenMan(cmd, nil, os.Stdout)
}
```

```
go run . > demo.1 && man -l demo.1
```

With cobra v0.0.5 each description is on its own line. With v0.0.6 up to v1.10.2 it is on the option line, the gap after each option differs, and the long one wraps back to the margin.

I generated the man pages of docker, hugo, restic, caddy and helm with their own commands, and all of them have this layout. gh fixed it in its own copy of the generator by writing the usage as a go-md2man definition list ([cli/cli#4939](https://github.com/cli/cli/pull/4939)), which renders as `.TP`.

I have a fix with a regression test and will open a PR.
