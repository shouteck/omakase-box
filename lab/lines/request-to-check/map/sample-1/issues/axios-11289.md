## Title

Nested Buffer fields lose their parent paths in URL-encoded requests

## Body

### Describe the bug

Automatic URL-encoded serialization in Node drops the parent path of a nested Buffer. Two buffers under different objects are sent with the same bare field name, so the receiving server cannot tell them apart. Ordinary nested strings keep their paths.

### To reproduce

```js
import axios from 'axios';
import { createServer } from 'node:http';

const server = createServer((req, res) => req.pipe(res));
await new Promise((resolve) => server.listen(0, '127.0.0.1', resolve));
try {
  const response = await axios.post(
    `http://127.0.0.1:${server.address().port}/`,
    {
      first: { file: Buffer.from('abc') },
      second: { file: Buffer.from('xyz') },
    },
    { headers: { 'Content-Type': 'application/x-www-form-urlencoded' } }
  );
  console.log([...new URLSearchParams(response.data)]);
} finally {
  await new Promise((resolve) => server.close(resolve));
}
```

Actual: `[['file', 'YWJj'], ['file', 'eHl6']]`.

Expected: `[['first[file]', 'YWJj'], ['second[file]', 'eHl6']]`. With `formSerializer: { dots: true }`, the names should be `first.file` and `second.file`.

### Environment

Axios 1.20.0, `v1.x` at `c4303eeb601d3d5914a0f425cc7539616fdc7ea7`; Node 24.11.1 on macOS. Reproduced through `axios.post` against a local HTTP echo server.

The Buffer branch of `toURLEncodedForm` appends `key` directly and ignores `path`. Passing the existing base64 string to the default form visitor preserves the path and configured notation. Top-level Buffer encoding can stay unchanged.
