## Findings and attacks

1. **Coverage observation parity is missing.** measure.py compares plain exit/stdout/stderr only to strace, not coverage. fixture_driver.py only checks the coverage command exit. A coverage-instrumented run can change the observable failure while contributing E seeds. Coverage raw artifacts exist, so the admission adapter must compare frozen failure identity against the uninstrumented run and reject mismatch; passing strace parity is insufficient. Timing is a further concern: measure.py performs several commands with individual 110-second timeouts inside a runner capped at 120 seconds total. Aggregate timeout must remain an environment failure, not an absent trace.

2. **Value imports are excluded with erased imports.** typescript_adapter.mjs originalVisit rejects every ImportDeclaration. A module consisting of `import './side-effect'` executes generated require code but cannot receive an E statement through the original-import mapping. Type-only import exclusion does not justify excluding executable imports. Re-exports similarly need an explicit semantic fixture, because ExportDeclaration is categorically excluded despite possible runtime require work. This does not invalidate the present dead/type/comment fixture; it limits the adapter claim pending a known-answer import/re-export calibration.

3. **cwd uncertainty can copy the wrong bytes.** I independently ran a light Node counterexample against parseTrace: chdir('/case/tree/data') followed by openat(AT_FDCWD,'value.txt',O_RDONLY)=3</case/tree/data/value.txt>. With both data/value.txt and value.txt tracked, the parser emits value.txt as present/read and selects the wrong root file. It lists chdir as unknown, but exportCase does not refuse trace unknowns. Recorded README says admission must refuse uncertain cwd; this must become a caller check or parser refusal before export. Successful open result annotation already identifies the actual path in this example.

4. **Existence-only probes become file bytes.** parseTrace's observed set uses all successful events, including stat/access, rather than successful file reads. An access/stat probe of an omitted source adds its bytes to requiredProductionExpansion; non-source existence probes add bytes to primary packaging. Protocol distinguishes query state from bytes actually read. Preserve existence/listing state and its reconstruction obligation; do not silently substitute full content for existence-only state.

5. **Artifact trust is limited to cooperative public code.** Runner bounds mounts/network/CPU/memory and uses a read-only case, which is materially useful isolation. However target and supervisor share uid 1000 and writable /tmp,/record. Target can write ready/release sentinels or supervisor.json; a descendant creating another session can escape killpg and mutate artifacts during capture. This is not evidence of host access, but it prevents treating supervisor/artifact contents as tamper-resistant authority against adversarial targets. Current fixture is cooperative. Future public adapters should state this boundary or separate verdict channel/ownership. Capture limits and symlink refusal are present, but rglob enumeration itself can be large before regular-file limits are enforced.

6. **Project maps remain unsupported.** Hash receipts, source content equality, and exact mapped columns improve the synthetic TS adapter over line-only guessing. They do not establish native project-loader map correctness: receipt source filenames/map headers, project tsconfig/module mode and loaders must be verified before admission. README already explicitly limits transpile to authored CommonJS ES2022 fixtures, which is appropriate. Do not present that fixture as native ky/zod readiness.

7. **Exclusion accounting remains provisional.** Accepted-overlay receipt for click3192 reports tests=0 and explicitly is not admission. Collection correctly rejects confirmation IDs before fetch and keeps accepted first-parent/test-only overlay provenance separate. A zero-test receipt is not evidence of no runnable example until request/command admission is attempted under the frozen rules. Setup failures, overlay absence, resource exhaustion and adapter unsupported outcomes must remain visible in development readiness; no selector-success-conditioned denominator.

### Findings

1. **"Import closure reaches the whole root" has a different cause in each case, and on Ky it is almost entirely type-only imports.** Diagnostic outside the frozen protocol: I classified import statements in the Ky base source with a regex (not the compiler; my all-edges closure reproduces the recorded EI of 24 exactly). Nine of the ten non-executed files (all eight `source/types/*.ts` and `source/utils/types.ts`) enter only through `import type` / `export type` edges; one (`delay.ts`) through a value import. The frozen rule says type-only imports count as disclosure, so this is the protocol working as written, not an instrument error; but the page's sentence hides that on Ky the whole EI-minus-E gap except one 690-byte file is erased at runtime. So "E is runnable on Click, not on Ky" (C3) and "E is 82% on Click, 58% on Ky" (C2) are partly products of that asymmetry, not of the projects. A function-level notion on Click gives 11/17 files and 76.8% of root bytes; a statement-level one gives 1,693 of 4,410 statements (38.4%). Nothing at file granularity reaches 25%; finer granularity is the only place a small number could come from, and the protocol deliberately excludes it. These are diagnostics, not a new rule.
