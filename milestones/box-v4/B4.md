# B4. Bounded Open Box milestone

This is the active Box V4 plan. Read the common specification, standing orders and state protocol before work. Every task requires approval of its named work wave. The CTO coordinates; station leads dispatch scoped workers; independent reviewers bind verdicts to exact candidates. Current product code is an asset to evaluate, not automatic proof of these new criteria.

## B4.1. Expose the common Box lifecycle API

Owner station is platform_execution. Dependencies are B1.2, B2.2, B3.2. Supplement stage is 2.

### Allowed outputs

- `services/private-api/boxes/routes/**`
- `services/private-api/boxes/api/**`
- `packages/box-contracts/api/**`
- `tests/box/api/**`

Shared schemas, migrations and tooling require a CTO-managed integration lease. All product writes must also be inside the approved wave scope.

### Reuse to inspect

- `services/private-api/src/bootstrap/server.ts`
- `packages/contracts/auth/**`
- `services/private-api/intents/routes.ts`

### Deliver

- Register/create/version/approve/get-context/open/evaluate/submit/evidence/review operations through typed Box methods.
- Shared human/agent capability checks, scoped agent identities and idempotent operation/event records.
- Readiness/transition contract that makes absent profile/evaluator/approval explicit.

### Acceptance

- Human UI and headless clients call the same operations and cannot bypass approval, path or role gates.
- Cross-repo/attempt/resource access fails server-side; executor cannot review/merge itself; no duplicate authoritative submissions.
- Private and external legacy data remain isolated and no new general internal serializer leaks context.

### Verify

- Required new test:box-api runs actual synthetic authenticated API transaction and stale/concurrent/idempotency checks.
- Independent authorization audit and interface/version tests against literal behaviors.

New named suites are required future commands, not existing commands or passed checks. Implement them under the owning task and tooling lease before using their results. Tests must exercise behavior with independent expectations. Unavailable checks stay unavailable.

### Handoff

Use templates/box-v4/handoff.md. Save bounded evidence under `.execution/box-v4/evidence/B4.1/` and a candidate handoff to the owning lead. Root finalizes `.execution/box-v4/handoffs/B4.1.md` only after independent revision-bound acceptance and dependencies. Report limits, actual runtime/model and next-agent interface context. Do not update legacy state.

- `apps/private-console/intake/**`

### Deliver

- Box list/detail with approved behavior/context, attempts, statuses/evidence and next permitted action.
- Goal-first create/approve/assign/open/submit/review flow; loading/failure/mobile/keyboard behavior.
- Show lineage/version, capability and assurance states plainly without requiring users to read raw technical records.

### Acceptance

- PM and executor navigate one full-stack Box and policy Box through the common API; gates match server state.
- Known blocked/failed/unavailable states are visible; no screen claims automatic payment, native pstack or accepted code without evidence.
- Synthetic end-to-end walkthrough is labeled as such; complete details remain accessible.
