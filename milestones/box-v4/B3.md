# B3. Bounded Open Box milestone

This is the active Box V4 plan. Read the common specification, standing orders and state protocol before work. Every task requires approval of its named work wave. The CTO coordinates; station leads dispatch scoped workers; independent reviewers bind verdicts to exact candidates. Current product code is an asset to evaluate, not automatic proof of these new criteria.

## B3.1. Provision a pinned trusted Open Box workspace

Owner station is platform_execution. Dependencies are B1.2, B0.2. Supplement stage is 1.

### Allowed outputs

- `packages/box-workspace/**`
- `infra/box-workspaces/**`
- `services/private-api/boxes/workspaces/**`
- `tests/box/workspaces/**`
- `docs/box-v4/workspace-operations.md`

Shared schemas, migrations and tooling require a CTO-managed integration lease. All product writes must also be inside the approved wave scope.

### Reuse to inspect

- `templates/workspaces/public-image-profile.ts`
- `templates/workspaces/catalogue.ts`
- `infra/trusted.Dockerfile`
- `scripts/docker.mjs`

### Deliver

- Approved local Dev Container/Docker workspace recipe with pinned tools/images, attempt mounts and bounded resources.
- Trusted command registry and ready/cancel/dispose lifecycle; fixed networking/storage policy and no unnecessary host credentials/daemon mounts.
- Keep Open Box IDs/profile separate from unavailable dedicated hostile-runner services.

### Acceptance

- Fresh approved synthetic attempt environment starts reproducibly and runs declared fixture commands; unavailable resources block honestly.
- Candidate/repository code executes only in declared workspace, not the host; no arbitrary model shell strings or privileged fallback.
- Sparse checkout is optional context reduction and no secrecy claim; restricted_private/hostile_external cannot route here.

### Verify

- Required new test:box-workspaces --real on approved existing Docker environment; unit mocks remain separate.
- Verify actual limits, mount/network policy, image/digest drift, cancelled jobs and scoped cleanup without touching unrelated data.

New named suites are required future commands, not existing commands or passed checks. Implement them under the owning task and tooling lease before using their results. Tests must exercise behavior with independent expectations. Unavailable checks stay unavailable.

### Handoff

Use templates/box-v4/handoff.md. Save bounded evidence under `.execution/box-v4/evidence/B3.1/` and a candidate handoff to the owning lead. Root finalizes `.execution/box-v4/handoffs/B3.1.md` only after independent revision-bound acceptance and dependencies. Report limits, actual runtime/model and next-agent interface context. Do not update legacy state.
