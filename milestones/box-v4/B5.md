# B5. Bounded Open Box milestone

This is the active Box V4 plan. Read the common specification, standing orders and state protocol before work. Every task requires approval of its named work wave. The CTO coordinates; station leads dispatch scoped workers; independent reviewers bind verdicts to exact candidates. Current product code is an asset to evaluate, not automatic proof of these new criteria.

## B5.1. Open a Box in an existing workbench

Owner station is product_experience. Dependencies are B4.2, B3.1. Supplement stage is 2.

### Allowed outputs

- `packages/box-workbench/**`
- `apps/private-console/boxes/workbench/**`
- `docs/box-v4/workbench/**`
- `tests/box/workbench/**`

Shared schemas, migrations and tooling require a CTO-managed integration lease. All product writes must also be inside the approved wave scope.

### Reuse to inspect

- `Current installed Cursor/editor capabilities`
- `Existing environment/workspace managers and Box API`

### Deliver

- Thin installed-editor/workspace adapter for open Box, behavior/context reference, evaluator invocation and actual diff.
- Reuse editor code/terminal/debug/diff features; avoid custom IDE/VCS engine.
- Document actual available behavior-pane integration or explicit web-detail/editor-link fallback with its UX limits.

### Acceptance

- Opening a Box brings an immediately usable attempt with exact behavior/version and evaluator controls; stale/unavailable links fail visibly.
- Native editor claim has an actual live integration receipt; a fallback is labeled and no imaginary editor hook is required.
- Workspace and scoped API authority remain the same as headless execution; editor actions cannot approve their own attempt.

### Verify

- Required new test:box-workbench plus live editor/workspace walkthrough on exact candidate and installed capability.
- Independent inspect/open/edit/check/diff cycle, reconnect/error and stale-Box cases; save actual screenshots/receipts.

New named suites are required future commands, not existing commands or passed checks. Implement them under the owning task and tooling lease before using their results. Tests must exercise behavior with independent expectations. Unavailable checks stay unavailable.

### Handoff

Use templates/box-v4/handoff.md. Save bounded evidence under `.execution/box-v4/evidence/B5.1/` and a candidate handoff to the owning lead. Root finalizes `.execution/box-v4/handoffs/B5.1.md` only after independent revision-bound acceptance and dependencies. Report limits, actual runtime/model and next-agent interface context. Do not update legacy state.

Owner station is platform_execution. Dependencies are B4.1, B3.2. Supplement stage is 2.

- `services/private-api/boxes/executors/**`
- `apps/private-console/boxes/executor-controls/**`
- `tests/box/executors/**`

Shared schemas, migrations and tooling require a CTO-managed integration lease. All product writes must also be inside the approved wave scope.

### Reuse to inspect

- `Available approved local agent runtime`
- `Box API, workspace and evaluation methods`

### Deliver

- Explicit human/agent/hybrid selection and approved headless runtime adapter consuming identical Box/context/environment/evaluator.
- Scoped short-lived identity, cancellation/progress and bounded attempt submission; no privileged model approval path.
- Demo adapter is separate; unavailable real executor remains a capability blocker with a safe human path.

### Acceptance

- An actual approved agent adapter submits one attempt through the same API/checks as a human path; mocked solver output does not count.
- Agent cannot escape assignment/scope, self-review or mutate approved contract; cancellation/retry is idempotent.
- No automatic cloud/private-code upload or paid model fallback; model availability and cost remain within wave policy.

### Verify

- Required new test:box-executors with real approved runtime integration receipt and mock protocol tests separately.
- Independent compare human/agent API bindings, wrong token, stale context, cancellation and output bounds.

New named suites are required future commands, not existing commands or passed checks. Implement them under the owning task and tooling lease before using their results. Tests must exercise behavior with independent expectations. Unavailable checks stay unavailable.
