# B6. Bounded Open Box milestone

This is the active Box V4 plan. Read the common specification, standing orders and state protocol before work. Every task requires approval of its named work wave. The CTO coordinates; station leads dispatch scoped workers; independent reviewers bind verdicts to exact candidates. Current product code is an asset to evaluate, not automatic proof of these new criteria.

## B6.1. Coordinate cross-Box dependencies and team assignments

Owner station is platform_execution. Dependencies are B4.1, B5.2. Supplement stage is 3.

### Allowed outputs

- `services/private-api/boxes/teams/**`
- `packages/box-contracts/dependencies/**`
- `tests/box/teams/**`

Shared schemas, migrations and tooling require a CTO-managed integration lease. All product writes must also be inside the approved wave scope.

### Reuse to inspect

- `services/private-api/assignments/**`
- `packages/contracts/public/composition.ts`

### Deliver

- Cross-Box DAG separate from within-Box interfaces, role-bound assignment and ready/blocked/failed/cancelled semantics.
- Concurrent attempts with exclusive worktree ownership and stable dependency/Box version references.
- No forced AI routing, bounty reservations or reward semantics in internal team assignment.

### Acceptance

- Cycle/wrong-version/foreign-owner dependencies are rejected; unmet required parent result blocks readiness.
- Two independent Boxes can proceed without a shared writer; same-target integration is queued safely.
- A worker return or component check cannot satisfy parent acceptance; failure/cancellation propagates with clear reason.

### Verify

- Required new test:box-teams runs synthetic concurrency, DAG/cancellation and authorization API transactions.
- Independent distinguish inter-Box prerequisites from service interfaces; inspect actual attempt isolation.

New named suites are required future commands, not existing commands or passed checks. Implement them under the owning task and tooling lease before using their results. Tests must exercise behavior with independent expectations. Unavailable checks stay unavailable.

### Handoff

Use templates/box-v4/handoff.md. Save bounded evidence under `.execution/box-v4/evidence/B6.1/` and a candidate handoff to the owning lead. Root finalizes `.execution/box-v4/handoffs/B6.1.md` only after independent revision-bound acceptance and dependencies. Report limits, actual runtime/model and next-agent interface context. Do not update legacy state.

### Deliver
