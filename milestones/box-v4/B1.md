# B1. Bounded Open Box milestone

This is the active Box V4 plan. Read the common specification, standing orders and state protocol before work. Every task requires approval of its named work wave. The CTO coordinates; station leads dispatch scoped workers; independent reviewers bind verdicts to exact candidates. Current product code is an asset to evaluate, not automatic proof of these new criteria.

## B1.1. Implement the versioned Open Box aggregate and transitions

Owner station is platform_execution. Dependencies are B0.1, B0.2. Supplement stage is 0.

### Allowed outputs

- `packages/box-contracts/**`
- `services/private-api/boxes/store/**`
- `services/private-api/db/migrations/**`
- `tests/box/contracts/**`
- `tests/box/auth/**`

Shared schemas, migrations and tooling require a CTO-managed integration lease. All product writes must also be inside the approved wave scope.

### Reuse to inspect

- `packages/contracts/hash.ts`
- `packages/contracts/public/composition.ts`
- `services/private-api/db/intent-store.ts`
- `packages/contracts/auth/**`

### Deliver

- Typed BoxVersion, Attempt, EvaluationReceipt, Assignment, ReviewDecision and MergeRecord with immutable version hashes and explicit open_trusted profile.
- Forward migrations and idempotent optimistic state transitions; server-side author/executor/reviewer/merge-owner permissions and scoped attempt identity.
- Register meaningful future test:box-contracts and test:box-auth commands through a coordinator tooling lease.

### Acceptance

- Single-unit, UI/API and UI/API/policy Boxes validate; mandatory reward/disclosure/dedicated-KVM fields do not contaminate the Open Box schema.
- Draft/approval/edit invalidation, wrong identity, cross-repo/attempt IDs, stale updates and illegal transitions are rejected server-side.
- Current profile remains separate from legacy restricted enums/guards; no new private-to-external serializer is introduced.
- Use this first coding unit as the approved lead/worker/verifier orchestration pilot. Verify its durable receipt and actual adapter before any parallel implementation fan-out.

### Verify

New named suites are required future commands, not existing commands or passed checks. Implement them under the owning task and tooling lease before using their results. Tests must exercise behavior with independent expectations. Unavailable checks stay unavailable.
