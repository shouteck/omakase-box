# B7. Bounded Open Box milestone

This is the active Box V4 plan. Read the common specification, standing orders and state protocol before work. Every task requires approval of its named work wave. The CTO coordinates; station leads dispatch scoped workers; independent reviewers bind verdicts to exact candidates. Current product code is an asset to evaluate, not automatic proof of these new criteria.

## B7.1. Review exact candidates and handle target drift

Owner station is assurance_research. Dependencies are B3.2, B6.1. Supplement stage is 3.

### Allowed outputs

- `services/private-api/boxes/reviews/**`
- `packages/box-evaluation/review/**`
- `packages/box-git/drift/**`
- `apps/private-console/boxes/review/**`
- `tests/box/review/**`

Shared schemas, migrations and tooling require a CTO-managed integration lease. All product writes must also be inside the approved wave scope.

### Reuse to inspect

- `services/private-api/acceptance/**`
- `apps/private-console/review/**`
- `Current exact hash/version guards`

### Deliver

- Independent review record for actual diff/candidate and behavior/evaluator/version proof.
- Target/base drift detection, merge-preview binding and affected revalidation plan.
- Owner merge request authority separate from reviewer verdict, team assignment and CEO wave integration permission.

### Acceptance

- Executor self-review, wrong revision, missing checks and stale target cannot become merge-ready.
- Target movement or changed merge result invalidates affected review/checks; no blind apply of an old pass.
- Missing contract context is Box defect, not hidden contributor failure; independent reviewers and evidence remain truthful.

### Verify

- Required new test:box-review includes real synthetic branch divergence/conflicts and candidate hash/version cases.
- Independent reviewer audits literal same-revision authority and UI/API drift responses.

New named suites are required future commands, not existing commands or passed checks. Implement them under the owning task and tooling lease before using their results. Tests must exercise behavior with independent expectations. Unavailable checks stay unavailable.

Use templates/box-v4/handoff.md. Save bounded evidence under `.execution/box-v4/evidence/B7.1/` and a candidate handoff to the owning lead. Root finalizes `.execution/box-v4/handoffs/B7.1.md` only after independent revision-bound acceptance and dependencies. Report limits, actual runtime/model and next-agent interface context. Do not update legacy state.
