# B0. Reconcile before product changes

This is the active Box V4 plan. Read the common specification, standing orders and state protocol before work. Every task requires approval of its named work wave. The CTO coordinates; station leads dispatch scoped workers; independent reviewers bind verdicts to exact candidates. Current product code is an asset to evaluate, not automatic proof of these new criteria.

## B0.1. Reconcile existing source, evidence and Git history

Owner station is assurance_research. Dependencies are none. Supplement stage is 0.

### Allowed outputs

- `docs/box-v4/REUSE.md`
- `docs/box-v4/reconciliation/**`
- `.execution/box-v4/evidence/B0.1/**`

Shared schemas, migrations and tooling require a CTO-managed integration lease. All product writes must also be inside the approved wave scope.

### Reuse to inspect

- `.execution/state.json`
- `.execution/handoffs/**`
- `.execution/evidence/**`
- `docs/DECISIONS.md`
- `packages/contracts/**`

### Deliver

- Census all legacy components as reuse/adapt/revalidate/defer, with paths and current digests; separate historical approvals from current bytes and integration proof.
- Record actual Git HEAD/dirty state without committing, resetting or stashing; plan a reviewed synthetic/project baseline.
- Preserve legacy graph/state/receipts; publish metadata drift and real runtime/model gaps instead of rewriting old approvals.

### Acceptance

- 18 review/14 blocked records are reconciled against current source without inventing current approvals; snapshots and historical handoffs remain intact.
- Git base is explicitly absent until a real commit exists; no product changes, process startup or legacy coordinator writes occur in the reconciliation scope.

### Verify

- Read-only Git status/HEAD and exact file/evidence hash comparison; no product test execution is required to claim this inventory.
- Independent reviewer checks at least one previously approved, one checked/currently stale and one runner-blocked component and validates the preservation manifest.

New named suites are required future commands, not existing commands or passed checks. Implement them under the owning task and tooling lease before using their results. Tests must exercise behavior with independent expectations. Unavailable checks stay unavailable.

### Handoff

Use templates/box-v4/handoff.md. Save bounded evidence under `.execution/box-v4/evidence/B0.1/` and a candidate handoff to the owning lead. Root finalizes `.execution/box-v4/handoffs/B0.1.md` only after independent revision-bound acceptance and dependencies. Report limits, actual runtime/model and next-agent interface context. Do not update legacy state.
