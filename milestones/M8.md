# M8: Independent security and package readiness review

Threat boundaries and complete-package behaviour survive independent adversarial checks.

Read `docs/SPEC.md`, `docs/COMPOSITION.md`, `docs/ARCHITECTURE.md` and `docs/SECURITY.md` before implementing. These task cards are additive to their normative requirements. Normal execution requires accepted prerequisite handoffs. Sequential fallback may use checked implementations under START.md, while independent-review gates remain open.

The milestone passes when every task below has evidence and an independent accepted review. Sequential checked implementations alone do not complete the milestone. A mocked or unavailable mandatory runtime does not satisfy a real-runtime gate.

## M8.1: Adversarial boundary verification

Role: `security_review`. Prerequisites: M4.3, M5.2, M6.3, M7.2, M5.4.

Write scope: `tests/security/**`, `docs/security-review.md`. Shared changes require coordinator ownership.

### Implement

- Complete mandatory attack suite and evidence report from SECURITY.md.
- Open findings with severity, trusted assumptions and limits; no unsupported security claims.
- Independently challenge composite disclosure, API proxy privileges, data-only policy handling, verdict aggregation and shared-path ownership gates.

### Acceptance

- All decisive adversarial tests run with independent expected outcomes and actual VM jobs where required.
- Any unresolved blocker prevents pilot-ready status; positive good-submission cases still work.

### Verify

    pnpm test:security --real
    pnpm test:auth
    pnpm test:compiler

Commands must really run or be recorded unavailable. Implement the relevant meaningful suite if this is its first owner; an empty script is not evidence.

### Handoff

Write a draft using `templates/handoff.md`, include `.execution/evidence/M8.1/`, exact revision, outcomes, failures and delivered interfaces. Reviewer checks the task and security boundary. Coordinator finalizes `.execution/handoffs/M8.1.md` and advances eligible successors. Do not assume previous chat history.

## M8.2: External-only cold-start and alternatives

Role: `readiness_review`. Prerequisites: M7.1, M6.2.

Write scope: `tests/e2e/cold-start/**`, `research/readiness/**`, `docs/package-readiness-review.md`. Shared changes require coordinator ownership.

### Implement

- Fresh external-only workspace build/check/submit rehearsal and alternative satisfying patches.
- Incomplete package, support failure and defect-report classification; explicit human-readiness evidence field.
- Run the actual fresh package-only build/rehearsal in an isolated workspace. A solver, when available, has fresh context and package-only tool/filesystem exposure; full-history/shared-repository solves are labeled limited rehearsal.

### Acceptance

- Rehearsal has no private references/model/context; valid alternatives transfer privately.
- An agent solve is recorded as an agent solve; no human independence evidence is fabricated.
- Record mechanical rehearsal separately from blind solver and human evidence. Missing a constrained solver/human does not fabricate evidence; implementation can pass its mechanical gate while those research fields remain unverified.
- Cold-start mechanical readiness covers the connected full-stack package and response-policy package; valid alternatives pass aggregate private transfer, not merely isolated unit checks.
