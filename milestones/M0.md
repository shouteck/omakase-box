# M0: Foundation and reproducible fixture

A fresh agent can install, inspect capabilities and start separate trusted services without private data.

Read `docs/SPEC.md`, `docs/COMPOSITION.md`, `docs/ARCHITECTURE.md` and `docs/SECURITY.md` before implementing. These task cards are additive to their normative requirements. Normal execution requires accepted prerequisite handoffs. Sequential fallback may use checked implementations under START.md, while independent-review gates remain open.

The milestone passes when every task below has evidence and an independent accepted review. Sequential checked implementations alone do not complete the milestone. A mocked or unavailable mandatory runtime does not satisfy a real-runtime gate.

## M0.1: Bootstrap the workspace

Role: `platform`. Prerequisites: none.

Write scope: `package.json`, `pnpm-workspace.yaml`, `pnpm-lock.yaml`, `tsconfig*`, `scripts/**`, `apps/**/package.json`, `services/**/package.json`, `packages/**/package.json`, `docs/tooling.md`, `apps/**/src/bootstrap/**`, `services/**/src/bootstrap/**`, `tests/bootstrap/**`. Shared changes require coordinator ownership.

### Implement

- Pin Node/pnpm/dependencies; establish layout and nonempty check/build/doctor scripts.
- Record prerequisites, platform compatibility and supported versions; initialize a dedicated Git repository only if absent.
- Create runnable application/service skeletons and test entry points, not merely empty manifests.

### Acceptance

- A clean dependency installation and build succeed or an exact host prerequisite is recorded.
- Doctor reports model/DB/VM capabilities without credentials; no unavailable suite is represented as passing.

### Verify

    pnpm install --frozen-lockfile
    pnpm check
    pnpm build
    pnpm doctor --json

Commands must really run or be recorded unavailable. Implement the relevant meaningful suite if this is its first owner; an empty script is not evidence.

### Handoff

Write a draft using `templates/handoff.md`, include `.execution/evidence/M0.1/`, exact revision, outcomes, failures and delivered interfaces. Reviewer checks the task and security boundary. Coordinator finalizes `.execution/handoffs/M0.1.md` and advances eligible successors. Do not assume previous chat history.

## M0.2: Separate trusted runtime services

Role: `platform`. Prerequisites: M0.1.

Write scope: `infra/**`, `services/private-api/bootstrap/**`, `services/external-api/bootstrap/**`, `.env.example`, `docs/runtime.md`, `tests/auth/bootstrap/**`. Shared changes require coordinator ownership.

### Implement

- Compose configuration, service-specific volumes/networks and DB credentials.
- Local owner bootstrap and environment-variable validation; no real secrets in source.

### Acceptance

- External service cannot read private DB/storage or obtain model/release credentials.
- Default listeners are loopback; missing config fails explicitly; ordinary startup does not launch untrusted jobs.
- Real browser requests to contributor host contain no private session credential; cookies are host-only and origins explicitly allowed.
