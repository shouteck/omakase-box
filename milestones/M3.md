# M3: Boundary creation and private transfer planning

Supported responsibilities are separated through typed adapters and independently checked evidence.

Read `docs/SPEC.md`, `docs/COMPOSITION.md`, `docs/ARCHITECTURE.md` and `docs/SECURITY.md` before implementing. These task cards are additive to their normative requirements. Normal execution requires accepted prerequisite handoffs. Sequential fallback may use checked implementations under START.md, while independent-review gates remain open.

The milestone passes when every task below has evidence and an independent accepted review. Sequential checked implementations alone do not complete the milestone. A mocked or unavailable mandatory runtime does not satisfy a real-runtime gate.

Role: `analysis`. Prerequisites: M2.1, M1.1.

Write scope: `packages/analyzer/**`, `tests/analysis/**`. Shared changes require coordinator ownership.

### Implement

- TypeScript AST/import closure, edit-surface report and conservative unsupported-feature classification.
- Detect protected imports, dynamic loading, unsafe globals and omitted state dependencies.

### Acceptance

- Known forbidden coupling is rejected; unknown dynamic behaviour is not marked safe.
- Reports disclose assumptions and limits; AST linting is never labeled semantic confidentiality proof.
