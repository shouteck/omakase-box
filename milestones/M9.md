# M9: Integrated delivery and evidence-backed handoff

A fresh operator can run the prototype and see honest capability/research status.

Read `docs/SPEC.md`, `docs/COMPOSITION.md`, `docs/ARCHITECTURE.md` and `docs/SECURITY.md` before implementing. These task cards are additive to their normative requirements. Normal execution requires accepted prerequisite handoffs. Sequential fallback may use checked implementations under START.md, while independent-review gates remain open.

The milestone passes when every task below has evidence and an independent accepted review. Sequential checked implementations alone do not complete the milestone. A mocked or unavailable mandatory runtime does not satisfy a real-runtime gate.

## M9.1: End-to-end PM to accepted contribution

Role: `integration`. Prerequisites: M8.1, M8.2, M8.3, M7.3.

Write scope: `tests/e2e/full-journey/**`, `apps/**/integration/**`, `scripts/demo.*`, `docs/demo-walkthrough.md`. Shared changes require coordinator ownership.

### Implement

- Complete single-unit compatibility, coherent full-stack selection and executable response-security policy journeys, including intent/approval/invalidation/reservation/patch/aggregate review/ledger states.
- Usable responsive UI, loading/error states and accessibility smoke checks.
- Complete the combined frontend/backend/policy journey; a local-unit-pass/aggregate-fail patch never reaches accepted or creates a payable record.

### Acceptance

- PM can describe an outcome and owner/contributor complete the prescribed workflow without bypassing gates.
- Invalidation, task defects and failed jobs appear honestly; correct patches integrate as candidate diffs only.
- Full-stack success requires one task/contract/package/reward with working UI-to-candidate-API behaviour; response-security policy completes private loader/preservation checks. Frontend+backend+policy also completes one combined journey with passing and failing real-runner patches, aggregate owner acceptance and one payable event; no exclusive family rule remains.

### Verify

    pnpm test:e2e -- --suite full-journey
    pnpm check
    pnpm build

Commands must really run or be recorded unavailable. Implement the relevant meaningful suite if this is its first owner; an empty script is not evidence.

### Handoff

Write a draft using `templates/handoff.md`, include `.execution/evidence/M9.1/`, exact revision, outcomes, failures and delivered interfaces. Reviewer checks the task and security boundary. Coordinator finalizes `.execution/handoffs/M9.1.md` and advances eligible successors. Do not assume previous chat history.

### Implement

- Clean-install verification, credential-free demo instructions and real VM setup/run documentation.
- Workspace-scoped backup/restore, interrupted-job recovery and machine-readable delivery status.

### Acceptance

- Mandatory real-runner gate must pass; missing VM is a blocker, not a successful mock substitute.
- Live model verification is either genuinely observed or clearly needs_configuration; backups do not export private data into external storage.
- Runtime verification excludes the final coordinator task-state audit so M9.3 can execute its checks before its own completion.
- verify:mvp requires full-stack and executable policy pathways plus real composite runner gates; future unsupported adapters remain explicit capability gaps.

## M9.3: Final independent review and delivery report

Role: `final_review`. Prerequisites: M9.2.

Write scope: `docs/DELIVERY.md`, `README.md`, `docs/limitations.md`, `.execution/evidence/M9.3/**`. Shared changes require coordinator ownership.

### Implement

- Evidence-backed milestone audit, exact commands/URLs and current limitations.
- Separate statuses for software, VM runner, live provider, independent review and real human study; next research steps.

- No unresolved mandatory implementation/security gates or invented successes.
