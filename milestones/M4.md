# M4: Approved deterministic task packages

Only exact approved content reaches a runnable external package.

Read `docs/SPEC.md`, `docs/COMPOSITION.md`, `docs/ARCHITECTURE.md` and `docs/SECURITY.md` before implementing. These task cards are additive to their normative requirements. Normal execution requires accepted prerequisite handoffs. Sequential fallback may use checked implementations under START.md, while independent-review gates remain open.

The milestone passes when every task below has evidence and an independent accepted review. Sequential checked implementations alone do not complete the milestone. A mocked or unavailable mandatory runtime does not satisfy a real-runtime gate.

## M4.1: Release review and approval binding

Role: `release`. Prerequisites: M1.3, M3.2, M2.3, M3.4.

Write scope: `services/private-api/releases/**`, `apps/private-console/releases/**`, `tests/compiler/approval/**`. Shared changes require coordinator ownership.

### Implement

- Review exact listing/contract/assets/feedback/terms; stage approved content-addressed bytes.
- Owner approval signatures bound to hashes, versions and frozen policy.
- Review combined public meaning, interfaces and capability union across all work units; one owner approval covers the exact whole task.

### Acceptance

- Editing any approved byte, policy or template requires reapproval.
- AI/worker cannot approve; a displayed summary cannot replace review of actual released contents.

### Verify

    pnpm test:compiler -- --suite approval
    pnpm test:auth

Commands must really run or be recorded unavailable. Implement the relevant meaningful suite if this is its first owner; an empty script is not evidence.

### Handoff

Write a draft using `templates/handoff.md`, include `.execution/evidence/M4.1/`, exact revision, outcomes, failures and delivered interfaces. Reviewer checks the task and security boundary. Coordinator finalizes `.execution/handoffs/M4.1.md` and advances eligible successors. Do not assume previous chat history.

## M4.2: Approved-only compiler and workspace templates

Role: `compiler`. Prerequisites: M4.1, M1.1, M3.4.

Write scope: `packages/compiler/**`, `templates/workspaces/**`, `tests/compiler/package/**`. Shared changes require coordinator ownership.

### Implement

- Deterministic ZIP/manifest build with composable vetted fragments for frontend, pure module, backend API and application policy; assemble one offline-capable workspace with fixed shared toolchain/start/check instructions.
- Pinned trusted public image with required dependencies and runnable public checks.

### Acceptance

- Two different private systems with identical approved inputs produce byte-identical packages.
- Package excludes private mappings/canaries/history/cache/source maps; compiler has no arbitrary private-path or model access.
- Execution image layers/history contain no private files/canaries; images are built exclusively from public/vetted inputs.
- Single-unit, connected full-stack and policy packages compile; schema/toolchain collisions and dangling interfaces fail; changing one unit/interface invalidates whole-package approval.
