# M1: Contracts, state and authorization

Every later feature shares versioned public/private contracts and enforced transitions.

Read `docs/SPEC.md`, `docs/COMPOSITION.md`, `docs/ARCHITECTURE.md` and `docs/SECURITY.md` before implementing. These task cards are additive to their normative requirements. Normal execution requires accepted prerequisite handoffs. Sequential fallback may use checked implementations under START.md, while independent-review gates remain open.

The milestone passes when every task below has evidence and an independent accepted review. Sequential checked implementations alone do not complete the milestone. A mocked or unavailable mandatory runtime does not satisfy a real-runtime gate.

## M1.1: Typed contracts and immutable hashes

Role: `contracts`. Prerequisites: M0.1.

Write scope: `packages/contracts/**`, `tests/contracts/**`. Shared changes require coordinator ownership.

### Implement

- Zod types, canonicalization version and positive public projections.
- Valid/invalid fixture examples for all schema types from ARCHITECTURE.
- Define nonexclusive disciplines, WorkUnit/PublicInterface arrays, adapter versions, exact edit ownership and aggregate end-to-end requirements; no exclusive task-family discriminator.

### Acceptance

- Unknown privileged fields are rejected; external DTOs contain no internal provenance.
- Identical canonical content hashes identically; one-byte changes invalidate its digest; path collisions are rejected.
- Single-unit, frontend+backend and frontend+backend+policy contracts validate; conflicting path/schema ownership, dangling links and unknown capabilities are rejected.

### Verify

    pnpm test:contracts
    pnpm check

Commands must really run or be recorded unavailable. Implement the relevant meaningful suite if this is its first owner; an empty script is not evidence.

### Handoff

Write a draft using `templates/handoff.md`, include `.execution/evidence/M1.1/`, exact revision, outcomes, failures and delivered interfaces. Reviewer checks the task and security boundary. Coordinator finalizes `.execution/handoffs/M1.1.md` and advances eligible successors. Do not assume previous chat history.
