## Delivered behaviour and interfaces

### packages/evaluation/runner-results/index.ts (pure result classification; no private-api import)

- Types: `JobKind`, `VerifiedOutcome`, `EvidenceClass` ('verified' | 'unverified' | 'infrastructure'), `EvidenceOutcome`, `AnomalyCause`, `InfrastructureCause`, `EvaluationState`, `Verification Cases` documented in code; helper constants `LOG_BYTE_LIMIT = 1048576`, `ANOMALY_CAUSES`, `INFRASTRUCTURE_CAUSES`, `FEEDBACK_CATEGORY_LIMIT = 512`, `PAYLOAD_DIGEST_INPUT_LIMIT`.
- `verifiedResultEvidence(binding, record)` — classifies an already protocol-verified runner result; rejects contract-breaking bindings (job id/kind/package/submission/artifact/image/harness digests must match the immutable job binding), contradictory verdicts (passed with non-passed checks) and unbounded values.
- `infrastructureEvidence(binding, cause, logDigest)` and `anomalyEvidence(binding, cause, logDigest, payloadDigest)` — deterministic records for timeout/interruption/unavailable ('infrastructure') and corrupt/replayed/late/malformed/'runner_reported_unverified' results ('unverified'); both can never classify as passing.
- `aggregateAuthoritativeOutcome(records)` — public-only or private-only evidence yields 'unverified' (never passed); infrastructure evidence yields 'infrastructure_failure'; unverified yields 'unverified'; verified failed public evidence yields 'contract_failure' and failed private evidence 'integration_failure' (private failure dominant); 'passed' requires verified passing evidence for both job kinds.
- `buildInternalEvaluationResult(input, records, privateLogsBytes)` — builds the schema-valid `InternalEvaluationResult` (packages/contracts/private) whose outcome can only be 'passed', whose evidence entries bind checkId/jobId/jobKind/artifactHash/harnessDigest, and whose bounded `privateLogs` (≤1 MiB) stays inside the private payload; throws `EvaluationNotPassedError` otherwise.
- `trimCapture(bytes, limit = LOG_BYTE_LIMIT)` — deterministic capture bounding: overshoot truncates at ≤3 bytes below the limit on a UTF-8-safe boundary, records `complete=false` plus `originalByteCount`, and the SHA-256 `digest` always names exactly the stored bytes.
- `verifyEvidenceBinding(evidence, expected)` — returns every drifted binding field (artifact/image/harness digests, jobKind/jobId, revision taskId/taskVersion/privateBaseRevision).
- `projectPublicFeedback({publicId, releasePolicyVersion, evaluationState, evidence})` — projects the approved public feedback vocabulary (received/processing/owner_review/accepted/changes_required/package_defect/infrastructure_issue, plus 'expired' for the reservation-lifecycle state) with `publicCheckDetails` built ONLY from verified public evidence; private evidence contributes nothing, and unknown states fail closed. Validated by `PublicFeedbackSchema` (packages/contracts/public).

### services/private-api/jobs/store.ts (`EvaluationJobStore` with injected `pg.Pool`)

- `enqueue(actor, input)` — transactional and authoritative only: re-checks account/session/CSRF inside the transaction; takes package/submission hashes, task/taskVersion, submissionId from the permit-bound `private_evaluations` row (never from the caller); requires the approved `private_release_approvals.manifest->>'executionImageDigest'` for (task, version) and the approved `private_release_candidates.contract.publicChecks` id set (public kind must bind the exact complete published check set); harness must be a fixed trustedHarness mapping with matching digest; deadline must lie inside (now, now+120s]; validates superseded/out-of-order states. Duplicate enqueue with identical binding (`attemptId`, artifact/image/harness, required checks) is idempotent — returns the existing job, no evaluation version change, no extra disclosure; any binding difference is `JobBindingConflict`. Concurrent enqueues produce at most one job (unique (evaluation_id, job_kind) + (permit_id, job_kind), unique-violation retry).
- `assumeLease(jobId, lease)` — LeaseSchema-validated lease identity bound immutably exactly once; job queued→running.
- `recordResult(jobId, signedInput, publicKey, logs?, now?)` — re-verifies the delivered signed result with `packages/runner-protocol.verifyTrustedResult` against a protocol Job/Lease rebuilt from the immutable row binding (no signing reimplementation). Verified results require stored log bytes to match the signed `logDigest` when bytes are passed; anomalies (unauthenticated/binding mismatch/stale/late/replayed/malformed/incomplete/contradictory/log mismatch/runner-declared unverified) are recorded as unverified result rows and, when the job is running, end the job unverified with the evaluation set to `infrastructure_failure`. Late results (post-cancel/completion/queued) are recorded but never affect state. `payloadDigest` (bounded canonical signed-input digest) enables replay detection per job.
- `recordTimeout(jobId)` — running jobs only, ends infrastructure with cause 'timeout'; queued timeouts are 422; terminal jobs are harmless no-op reports.
- `recordInterruption(jobId, cause)` — 'interrupted' | 'lease_lost' | 'runner_unavailable'; valid from queued or running; same never-passing guarantee.
- `cancel(actor, jobId, expectedVersion)` / `cleanup(actor, jobId, expectedVersion)` — transactional, scoped precisely to one job row: cancel queued/running only with exact-version checks (409 stale otherwise); cleanup additionally discards only that job's stored log row (refused for completed jobs, 409); neither touches any other job, workspace, release object, or active evaluation row beyond the mapping described below.
- `read` / `readForEvaluation` / `readLogs` — operator-only bounded projections; reads never include raw log bytes (digests only); `readLogs` is the only private raw-log path.
- Evaluation-state mapping deconflicted through the M1.2 trigger-guaranteed `private_evaluations` transitions: public verified pass leaves the evaluation in `public_evaluating` (the private enqueue is gated on the public job being verified-passed), public/private verified fail → `changes_required`, infrastructure/unverified → `infrastructure_failure`, private verified pass → `owner_review` with a `InternalEvaluationResult` payload built from BOTH jobs' evidence; a mapping precondition mismatch is skipped (recorded) rather than silently claimed; owner acceptance itself remains M7.
