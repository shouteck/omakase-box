## Simple operating modes

- Enhanced: selectively use reviewed premium assignments within included allowance, retaining cheaper/free routine workers and a review reserve.
- Economy: conserve allowance for difficult decisions and consequential review; prefer verified free workers for routine tasks.
- Free mode: no quota-consuming child dispatch. Use a model currently verified free for this account, such as SWE-2 while its promotion actually applies. If none is suitable/available, checkpoint and report the smallest decision needed.

"Quota available" requests Enhanced mode subject to current account evidence. "Free mode" requests Free mode for subsequent child dispatch. Neither approves a wave or clears a hold. START.md stays the entrypoint; no additional routine command is needed once reliable automatic quota detection exists.

When quota cannot be read reliably, default children to Free mode until the CEO supplies a current allowance confirmation or a supported source is available. Ask at most one concise question if necessary. Human confirmation can select a mode but cannot provide a continuously refreshed exact balance.

## Budget and dispatch rules

1. Check BOTH daily and weekly allowance, source and observation time, shared usage and pending work before dispatch. Missing/stale values mean unknown. Propose explicit mode thresholds and a review reserve in the concrete setup; never invent precise quota estimates.
2. Do not purchase, enable or consume paid extra usage under this included-allowance policy. Verify an actual provider/account spend boundary before claiming allowance-only premium dispatch. Prompt rules and estimated reserves cannot enforce a billing cap. If the boundary cannot be established, use verified free children or report the gap.
3. Custom Devin profiles require supported explicit model fields (or a supported skill override). A model name in a task prompt does not select the model. Verify exact available IDs, premium/free profiles and discovery before activation; do not rewrite shared profiles during active dispatch.
4. Switch at a safe new dispatch boundary, preserving handoffs, receipts, approved topology and one-writer leases. Do not assume profile edits change an already-running or resumed child's model; record a new identity where needed.
5. Once reviewed assignments, budget controls and fallbacks are in an approved setup/wave envelope, ordinary selection within it needs no repeated permission. New providers, extra usage, out-of-envelope models or material scope changes need an amended proposal. Quota reset never starts/resumes work.
6. Record configured model, actual model where exposed, operating mode and quota source. If the runtime hides the model, say unobserved; never invent diversity or exact consumption.
7. Prefer bounded process supervision and collected logs over repeated model calls polling unchanged results. Do not repeat unchanged failures without a new hypothesis or exceed approved retry/time limits. Stabilize W002's test environment independently of model routing.
