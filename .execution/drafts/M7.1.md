## Delivered interfaces

- `packages/evaluation/pipeline/jobs.ts` — `planEvaluationJobs` freezes one public + one private job per evaluation from pinned M5.4 attempt descriptors. All binding fields (evaluationId, permitId, attemptId, submissionId, taskId/taskVersion, submissionHash, packageHash, privateBaseRevision) validated; identical descriptors and descriptor-kind mismatches rejected; harness digest derived internally via `trustedHarness('composed/v1')` — never caller-supplied. Deterministic sha256-derived jobIds and planDigest.
- `packages/evaluation/pipeline/patch-map.ts` — `mapPatchToUnits`: validated M6.3 patch paths → declared work units via the template unit index. Traversal/non-portable paths throw `invalid_path`; unknown paths collect into `unmappedPaths`.
- `packages/evaluation/pipeline/candidate-diff.ts` — `buildCandidateDiff`: private candidate diff as pure data (canonical digest over privateBaseRevision + submissionHash + patchDigest + per-unit file lists). Rejects unmapped paths and empty diffs. No merge, no deploy.
- `packages/evaluation/pipeline/fit.ts` — `evaluatePrivateFit`: composes M3.4 contract-fit partition + M5.4 aggregate + response-policy loader verification. Mismatch patch passing unit checks still fails whole-task fit; unpublished private expectations → `package_defect`; contract-fit classes preserved (no flattening).
- `packages/evaluation/pipeline/advance.ts` — `advanceEvaluation`: honest transition fold — pending/unverified/infrastructure-only evidence never advances; only complete verified aggregate + passed fit reaches `owner_review`.
- `services/private-api/evaluations/pipeline.ts` — `EvaluationPipeline` facade composing `EvaluationJobStore` (M5.3): `plan(actor, input)` loads the stored evaluation binding, freezes the pair, enqueues public→private through `enqueue` (release-manifest image, published-check and harness authority re-checked per job); `candidateDiffFor` binds diffs to stored hashes; `applyFit` persists trusted fit outcomes under a guarded UPDATE (private_evaluating/owner_review only, all jobs terminal first); `status` bounded projection. **No evidence-writing path exists here** — signature verification and lease authority stay exclusively in `EvaluationJobStore`.
- `tests/acceptance/integration/pipeline.test.ts` — 17 unit tests: deterministic frozen pair, binding/kind/identical-descriptor rejection, per-unit mapping + traversal/forbidden/unmapped paths, diff determinism + rebinding rejection, fit outcomes (contract_failure vs package_defect vs unverified), advance truth table.
- `tests/acceptance/integration/pipeline-live.test.ts` + `scripts/verify-evaluation-pipeline.mjs` — real PostgreSQL: job lifecycle guards, infra-only queued completion, append-only results, binding immutability, stale-version denial.
- `tests/acceptance/integration/fixtures.ts` — shared descriptor/evidence fixtures.

## Limitations

- No candidate byte executes: the dedicated Linux KVM runner remains absent; jobs can only complete via `recordInterruption(..., 'runner_unavailable')` or stay queued. `test:runner -- --real` exits 2 `unverified`/`unavailable` as designed.
- `EvaluationPipeline` is a delivered library interface, not yet route-mounted (matches `jobs/store.ts` precedent — no Dockerfile changes needed since the built bundle does not import it).

The candidate-diff hash binds at M7.2 acceptance time against the same stored binding (result JSONB is immutable once set).
