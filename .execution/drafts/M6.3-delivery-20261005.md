## Delivered interfaces

- `services/external-api/submissions/patch-validation.ts` — strict unified-diff intake: UTF-8/NUL rejection, byte cap, `diff --git`/`index`/`---`/`+++` headers, `a/`-`b/` path agreement, portable-path and editable-allowlist enforcement, file/directory + case-fold collision checks, declared-hunk count validation, changed-line ceiling; rejects binary patches, mode changes, renames, symlinks, submodules and evaluator/manifest paths. Hash binds raw submitted bytes (CRLF normalized only for parsing).
- `services/external-api/submissions/protocol.ts` — Ed25519 sign/verify over canonicalized payloads; attempt-permit verification; signed export pull/ack request verification with audience, event/nonce, lifetime and replay-shape checks.
- `services/external-api/submissions/envelope.ts` — flat permit payload schema pinned by the foundation DB guards (permitId/submissionId/reservationId/taskId/taskVersion/packageDigest/submissionHash at top level) and the contributor submission envelope.
- `services/external-api/submissions/store.ts` — `SqlSubmissionStore.submit`: one atomic PostgreSQL transaction — advisory xact lock, account/reservation FOR UPDATE, idempotency lookup before state gating, published-contract binding, patch validation, contract-frozen `maxPatchBytes`/`maxChangedLines`/`maxEvaluatedAttempts`, lineage counter (cap 12), rolling workspace counter (cap 100/7d), permit sign, submission insert, reservation→in_review, outbox insert. `pullNext`/`acknowledge` provide the payload-hash-bound export queue. `EXTERNAL_SUBMISSION_EXPORT_DDL` byte-identical to migration 0006.
- `services/external-api/submissions/export-receiver.ts` — verifies signed pull/ack envelopes and applies them; malformed packets normalize to `invalid_request`.
- `services/external-api/submissions/routes.ts` — contributor `POST /v1/reservations/:id/submissions` (session + `submission.write`, strict base64, fixed safe error codes) and ingest `POST /v1/submission-exports` (no session; Ed25519 envelope is the authority).
- `services/private-api/submission-import/store.ts` — `SqlSubmissionImportStore.importPermit`: verified permit + approved release row (`private_release_approvals` → `private_revision`) + full binding match (task/version/package hash/submission hash/lineage/reservation) → atomic import row + `private_evaluations` creation; idempotent replay at the import row. `PRIVATE_SUBMISSION_IMPORT_DDL` byte-identical to migration 0009.
- `services/private-api/submission-import/importer.ts` — pull→verify→import→ack loop with crash-safe redelivery; no evaluation is created without a committed import.
- Migrations: `services/external-api/db/migrations/0006_submission_export.sql` (outbox `created_at`), `services/private-api/db/migrations/0009_submission_import.sql` (import table + guards).
- Bootstrap: submission + export routes mounted in `services/external-api/src/bootstrap/server.ts` and `main.ts`; importer loop wired in private `main.ts`; `assignment_delivery` internal network carries export traffic; submission permit keys provisioned additively by `scripts/synthetic-runtime.mjs`; external body limit raised to 2 MiB for the 1 MiB patch cap.

## Defects found and fixed during verification

1. Boundary checker rejected the validator under `packages/evaluation/` — canonical module moved inside the external intake boundary; the evaluation path is a re-export.
2. A NUL literal written to source as a raw byte silently turned `includes('\u0000')` into `includes(' ')` — every patch rejected. Expressed as `String.fromCharCode(0)`; all 11 patch-validation tests then passed.
3. `external_published_tasks` uses column `version`, not `task_version` — fixed the binding query (raw PG error surfaced via `cause` while the external code stays `persistence_unavailable`).
4. Fixture collided with `external_one_live_reservation` (unique per task+version while live) and the lifecycle guard (`cancelled` is terminal): fixture now retires prior live reservations and reuses the still-live `conflictRes` for rejection/budget stages.
5. Lineage cap from the budget stage bled into the concurrency stage — reset before the races so they exercise the reservation lock, not the cap.
6. The export-ingest route was reachable on the public contributor host — host scoping now permits ingest paths only under the internal `external-api:4001` host (403 on the public host).
7. Private release binding rejected a fixture approval whose manifest task/version mismatched the approval columns — fixture corrected to the real binding.
8. Migration file first landed at repo-root `db/migrations/` — moved under `services/private-api/db/migrations/` and baked into the image; journal byte-identity asserted by fixtures.
