# M7.2 draft handoff — owner review, controlled feedback and atomic acceptance

Status: checkpointed (assurance: tested). Local implementation is complete and verified; the task remains blocked for real-runner evidence and independent review.

Blockers: deferred_physical_runner, independent_review_unavailable

## Delivered interfaces

- `services/private-api/acceptance/store.ts` — `PrivateAcceptanceStore`: owner-only decisions inside one transaction. `accept()` re-verifies a live non-disabled owner session (`acceptance.approve`), locks the evaluation `FOR UPDATE` (must be non-superseded `owner_review` at the caller-pinned `expectedVersion` with `passed` result), and atomically writes: immutable `private_acceptances` row (recomputed candidate-diff hash from stored patch bytes + approved work units — never caller input), `private_payment_obligations` row at `due` with contract reward terms, `accepted` transition, and the allowlisted feedback outbox event. `reject()` → `changes_required` + feedback, no payable. `compensate()` → `package_defect` + `package_defect_compensation` obligation with `acceptance_id: null` (package defect, not submission acceptance). `pending()` bounded owner-review queue projection.
- `services/private-api/ledger/acceptance-transaction/record.ts` — transaction primitives + deterministic identity derivation: `deriveEventId(evaluationId, decision)`, `deriveAcceptanceId`, `deriveFeedbackPublicId` (sha256 over disjoint scopes — retries converge to `created:false`, never a second payable or feedback event).
- `services/private-api/feedback/policy.ts` — `renderPublicFeedback` + `feedbackCategoryFor` + `FeedbackPolicySchema`: strict `PublicFeedback` only (category, policy version, public check id + bounded message code from outcome). No canary/log/stack/score field exists in the output shape.
- `services/private-api/feedback/store.ts` — `PrivateFeedbackStore`: outbox write inside the caller's transaction; payload re-validated at write and read (`outbox_payload_damaged` on corruption).
- `services/private-api/feedback/delivery.ts` — `FeedbackDeliverer`: signed `external-feedback-delivery/v1` push to the external ingest; `delivered_at` only after a receipt-signed ack with matching `payloadHash`/`eventId`; everything else → `retry`.
- `services/private-api/acceptance/routes.ts` — owner routes: `POST /v1/acceptance/evaluations/:id/{accept,reject,compensate}` + `GET /v1/acceptance/pending`.
- `services/external-api/status/{store,receiver,routes}.ts` — `SqlExternalStatusStore` (idempotent `public_id` ingest, corrupted rows degrade to `feedback:null`), `FeedbackIngestReceiver` (signature/tamper/expiry/cross-audience verification → signed hash-bound ack), `installFeedbackIngestRoutes` (internal host only), `installContributorStatusRoutes` (`GET /v1/submissions/:id/status` → `schemaVersion/id/reservationId/state/version/feedback`; foreign submissions indistinguishable from absent).
- `packages/contracts/public/feedback-bridge.ts` — shared `FeedbackDeliverySchema`/`FeedbackAckSchema` for the private→external bridge (no cross-service implementation import).
- `apps/private-console/review/review-panel.tsx` — owner review tab: evaluation binding, candidate diff hash, fit/aggregate status, feedback preview, accept/reject/compensate controls. Data-only.
- Migrations: private `0011_feedback_submission.sql` (`submission_id` column, insert-required trigger, immutability extension); external `0007_feedback.sql` (immutability trigger on pre-existing `external_feedback`).
- `scripts/verify-acceptance.mjs` — live PostgreSQL guard verification.

## Limitations

- Every accepted evaluation is synthetic/tested pipeline evidence — no VM ever ran candidate code. The acceptance transaction machinery is `tested`/`bounded`, never `proved`; `test:runner -- --real` stays `unverified`/`unavailable`.
- `FeedbackDeliverer.deliverOnce` is a library interface — periodic delivery loop/wiring cadence is a later-operational concern; the signed packet + ack semantics are fully tested.
- The contributor status route replaced the pre-existing `resources.submission` placeholder mount in `main.ts` (and `resources.reservation` was dropped since `installContributorReservationRoutes` already owns `/v1/reservations/:id`) — mounting both crashed the service on duplicate registration; `verify-auth.mjs` expectations were updated to the new projection shape.
- `private_feedback_outbox.submission_id` is nullable to preserve 103 already-delivered synthetic events honestly; new inserts require it by trigger.
- The review console panel is implemented and mounted but not browser-verified end-to-end (no owner-review data in the synthetic DB drives it yet).
- Independent review unavailable; implementer-only checkpoint.
