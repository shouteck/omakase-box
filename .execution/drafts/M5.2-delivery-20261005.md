# M5.2 delivery draft — sandboxed jobs and adversarial runtime checks

Task: M5.2 (security_runtime). Scope: `infra/runner/jobs/**`, `services/runner-controller/isolation/**`, `tests/security/runtime/**`, plus sanctioned shared edits to `infra/runner/broker.py` and `tests/runner/protocol/broker_cases.py` (re-snapshot sweep applied to all stale manifests).

Assurance: `tested` for local components; `bounded` for static specs; `unverified` for anything requiring the deferred dedicated Linux KVM host. No candidate byte executed in a VM; no real-runner, independent-review or milestone-completion claim is made.

## What was delivered

- Guest harness (`infra/runner/jobs/harness/`): `records.mjs` (bounded LE-framed records, strict envelope/contract/request/response/result validation), `sandbox-spec.mjs` (pure fixed launch spec: unshare user/pid/ipc/uts/mount namespaces, cgroup v2 budget, mount table, device allowlist, scrubbed env, setpriv+prlimit inner argv), `container-init` (namespace init: rprivate, stashed 3-device private /dev, ro root, bounded tmpfs, ro binds of staged candidate tree + tooling, fixed inner exec), `driver-pure-module.mjs` (trusted verdicts from sealed expectation vs bounded observed value; `process.exit(0)`/forged stdout/monkeypatching can only produce `unverified`/`failed`), `observations.mjs` (authoritative observation vocabulary), `supervisor.mjs` (sole channel writer/key reader: envelope+artifact read, deterministic staging, cgroup budget, worker spawn/drive, Ed25519 signing of the strict ResultSchema).
- Tooling (`infra/runner/jobs/tooling/`): `build.mjs` (hash-bound JSON-bundle staging; contract lands supervisor-side only; real local execution verified by staging.test.ts), `worker.mjs` (candidate-side shim; carries no verdict authority).
- `infra/runner/jobs/guest-provision.yaml`: baseline image contract (packages, single pwuser account, root-only result key, no NIC/agent, supervisor-at-boot) — documentation of what the operator image must contain; `assurance: unverified_until_dedicated_host`.
- `infra/runner/broker.py`: `run` operation — strict per-operation key sets, full job binding (protocolVersion/profile/kind/harness/hashes/deadline/fixed limits), fresh-lease + artifact-hash + running-guest checks, virtio-serial channel exchange (connect-retry, bounded frame+result), observations stripped to a forensic file, quarantine on any channel fault; domain XML gains the single `org.private-task.control` channel, still no NIC/agent.
- Controller isolation (`services/runner-controller/isolation/`): `run-request.ts` (exact broker request + guest envelope + frame bytes + digest, honest `unverified` flags), `observations.ts` (guest-record classifier — only strict signed pairs are verifiable; faults and forgeries degrade to `unverified`), `adversarial.ts` (fixed 12-case catalog: good, network egress, file-read probe, output flood, infinite loop, process explosion, memory exhaustion, forged stdout verdict, forced exit-zero, assertion monkeypatch, cross-job persistence, signing-key probe — all honestly `assurance: unverified`).
- Tests: `tests/security/runtime/` — guest-records (envelope/contract/frame/protocol bounds, 23), driver (verdict authority, forged-value and containment semantics, 22), sandbox (spec/container-init cross-check, 10), staging (real local stageArtifact over every catalog case + hostile paths/budgets, 11), run-request/classifier/catalog (10) plus the 60 pre-existing plan tests; `tests/runner/protocol/broker_cases.py` gains 5 injected `run` cases (request shape, lease/artifact/guest gating, envelope contents, signed-pair pass-through, quarantine).

## Interfaces for the next agent

- Broker `run` response is exactly `{result, signature}` and feeds `provider.execute` → `verifyTrustedResult` unchanged.
- Guest envelope fields: `{artifactBytes, artifactHash, deadline, job, leaseId}`; artifact bytes follow raw on the same channel; result record = framed `{result, signature, observations?}`.
- Artifact bundle format: `{files: {relpath: base64}, contract?: {checks:[{checkId,exportName,arguments,expected}]}}` — `isolation/adversarial.ts#adversarialArtifact` produces valid bundles; M5.3/M7.1 attempt pipelines should produce the same shape.
- Only `pure-module/v1` evaluation is implemented; other harnesses yield signed `unverified`.

## Limitations

- No VM ever booted: supervisor/container-init/cgroup/virtio-serial behavior is statically reviewed and unit-tested at the pure-module and injected-broker level only. Real hostile-code containment, egress denial, resource bounds and disposal are `unverified` until the dedicated host exists.
- Independent review unavailable (sequential session): gate stays open; this draft needs coordinator acceptance before `.execution/handoffs/M5.2.md`.
- `writableBytesUsed` is honestly `null` (cross-mount-namespace measurement not feasible); enforcement is the bounded tmpfs itself.
- The result signing key, guest image build and supervisor unit installation are operator actions on the dedicated host.
