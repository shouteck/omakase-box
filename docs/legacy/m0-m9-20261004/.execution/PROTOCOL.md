# State, evidence and ownership protocol

Statuses are `pending`, `running`, `review`, `changes_requested`, `done`, `blocked`. Eligibility is derived from dependencies, never from a worker's statement. Only the coordinator changes canonical state. It increments attempt and records owner/lease at dispatch. Workers write separate drafts and evidence directories. A reviewer records decision against exact file digests or Git revision. Coordinator verifies prerequisites/evidence and finalizes `done` with the accepted handoff path.

Keep `.execution/state.json` as valid JSON, update atomically and preserve task IDs/schema version. A milestone is `done` only when all its tasks are `done`. Track each task's implementationStatus and independentReviewStatus separately. In explicit sequential fallback, checked implementations remain status review/not_available and may feed implementation-only successor work. They do not clear independent-review, milestone-done or final delivery gates. A handoff accepted at an earlier revision is stale if its scoped implementation changes materially; revalidate affected tasks/dependents. Recovered sessions inspect git/files/leases and reconcile inconsistent partial writes before dispatching more work.

Independent work may be concurrent when write scopes do not overlap. Shared `package.json`, lockfiles, schemas, migrations and integration wiring have a coordinator-managed lease. Workers request an integration edit rather than racing. Local commits may be created inside this dedicated repository after verified changes; do not push or open a PR unless separately requested.

On a blocker, record exact missing capability and the failed check, mark dependent paths unavailable and continue unrelated ready tasks. Do not mark skipped security or runner checks passed. If sequential self-review is the only option, preserve that fact and leave independent-review status unverified. No file-based state can keep a terminated runtime alive; the same START command resumes work.

Read accepted prerequisite handoffs, the task card, normative spec and relevant files. Every successor dispatch includes interface version, dependencies and required acceptance, rather than a vague instruction to continue. Evidence/handoffs for this synthetic build are source-control eligible; never commit actual customer data, keys, prompts or private runtime logs.
