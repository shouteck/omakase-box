How it works, with the by-hand tabs open

The same page with the second tab chosen in both halves: for a person who will not use the tool.

  1. 1
    Without installing: four plain steps. Sign in with GitHub; paste the issue's address and set a reward; solvers answer on GitHub with "Fixes #12"; you choose whom to pay. The address is shown as an example so nobody has to guess its shape.
  2. 2
    By hand no longer speaks our jargon. Today's step says only "box-bounty/<id>, on the bounty's repository". Now it says what that is (the branch the bounty was posted on, named on the bounty's page) and gives the exact Git commands to fork, fetch that branch, and push.
  3. 3
    It says where the pull request goes: into the owner's repository with the bounty's branch as the base, not main. That is the mistake a person working by hand is most likely to make.
  4. 4
    One line covers the simpler kind: a bounty listed from an existing issue takes a pull request against the usual branch with "Fixes #12". The bounty's own page says which kind it is.
  5. 5
    For you to check: all the by-hand wording is new and mine, taken from what the bounty page and the listing window already say. The Git commands are written to be safe with today's branch names; I have not run them against a real bounty.
