The site, before and after, with the reason for every change

You were right. Seen at full size, the site you have is good, and most of what I drew made it worse. This pass keeps your design and changes four things.

What I got wrong the first time

  • I judged the site in a narrow window. My review looked at it about 800 pixels wide, where inner pages stack into one column. At a real laptop width they use the full page, as the "before" pictures below show. "It reads as two sites" came from my window, not from your design.
  • I redrew pages from scratch in place of starting from yours. That is how the front page lost its tiles and How it works lost "Your agent takes it from there".
  • I proposed layouts you already have. A bounty's page already has the task on the left and the reward block on the right. The board's rows already lead with the title and a quiet line of facts.

How this pass is made: every "after" is your real page with a small patch applied in the browser. Anything a proposal does not mention is unchanged by construction.

Front page

Every section stays: the picture, From stuck to merged and its five tiles, Some things it never does, the ways in. Two things are added.

  1. 1
    The install line sits under the two buttons, with a copy button. A developer who is already convinced can act without a second page. The buttons stay for everyone else.Reference: Bun puts its install command in the first screen with a copy button; so do most developer tools that are praised for their pages.
  2. 2
    A third way in: "Maintain a repository?" You built listing an existing issue (no install), and the front page never mentions it. It joins "Have an agent?" and "Want to solve?" as an equal third, in the same tile.
  3. 3
    The top bar: mark A, the name, one button. See section 5 for the reasons. On the front page this means "Get started" appears twice on the first screen; Resend and Linear do the same, but tell me if it reads as too much on a phone.
  4. 4
    Not visible in a still picture: the picture is there from the first moment. Today each line of the terminal is invisible until its turn comes (up to four seconds), so a slow phone first shows an empty dark box. The fix keeps the motion and starts each line visible. This is a one-line change to the animation.

How it works

"You install it", "Your agent takes it from there", "If a reward is owed" and "The details" are untouched. One part changes.

  1. 1
    "Answer bounties" takes the same shape as "Your agent takes it from there". Today the owner's half is a panel of cards and the solver's half is a numbered list that fills the left 40% of the page and leaves the rest empty. Using your own panel for both makes the two halves read as equals and uses the width. The words inside each card are the page's own, unchanged.
  2. 2
    The panel needs a title and one line. I wrote "Three steps, with your own tools" and "You install nothing from this page. A GitHub account is enough." The second is a fact the page already states. Both are yours to reword.
  3. 3
    What I am not sure of: the numbers 1, 2, 3 go away, as they did for the agent's four cards. If you want the order to stay explicit, the cards can carry a small number.

The board, when it is empty

This is the one screen I would call unfinished, and it is the screen most early visitors will see: "Browse bounties" on the front page leads here, and at launch the board lists nothing.

  1. 1
    Show what will be here. One row drawn exactly as a real bounty's row, marked "Example". A visitor who has never seen the board learns what it is from the thing itself.You cleared test records from the live board, so this is drawn by the page and never stored, never in the feed. If you would rather have no example at all, the row goes and the rest stands.
  2. 2
    Say how a bounty gets here, twice. The two tiles are the front page's own: "Have an agent?" and "Maintain a repository?". An empty board is the moment a visitor is most likely to ask "so how does one appear?".
  3. 3
    The grey box goes. A filled, bordered box is how the site draws a code block and a poster's words. Used for "nothing here" it reads as an error message.
