# Git defences

Read again from the references on 26 November 2026. This table is the pinned contract for the bounty tool's Git layer. One row is one defence. The test reads the rows and compares them with the real arguments and environment captured at the Git seam.

Call classes:

- `git-version`: the `git version` probe.
- `all-repo`: every product Git invocation that runs with `-C <repository>`, including the configuration read, object and reference plumbing, worktree calls, network calls and the publish plan's stdin helper.
- `foreign-content`: a call in foreign mode that can read or write worktree content or the index. Object-and-reference-only operations are exempt because neither a filter nor a merge driver can run there.
- `diff`: a `git diff` invocation.
- `owner-merge`: the dry merge and the merge that lands a solution on the owner's branch.
- `github-https`: a fetch, push or clone whose arguments contain `https://github.com/`.
- `solution-fetch`: `collect.ts` fetching `refs/pull/<n>/head` into the owner's repository.
- `take-clone`: `take.ts` cloning the stranger's bounty branch.
- `take-fetch`: a later fetch of that bounty branch in the taken workspace.

## Boundaries this table does not move

- The owner's own fetches, including shared memory and the publish plan, do not get stranger-object fsck settings. They are not solution intake.
- Owner-content calls keep the owner's configured filters and merge drivers. Foreign-content calls blank them per invocation. No product call writes global or repository configuration.
- `GIT_ALLOW_PROTOCOL` is only for the stranger clone and its later bounty-branch fetches. It must not be set on calls that may use the owner's own SSH remote.
