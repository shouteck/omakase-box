THE FIX
  if ! systemctl restart fruitd; then
      echo "deploy.sh: systemctl restart fruitd failed" >&2
      exit 1
  fi
  echo "fruitd restarted OK"
  systemctl is-active fruitd

WHY THIS SHAPE
- `if ! systemctl restart fruitd` keys the report on the restart's real
  exit status, which was the whole bug — the old script ignored it.
- Error goes to stderr (ops-script convention) and `exit 1` gives the
  required non-zero status.
- `systemctl is-active fruitd` is the canonical one-word answer to
  "what state is the service in"; it prints e.g. "active" on stdout.
- As a bonus it keeps the script honest end-to-end: if the restart
  "succeeds" but fruitd is not active afterwards, is-active exits
  non-zero and that becomes the script's exit status, so deploy.sh still
  cannot report success while the service is down.

VERIFICATION (stubbed — real systemctl only exists on the pantry host)
- restart succeeds, service active → prints "fruitd restarted OK" then
  "active", exit 0.
- restart fails → systemctl's own stderr + "deploy.sh: systemctl restart
  fruitd failed" on stderr, exit 1, no OK line.
- restart succeeds but service inactive → prints "inactive", exit 3
  (is-active's status propagated).
- `sh -n` passes; committed blob is LF so the #!/bin/sh shebang is clean
  on Debian.
