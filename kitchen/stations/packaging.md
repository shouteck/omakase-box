# Station: Packaging

Selecting source for a Box, exporting it as a folder, proving it in a clean directory, submitting a patch from it, verifying that patch in the owner repository. D2/D3.1 and declared-command checks are built. A1 makes agreements neutral; A2 makes selection explicit and compares full-base/Box observations. A3 makes declared commands sufficient for neutral orchestration; ecosystem generation/install/compile remains explicit opt-in only.

## What this station knows

- A Box is a plain folder with `box.json`, selected source and declared setup/check commands. Prerequisites are arbitrary programs. Neutral A3 export/verify needs no pnpm or generated files; private-shop fixtures explicitly opt into the retained nodejs helper. Paired recipient checks require the same sourceRoot-relative paths in full base and Box.
- Name negative candidates by the actual source mutation. A cosmetic unused parameter is not the removed-parameter/unchanged-caller probe; a green alternative solution is not a wrong candidate.
- The design for the first fixture is in `docs/box-v4/delegation/SUPPORTED-CASE.md`: the `examples/private-shop` fixture, two supported requests (A: response security policy; B: deterministic ranking), the modules that must be absent from the export, and one unsupported coupling case.
- Reuse before writing: `packages/box-contracts` (Box schemas and hashing), `packages/analyzer` (import scanning), `packages/evaluation/patch-validation`.
- A2's `files` is the sole owner-source shipping authority. TypeScript `proposeSelection` supplies suggestions from entrypoints, never implicit export inputs. Owner-selected dependency files retain their bytes and provenance; optional generated helpers cannot overwrite them.

## Milestone BT: the bounty tool (from 10 October 2026)

The station's work is now the bounty tool: creating a bounty (the whole repository as a snapshot, never-ship files removed, with the task, the hand-off note and the check), the record that outlives the agent, taking an answer back, and telling agents the tool exists. PLAN.md has the journey and what is settled. A bounty folder is a Box of a new kind; reuse the Box's manifest, hashing, path handling and program launch.

- **The whole repository goes out, so never-ship is the security boundary.** Check each file's real path, fold case on both pattern and path, refuse links that leave the repository, and never list removed files' names inside the bounty. `packages/box-bounty/never-ship.ts` holds the rule table (C1 lesson folded in). Known still-shipping credential spellings left to the owner's `.boxignore`: `.kube/config`, `credentials.json`, `wp-config.php`, `id_x25519`, `backup_id_rsa`, `.env2`, `env.local`. The `secrets` rule matches any *segment* containing "secrets", basenames included — a legit `docs/secrets.md` cannot ship; tighten to directory segments if that bites.
- **Emitted bytes must equal the recorded identifier.** `bounty create` writes `repo/` from the snapshot commit via `git cat-file blob`, never the live worktree — one decision killed the TOCTOU, junction-swap and autocrlf findings. Keep it: a bounty whose bytes can drift from its identifier cannot be verified later. Corollary: clean filters (git-lfs) ship filtered bytes.
- **The snapshot commit keeps removed bytes reachable.** Never-ship files are absent from the bounty folder but their blobs sit in `.git/objects` under `snapshot.commit` until `gc` — required so the identifier resolves later; stated in BOUNTY.md, never a leak outside the machine.
- **A bounty outlives the agent that made it.** Anything a later session needs is written in the record, never left in a conversation.
- **Every outcome is a named state with a next step.** An empty or ambiguous answer from the tool cost a whole live trial once.
- **Wording is product.** A tool an agent is only told exists was not called; the description and the lines in a project's rules decide whether it is used. Test them by cold read.
- **The answer is verified against the version the bounty was made for, then brought forward.** Code moves on while a bounty is open.

- **Facts, never verdicts.** The tool says "the check you set now passes", never "this answer is correct". A wrong fact is a bug that can be found; a wrong verdict misleads and cannot be traced. Reports always say what was not checked.
- **Mechanical work is the tool's; judgement is the agent's.** Three decisions belong to the agent: hand off or not, what the task is, accept or not. Anything else a command asks the agent to supply is a defect to remove.
- **Discretion, not enforcement.** Nothing requires an agent to use the tool. How it is described decides whether it is used: published work found wording alone changes use tenfold, that more detail is not better, and that agents both overuse and ignore tools. Say what it does, when it is worth using, and when it is not.

## The product after 11 October 2026

- **Nothing a solver wrote is ever run by the tool.** There are no checks. If a change would execute something from a solution (a command, a hook, a filter, a merge driver), it is wrong.
- **The unsafe-command preflight (`git.ts` `unsafeOwnerCommands`) models what executes, not which programs exist.** BT6b took three passes to learn it: Git runs configured filter/driver values through `sh -c` (every separator/substitution starts a new command), a bare interpreter reads its program from stdin, `git` re-enters through aliases (`alias.*` and `-c`-injected), includes resolve against their own file's directory with `~` expanded, and launchers (`npm`/`make`/…) read their program from an in-repo manifest. The convergent rule is converse: once a program places outside the tree, every operand that decides what executes must place or recurse. Enumerating dangerous programs loses — `find -exec`, `tar --use-compress-program`, `wsl`, `ssh` are unbounded.
- **`rev-list --ancestry-path` is not "did it land".** For a commit that reaches a branch inside another branch's merge it returns nothing — the right shape for "the merge that carried X into first-parent history" is a binary search of the first-parent chain with `merge-base --is-ancestor` (containment is monotone tip-ward). BT7b-1 shipped the wrong shape and the pass's nested-merge attack caught it.
- **A good agent avoids the clash.** Two fresh journey agents read `look` diffs, saw the best solution diverged from in-flight work, and applied the clean one — the clash refusal may never fire for them; its UX value is protecting the agent that doesn't look. Journey evidence lives in the transcripts; build scenario fixtures where the best solution is *unambiguously* best or agents will rationally route around the path you wanted to watch.
- **Fixture hosts carry the owner's global config.** This machine's `~/.gitconfig` names `filter.lfs.*` — any stripped-PATH fixture hits unplaceable-command refusals unless a resolve-only `git-lfs` stub is on PATH (`github-fixture.ts` `withoutGh` has one). And K14 counts Git process starts: a new check must ride the pin layer's single `git config` read, not spawn its own. K14 measures the **built `dist`**, not the source — rebuild before trusting or pinning any start count (BT20).
- **Three GitHub stand-ins exist and a response-shape change touches each:** `tests/box/bounty/github-fixture.ts`, `tests/box/bounty/bt7-ux-fixture.mjs`, `kitchen/demo/gh-standin.cjs`. BT16 added `permissions.push` to the `repos/` answer and had to fix the second stand-in mid-wave; the third still lacks it because no suite drives it (K18's `page=` drift was the same class). Before changing a shape, grep all three.
- **Three hard stops, nothing else enforced:** never-ship, no private repository outside, the owner's standing rules. Do not add a refusal that polices a choice.
- **A stranger's words are not the tool's words.** Output that an agent sees without asking carries only what the tool generated. Text from a solver appears only when the agent asks to look, marked as the solver's.
- **Removing a capability means deleting it,** with the tests that covered only it listed in the Result. Not a switch, not a bent assertion.
- **Stored outside text is a replay surface.** BT7c's only real hole: a pre-wave record's `github.outside.answers` field was replayed verbatim through `status`/`describe`/OPEN/rules-block and could still print a removed command's name, long after the render paths were clean. When commands are renamed or removed, every stored free-text field the tool can print later needs the same migration scrub as `pending` — scanning rendered messages alone misses stored state. `asRecord` in `packages/box-bounty/record.ts` is where the scrub lives.
- **Record and status text must claim only what the tool verified.** BT8c's first FAIL: a folder post settled a scan finding as "the content changed" while the delivered bytes still held the secret — name the check state ("not re-checked"), never who acted, and keep findings visible on ended records in every status form.
- **A failed measurement must say nothing, not a wrong fact.** BT13's pass found `mergeTouched`'s diff-failure path returning an empty set that `partial` then reports as *every* solution file left-as-were, and a conflicted-`allow`-then-hand-merge still marked "not asked" — the comments promise silence, the code reports a conservative wrong fact. Check the comment's promise on the empty/failure path, not just the happy one (both in `packages/box-bounty/merged.ts`).
- **Fresh-reader and measurement trials have a reusable fixture:** `tests/box/bounty/bt8b-fixtures.mjs` builds per-case repos plus isolated settings under one owned temp root from the built CLI of the exact candidate SHA, freezes real captures, and refuses to clean anything it did not make. CTO dispatches the readers; the pass re-drives the frozen CLI itself.
- **Fresh agents did not reach for a removed command.** Six after-runs of BT7c's measured journeys: zero `command-removed` invocations — `look --from` collecting and reading in one step was discovered from output alone. The post journey went 6→5–6 commands, the collect journey 11–12→7–9. Folding steps into the decision commands (`look`/`apply`) is where the commands actually saved came from; dead-end removals (`undo`, `reply`) cost nothing because output already named what to do instead.
- **No token-shaped literal in tracked source, anywhere — including wave files.** BT8's reviewed commit was rejected by GitHub push protection twice: once for a `glpat-` fixture in `bt8.test.ts`, and a second time for the same fake value *quoted inside `waves/BT8.md`* while describing the first rejection. Push protection scans every commit's bytes, so a fixup commit is no escape — the literal must never exist in any pushed commit. Build every scan-pattern value at run time (`'glpat-' + parts`), keep doc examples describing shapes rather than containing them, and run the tool's own `scanText` over added diff lines before pushing. `tests/box/bounty/secret-literals.test.ts` is the standing guard: it runs the scanner over every tracked test file and names any hit. Do not click the unblock URL; remove the bytes.

## The real post (BT6 Part C, 11 October 2026)

- **The GitHub journey works end to end for real:** preview → `allowedDestinations: ["github"]` → `confirm --to github` → `post --to github` → blind solver PR → independent collector's `answer --pr` → `apply`. Issue #1, PR #2, merge `48b461c` on `shouteck/omakase-box`.
- **Verify outside state independently, never from the tool's word alone.** `gh api` and `git ls-remote` confirmed issue/branch/label/PR facts at each step; a draft, preview or local record proves nothing was posted.
- **A long silent `gh` call is normal, not a hang.** `answer --pr` ran ~2.5 min silent fetching on this host; `post` ran ~4 min packing 3,903 blobs via plumbing. Tell collectors to expect it; a progress line is a later nit.
- **Never write JSON values containing `$` through `node -e` inside a double-quoted shell string** — bash expanded `$0` into `.box/limits.json`'s `cost` line and only the collector's read caught it. Use file edits or single quotes. (Head-chef process lesson; the public issue was unaffected.)
- **`allowedDestinations` gates both directions:** `["github"]` alone refuses `post --to <dir>` until the owner names a directory — say so when showing limits to the owner.

## The real post (BT6a, 11 October 2026)

- **A bounty is an issue on the code already on GitHub.** `post --to github` pushes only what was not already public: unpushed commits the task needs, plus one `work in progress` commit for uncommitted work when `--with-changes` is chosen — never a repository snapshot. Solvers branch, push and PR like any contributor; the bounty branch's tip commit is what `answer --pr` checks PRs descend from.
- **The approval binds the whole working state, and the tool's own bookkeeping breaks it.** `confirm` records the plan, then its stage transition writes the `AGENTS.md` open-bounties line and `OPEN` — tracked files that `--with-changes` re-scans at `post`, so the rebuilt WIP commit never equals the approved `tip` (`github-preview-stale`, deadlock by design). Workaround used live: `git checkout -- AGENTS.md` between confirm and post; the same family left WIP bytes in `answer.ts` that tripped `apply-worktree-dirty` at collection. Fixture repos miss it because their bookkeeping is untracked. **Any re-plan at post must compare the recorded path lists, not the live dirty set.**
- **`undone` is terminal.** `undo` writes a revert commit and ends the record; `apply` refuses `already-ended`, and the outside issue stays closed (the tool comments the undo then PATCHes closed unconditionally). The BT6a brief's rehearsed apply→undo→apply→close journey was impossible from the start — a wave brief asserting a journey must be checked against `EndedStage`, not assumed.
- **Closed-by-base-deletion reads as rejection.** When the tool removes the bounty branch at close, GitHub auto-closes the PR unmerged with no comment — the outside trail says "rejected" where the issue comments say "applied". Carried nit: comment on the PR at close.
- **Test fixtures that run lighter than the real repo hide bookkeeping collisions.** The deadlock and the dirty-WIP block only appear when `.box/bounties/OPEN` and the rules file are *tracked* — fixture repos never hit it. Real-use journeys exist precisely for this gap; record the workaround, then fix root cause.

## Tracing a failing test (wave C1, not used by milestone BT; kept for the smaller Box later)

The station now also covers tracing a failing test, choosing a Box's files from the trace, and the hand-off and return. Two product rules apply to every wave here: nothing leaves the owner's machine without the owner's yes, and never-ship files never enter a Box.

- **Identify a function by its file and the line its definition starts on, never by name.** The lab's first tracer marked a property setter as run because the getter of the same name had run.
- **Follow the test into every process it starts.** Five public tasks produced no usable trace because their tests ran in child processes.
- **Trace calls, not lines.** Line tracing of whole test files hit five-minute timeouts; call tracing of one test took about two seconds.
- **A line that ran is not a function that was called.** A definition line runs when its file is loaded. If a later wave reads a standard coverage report in place of the tracer, treat hits as regions, and leave anything uncertain unmarked.
- **A wrapper must behave exactly like the command it wraps.** The lab's search wrapper ran a search to completion before passing output on, which changed what a piped command returned and went unnoticed because the check replayed old commands. Test the commands an agent actually types, including pipes and early exits.
- **Offered is not used, and empty costs.** A tool an agent is only told about was not called; a tool that could return nothing cost real steps. Put the hand-off in the path of what the agent already does, and pilot one real use before any batch.
- The tracer prototype is on the `lab` branch (`lab/lines/box-trial/`). Read it with `git show origin/lab:<path>`; do not import from it. The product tracer is `packages/box-trace` (C1): a `sitecustomize.py` hook on `PYTHONPATH`, `sys.monitoring` primary with `settrace` fallback.
- **Traced is not all that ran.** `processes` counts reported processes; a Python child still running when the command exits writes its record after the merge and is silently absent. Cross-process `order` groups per process, never wall-clock. `no-python-process` conflates `-S`/`-I`/`-E`, `python --version`, `os._exit` and killed children.
- **The hook dir must not sit under the run root.** With cwd an ancestor of the hook's temp dir, the trace lists `sitecustomize.py` itself as repository code.
- **No `box` binary exists.** The command is `node packages/box-cli/dist/cli.js` after a build; doc pages and tests must say so.

## Traps

- **Workspace links and frozen installs:** missing dependency declarations can work via siblings, so prove a package outside the checkout. Pinned pnpm also backfills absent empty workspace importers during --frozen-lockfile, dirtying Git; K7-ci's importer-parity regression guards new manifests. Adding workspace package.json files requires root lock parity even with no dependencies.
- **Windows paths.** This machine uses backslashes and the recipient's may not. Store paths in the Box with forward slashes, build them with path functions, and test both forms. `realpathSync` does not expand 8.3 short names: `GIT~1` stays `GIT~1` in the canonical path while resolving to `.git` on disk (BT26's pass wrote into `sub/.git/config` this way). Only the parent's `readdir` — a case-insensitive name match, else the entry sharing dev+ino — reveals the true name; segment checks must run on the re-spelled path as well as declared and canonical spellings.
- **The silent fallback.** If export cannot find something, it reports a named preparation gap. It never reaches back into the owner repository to fill the hole, and exporting the full source can never count as a pass.
- **The clean directory must be outside this checkout**, or module resolution will find the repository's `node_modules` on the way up.
- **Exclusion runs on the canonical path, not the spelling.** Two D2.1 bypasses proved it: a case-aliased entrypoint and an in-root junction both shipped `src/private/*` bytes while the declared path looked clean. `realpathSync` before BOTH the containment and the exclusion check; fold case on both sides; emit under the canonical path only. Note Windows realpath keeps declared case, so alias spellings can still reach emission on non-excluded paths — normalize if patch mapping ever sees them.

- **A clean install proves nothing.** With a needed sibling package missing, `npm ci` and `pnpm install --frozen-lockfile` both exit 0 and leave a dangling link (A0). Only a check that loads the code shows the gap.
- **`check` never reaches the box suites.** Its diff-reach map has no entry for `packages/box-package/` or `tests/box/`; `verify --full` alone proves nothing about this station's code. Briefs here must name `test:box-package` (and `test:box-*` as applicable) so the suite actually runs.
- **Splitting a hub: the hub's callers-out decide the new modules' inbound edges.** BT25 moved a shared helper to the lowest module that uses it, not where the layout table guessed, and gave record.ts's outward calls (read-scan, surfaces sync) registered triggers rather than imports — the `setMergeNoticeListener` seam shape. A mid-move cycle means the placement, not the wave, is wrong.
- **Plan the inner loop by file, not suite.** A full `--suite bounty` run is ~10–15 min on this host, dominated by `github.test.ts` (~80 s); iterate with `node scripts/suite.mjs box --suite bounty <file.test.ts>` (the path is repo-relative — `tests/box/bounty/bt22.test.ts`, not the bare filename) and save the full suite for pre-commit (BT21/BT22).
- **Equal red exits are not equal failures.** A2 pairs declared recipient checks in full-base/isolated-Box contexts and compares result, exit and full normalized decoded-text digest. Never compare display tails. JSON tuple framing separates stdout/stderr even with embedded NULs; beyond-tail and NUL-partition regressions caught two wrong implementations. Matching diagnostics remain observations, not causal proof.
- **A4 Windows npm declaration:** bare `npm` resolved an unspawnable extensionless shim on this host; fixture setup declares `npm.cmd` with `--ignore-scripts`. This is a host-specific recipe, not a portable executable claim. A4 proves npm/Python capability with unchanged core, immutable checks and retained pristine manifests; fixture checks are purpose-written and npm non-string inputs remain uncovered.
- **Windows shim quoting can silently change argv.** A1 dispatches `.cmd`/`.bat` by file kind through the system shell, not by tool name. Unsafe tokens, including trailing backslashes, are refused before spawn; embedded backslashes and supported metacharacters have real subprocess tests. Do not broaden quoting without negative tests.
- **Read a merge without running one with `git merge-tree --write-tree`** (git ≥2.38): exit 0 means clean, conflicted paths are named, and worktree/index/branch are byte-for-byte untouched — no scratch clone needed. A revert built on the real index must refuse on staged changes first.
- **Merging foreign bytes into the real repository is a boundary, not a call.** A refused `git merge` can still smudge worktree bytes (autocrlf), and merge ignores untracked *and ignored* files at touched paths — byte-identity after abort needs save/restore of raw file bytes, not a config pin. `git status --porcelain` `??` entries can be directories, and leading-space status columns vanish under `trim()` — parse `-z` untrimmed. Test the default state (`git add -A` in a fixture hides untracked dirs like `.box/` and can mask a whole crash class).
- **Git output uses a third path dialect, and it folds.** Beside worktree spellings and canonical shipped names, `git diff`/`ls-tree` emit *tree spellings* (junction-tracked paths under the link, not the target) and `diff.renames` silently drops rename sources from `--name-only`. Any classification, touched set or gate that reads git output must canonicalize *and* pass `--no-renames` — `undo`'s folded touched set clobbered an ignored file at a rename source (BT3b). Judge deletions by the *base tree's* spellings (`ls-tree` of the base commit), never by live-disk resolution — the disk shows whatever link replaced the path. A rule-covered canonical must not suppress a rule-free base spelling's change.
- **Junctions leave no git artifact.** No tree entry, index flag or diff token — a link planted before or after `baseCommit` is indistinguishable at git level (only forgeable, non-portable reparse-point metadata differs). Where the note cannot know, it must err toward reporting a change, never toward the all-clear; the indistinguishable family is recorded in `waves/BT3b.md` Result.
- **Facts the tool writes are only as true as the path dialect they were computed in.** The composed note's "matches the last commit" / "differs only in files that do not ship" survived four pass rounds because each fix classified one more dialect correctly. A claim that can be false is a defect; phrase the fallback to claim only what was proven.
- **A scenario's premise must be a shown fact, never an inference.** BT4's S2 failed review because "the site's solvers hold the access" was assumed, not stated — a probe declined on exactly that gap and the scenario couldn't tell a wording failure from a premise failure. Every scenario's sensible behaviour and each avoid-move's true reason must be verifiable inside what the agent is shown. The comparative runs are what caught it: prose review had read past it.
- **The owner-away scenarios all hinge on one distinction:** creating a draft is free, only posting needs the owner's yes — `describe` says it in one clause and `describe`'s "worth it / not worth it" shape (candidate A) out-performed a trigger-list wording without producing a single overuse. Wording lives in `packages/box-bounty/wording.ts` alone so a tuning swap touches nothing else; rejected candidates stay in `kitchen/scenarios/bt4.md`.
- **A declared setup must bootstrap from nothing.** A shipped snapshot carries no `node_modules` — BT5's first real create died assuming repository-local pnpm existed. Setup scripts name the toolchain bootstrap first (`npm ci --prefix scripts/tooling --ignore-scripts` before `scripts/pnpm.mjs`) and the task file must say the same; prove them in a copy with `.git`, `node_modules` and `dist` deleted, not in a warm checkout.
- **What setup creates, the solver must remove.** `answer` refuses any link or non-file inside `repo/` (`answer-unsafe-path`) and counts every install/build artifact as `added` — a solver that follows the README literally returns an unanswerable folder (BT5 journey finding #2, recorded unfixed: solver-cleanup docs vs an answer-side artifact rule is a product decision). Until then, a returned folder needs its derived trees stripped before `answer`.
- **A scenario's missing capability must be unfetchable.** BT5's needs-toolchain fixture used `php` — absent locally, but a public download; both rung agents provisioned it and declined the bounty correctly. A premise that stands in for licensed access fails if the capability is obtainable: use a credential, a network-restricted service, or something the owner's environment alone can supply.
- **A bounty is only viable where its check can pass.** `answer` verifies on the owner's machine — a task blocked by a *missing local* toolchain can never return a passing answer, no matter how good the solver's fix (a rung-2 agent derived this itself). `describe`'s "worth it" reasoning should eventually say so; recorded in `kitchen/bt5/evidence/rungs.md`.
- **Long foreground runs need a heartbeat on this host.** The exec host backgrounds any command silent for ~10s with no output poller — `scripts/verify.mjs` (~6 min) only completes via a `$TEMP` log + ticker loop, and `git stash push -- <path>` is the clean way to hold a reviewer's uncommitted verdict past verify's clean-tree gate.
- **Repo-local tool state collides with "create changes nothing."** `.box/bounties/` is written inside the repository by design (BT2), so the shared test `fingerprint` excludes `.box`; anyone adding more repo-local state must update it or the byte-for-byte test fights the feature. `.box` is a never-ship segment — records never enter a later bounty. The record is a JSON convention, not confinement: an agent can hand-edit `stage`, so `confirmed` gates workflow, not access.
- **The box suites assert Windows-only semantics.** Junctions (invisible to git there, visible links on Linux), `.cmd` command-file launch (refused off Windows by design), the A4 `npm.cmd` recipe, and a case-insensitive filesystem. K10 marked those tests host-only by platform or capability probe so the suites run off-machine; on Windows they still execute. Briefs naming Linux runs must expect these skips.
- **Preflight all contexts before any declared setup.** Stage recipient files first, resolve owner and recipient programs plus prerequisites, then run commands. A1's sentinel regression catches the per-context ordering bug; missing recipient tools must not follow owner setup side effects.
- **A copy of a stranger's tree is a second boundary, with three questions (BT7, parked).** What may run there: a linked working tree shares the owner's configuration, so plain Git typed by the agent runs the owner's filters, and a filter program that lives in the tree is the solver's once the solution replaces it; pinning the tool's own calls does not cover the agent's. A repository of its own with `info/attributes` (it outranks every `.gitattributes`) and no hooks path closes that, except for a bare-repository layout shipped inside a folder. Which byte form lives there: written with conversions off and read back with them on changes untouched files (autocrlf, encodings); a filter-using repository has two byte forms, so say per command which one it handles and test each in such a repository. What is checked on the way back: judge never-ship and paths on the tree that lands, never by asking Git inside the copy. Also: `git worktree remove` deletes contents before registration and fails on Windows while a process sits in the folder; an empty `diff.external` breaks `git diff`; one git start costs 30 to 90 ms here and a fixture test makes 150 to 250 of them.

- **First-merge notices follow the receiving repository.** Test independent bounties through both direct apply and recognition, a changed remote/fork, and a local repository gaining a readable address. Reapplying one terminal bounty does not prove once-per-repository behavior. In owner-facing relay text, name the agent as the actor choosing the solution; cold paraphrases exposed the implied owner choice in BT8a.
- **A path the tool writes needs a component walk, not `existsSync`.** BT9's `hook on` followed a dangling settings symlink outside the project because `existsSync` is false when the target does not exist — the escape check never ran. `lstat` every component of a tool-written path, link or not, existing target or not (the instructions.ts walker already does this; reuse the approach).
- **Anything the tool prints from its own records is hostile input on second read.** A solver PR merged onto the owner repo can land a `.box/bounties/*.json` — BT9 printed a tampered record's `id`/`branch` verbatim into agent context. Shape-check every field that can reach outside-facing text at the `asRecord` boundary, and degrade a bad record to a named corrupt fact, never injected text.
- **What goes public later must read what already went public, not the editable record.** BT11a bound the reward on the record at post, then re-rendered it into the issue block at close — a hand-edited `record.reward` reached the public block while the listing still showed the true amount. `boundAmount` now reads the `amount` inside `record.github.body` (the artifact GitHub accepted), and close PATCHes only `state` into the live block. Same family: `github.body` is still re-POSTed verbatim on a resume where the issue was never created — a crash-window replay surface, in BACKLOG.
- **A fixture that mints commits must make each one distinct by construction.** Git timestamps resolve to one second: `github-fixture.ts`'s `pr()` produced byte-identical commits for two solver PRs in one second — same tree, parent, identity and message — so dedup-by-SHA silently picked the wrong merge and cost a red master run (BT11b). Fold the request's number into the message. And a demo that needs a fake GitHub: `kitchen/demo/bt11b-replay.mjs` shows the `gh` stand-in + `git` PATH-shim pattern — a full post→PRs→merge→close journey with no sign-in and no network.

## The pass checks

- Run export and declared checks outside the repository. Shared test setup must be invocation-local and isolated for mutation; try poisoned/preseeded cache bytes before trusting a speedup (K6 failed this check).
- Confirm the excluded modules are really absent from the package.
- Try each negative: omitted dependency, path or link escaping the selection, unlisted input, edit outside the editable paths, wrong base commit, altered agreement.
- Record the share of owner source the package disclosed.
