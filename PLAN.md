# Open Box delivery plan

The CEO chose Open Boxes first and reuse of existing work. Git remains durable history. Box Web is the control surface; an existing editor/workspace is the execution surface. Humans and agents consume the same Box protocol. The old restricted-delegation implementation is an asset, not the active backlog.

## Run the plan

Invoke [START.md](START.md). It selects next unfinished work from [the B-series graph](tasks/box-v4-task-graph.json) and [active state](.execution/box-v4/state.json). Before every new wave, the CTO and station leads brief the CEO and wait for explicit approval.

Each milestone has two bounded units with dependencies, owner, files, delivered behavior and verification. A wave may contain several ready units and is not synonymous with a milestone. Native Cursor pstack is adapted to project policies; Codex uses the labeled fallback. This plan is not implementation approval.

## Product ladder and gates

The supplement's stages 0-1 become the nucleus and Open Box lifecycle. Stages 2-3 add Web/workbench and team operations. B1-B3 form the nucleus gate; B4-B5 form the useful workbench gate; B6-B8 form team delivery. Present evidence and obtain a new CEO wave approval at transitions.

[Later research](docs/box-v4/RESEARCH.md) retains stages 4-7: restricted disclosure, semantic transformation, external routing and optional bounties. Dedicated hostile-runner/release gates remain unmet and cannot be renamed away. Passing B8 does not authorize later-stage implementation or real participant studies. A twelve-week programme in the supplement is a planning hypothesis, not an agent deadline.

## Delivered software

A trusted synthetic/non-sensitive repository has real Git history. A PM's goal becomes approved behavior and a versioned Box. A human or agent opens its pinned environment, makes an attempt, runs visible checks, submits an actual diff, passes independent acceptance and owner review, and lands an explicitly authorized Git change with Box/attempt/evaluation provenance.

A coherent full-stack feature and a codebase policy example demonstrate nonexclusive scope. Dependencies, stale bases, evaluator drift, failed checks, retries and concurrent attempts behave honestly. No custom IDE engine or marketplace is required.

Native pstack needs actual capability/dispatch receipts before being called verified. Fallback can proceed when approved, but cannot masquerade as native execution. Live intent-model quality, human pilot and restricted-hostile execution stay separately labeled.

## Preserve and reuse

[The reuse audit](docs/box-v4/REUSE.md) maps 18 currently checked legacy tasks, 14 blocked tasks, historical reviewer approvals and 426 preserved product/runtime/test files into the new work. Reuse actual interfaces/evidence, not completion summaries. Current Git is unborn/uncommitted; B1 must not invent a base SHA. Approval/payment/release semantics remain later-profile assets, not mandatory fields for every Open Box.
